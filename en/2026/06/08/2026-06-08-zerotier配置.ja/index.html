説明

​ rp_filter

​ は Linux カーネルのネットワーク向けのネットワークセキュリティ保護機能で、データパケットの送信元アドレスと送信元ネットワークインターフェース（NIC）を検査します：

  • 0（つまり無効）に設定すると、すべてのデータパケットを通過させます。

    • ただし、正常に応答できない（ルーティングテーブルに対応する項目がない）一部のデータパケットもアプリケーションに渡されて処理され、余分なシステムリソースを消費します。
    • ただし、余分な消費はごく小さいはずなので、上記2項目を0に設定しても問題ありません。

  • 1（厳格モード）に設定すると、データパケットの送信元NICがこのデータパケットを送信するのに最適なNICでない場合（つまり、このアドレスに返信する際に別のNICを選ぶ場合）、このデータパケットを

    破棄する

    。

    • 送信元と返信が異なるNICになるのは DN42 内で非常によくある状況なので、絶対に 必ず 断じて rp_filter を 1 に設定してはいけません！

  • 2（寛容モード）に設定すると、

    理論上は

    、データパケットの送信元アドレスがルーティングテーブル内にない場合（つまり、本機がこのアドレスにどう返信すればよいか分からない場合）、このデータパケットを破棄します。

    • しかし理論は理論として、新しいバージョン（5.0+）のカーネルでは、実際の使用において依然として送信元アドレスが正しい多数の正常なデータパケットが破棄されます。したがってこのモードは使用せず、統一して 0 を使用してください。

  • 次に、絶対に 必ず 断じて UFW など iptables ファイアウォールを簡単に設定してくれるツールを無効にしてください。

ファイアウォールルールを追加する

Openwrt設定（shell不要）

WANポート/ファイアウォールの設定

ここまで来ると、何も設定しなくても、実は外部ネットワークから zeortier 経由で内部ネットワークに接続できます。

  • ただしこの時点で、あなたの openwrt の IP が仮想ネットワーク内で 192.168.191.50 だと仮定すると、luci ページにはアクセスできますが、元々 WAN ポート用にマッピングしたポートはすべてアクセスできなくなります。
  • たとえば、元々 WAN 用に設定した外部 3389 ポートを内部ネットワーク LAN 配下の 192.168.1.100 デバイスの 3389 にマッピングしている場合、192.168.191.50:3389 経由ではアクセスできません。なぜならトラフィックは WAN からではなく zerotier の仮想NICから来ており、そのトラフィックは宛先に転送できないからです。

設定する場合はとても簡単です。

インターフェースを1つ作成し、名前を ZTVPN にします（任意で構いません）

プロトコルは DHCP 客户端 にします（こうすることで zerotier に IP を自動割り当てさせられ、自分で指定する必要がありません。自分で多くのパラメータを指定すると変更されず、面倒でもあります）

必ず覚えておいてください：この手順は、絶対にあなたが外部ネットワークにいる状態でリモート設定しないでください。誤設定や読み込み順序の問題により、内部ネットワークへアクセスする機会を失う可能性が非常に高いです。

「物理設定」で、zerotier によって作成された仮想NIC、イーサネットアダプターにチェックを入れます

「ファイアウォール設定」で WAN ファイアウォールゾーンを指定します。そうすることで、この ZTVPN NIC に元々 WAN およびデフォルト出口のパブリックIPのNIC向けのルールを適用できます。同様に、以前設定したポート転送内容も有効になります。

保存して適用するのを忘れないでください。

OpenWrtでZerotierを設定した後、LAN側が不通になる場合の一つの解決策

  1. ネットワーク – インターフェースで新しいインターフェースを作成します。名前は任意で、ポートには zerotier が自動生成した zt で始まるネットワークポートを選択します。ネットワークプロトコルは静的を選択します（dropbear は IP をバインドする必要があり、静的アドレスで zt 内の IP を設定しておく必要があります。そうでなければ ssh できません）
  2. ポートを編集し、そのポートのファイアウォール設定で新しいゾーンを作成します。名前は任意です（例：zerotier）。そして新しく作成したインターフェースをそのゾーンに追加します
  3. ネットワーク – ファイアウォールで、zerotier ゾーンの受信、送信、および転送要求を許可します
  4. 変更ボタンをクリックし、「転送先ゾーンを許可」で wan にチェックを入れます
  5. ルーターを再起動します
