Git Tutorial

hexo clean && hexo g -d && hexo g -d && git push

Git is like a sortable stack, with the top of the stack at the bottom. You can only modify the most recent commit; if you want to modify earlier data, you need to reorder.

All operations except switch and checkout are performed at the current location of the reference.

The name of the commit record itself is a hash value.

commit

git commit creates a new version (not a complete copy; it only records differences)

git commit --amend modifies commit records

branch

  • git branch <branch_name> <branch_position>

​ branch points to a commit

  • git branch -f main head~3 git branch -f main c0 git branch -f can change the branch pointer

  • git switch <branch_name>

​ Switch to a branch

When you move using a branch, the branch will also follow and move.

merge/rebase

merge

Pull and merge

git merge 1

At this point, if branch is on main, it pulls 1’s code into main, and branch remains on main.

rebase

Merge onto, and copy commit records

git rebase 1

then merges main onto 1’s development line, and branch is on main.

Rebase does not move the lower-level versions; it only moves the version where the reference currently is.

git rebase -i head~3 select the 3 commits including the commit at the head reference, use the GUI to delete/reduce and sort; the processed result will appear on a new line (based at head~3)

-i changes all versions from the current version to the base version

git rebase -参数 基版本

head

This is the current reference location

git checkout 1

Point head to 1

head points to one commit record

When head is used as a reference, it must be uppercase HEAD

checkout

git checkout -b totallyNotMain o/main

git checkout -b 选择分支 追踪分支 (will create a branch; no need to create it in advance)

Can make a branch track a remote branch, equivalent to replacing main

You can also use

git branch -u 追踪分支 选择分支 (will not create a branch; need to create it in advance)

Relative References

^ moves up one commit

~num moves up num commit records

git checkout main^

==You can use a branch to represent a commit==

^2 can select the second parent commit

Commands support chained operations

git checkout HEAD~^2~2

Undo Changes

git reset git revert

git reset head^ is commit goes back to the previous record, deletes the current record, and changes the reference to the previous record

git revert head^ adds a new commit on this route, but the new commit is actually the same as the previous one

==Both commands operate on the current reference location==

Organize Branch

git cherry-pick c2 c4 copies c2, c4 in order under the branch where the reference currently is

Tag (avoid confusion caused by branch movement)

git tag v1 c1

Add v1 tag on c1

describe

git describe <引用>

output: __g

Remote

clone

git clone copies the remote repository

The first clone automatically points main and o/main to the same location

main and o/main

When checking out o/main and then committing, because remote repository data has not been downloaded, it causes detached HEAD; that is, o/main only changes its pointer when synchronized

The remote branch o/main (o/*) is actually the location of the remote main branch

fetch

git fetch

does not update the main branch; it only downloads remote repository code and updates the o/main reference

No arguments needed; it will automatically compare and download

git fetch origin <远程选定分支:本地选定分支> (can use relative references)

git fetch origin <:本地分支> will create a local branch

pull

is fetch+merge

git pull

is actually git fetch ; git merge o/main

It pulls code and automatically merges

It pulls under the current branch, so if o/main is not at the current location, it cannot pull due to desynchronization

git pull --rebase pulls code in rebase form and merges into the main branch; using this feature can rebase the entire branch

You can use git pull <远程分支:本地分支> git pull <:本地分支> similar to fetch

push

Opposite to pull, it uploads code, with no automatic merge. If the local repository is an old version, you need to update before pushing

git push origin <选定分支>

​ Positions HEAD to the head, automatically tracks the selected branch and uploads

git push origin <本地选定分支:远程选定分支>

Uploads the selected local branch to the selected remote branch; if the remote does not exist, it will be created

You can use relative references to not upload the entire branch git push origin <本地选定分支^:远程选定分支>

​ It will only upload to above the selected local point

git push <:远程分支>

​ It will delete the remote branch

Discard local uncommitted commits but keep files

rebase

  2. git add .
  3. git commit -m 'tmp'
  4. git rm ./tmp
  5. git commit -m 'commit info'
  6. git rebase -i 远程分支
  7. drop the middle commit. fixup/squash the first commit. reword the last commit, keeping only the last commit message

reset (used when changing case)

Delete all commits of a branch

git update-ref -d HEAD
