OpenWrt DS-Lite (IPv4 over IPv6)

Why Japanese broadband commonly uses DS-Lite

The traditional method (PPPoE) queues at NTT’s network termination equipment (BRAS, responsible for PPPoE authentication and assigning IPv4),
and speeds drop severely during evening peak hours. The reason is that NTT’s BRAS expansion standard is calculated by number of connected users (sessions),
not by actual traffic: per-user traffic has increased more than tenfold, but if the session count has not reached the threshold, capacity is not expanded.
Who bears the expansion cost (NTT or the ISP) has also remained disputed, so this problem has dragged on for many years without being solved.

The workaround is to have ISPs build their own IPv6 networks (IPoE / v6plus, Xpass),
so traffic does not pass through the BRAS. But pure IPv6 cannot access IPv4 websites, so IPv4 packets are encapsulated in an IPv6 tunnel,
and decapsulated by the gateway on the ISP side (AFTR)—this is DS-Lite (RFC 6333).
Another similar scheme in Japan is MAP-E (JPNE/KDDI-affiliated), while DS-Lite is used by NTT-affiliated ISPs.

Cost: behind the AFTR is carrier-grade NAT (CGNAT), and home routers cannot get a public IPv4 address,
so port forwarding/self-hosted services require another approach (use IPv6 or NAT traversal).

OpenWrt Configuration

1. Install packages

After installation, restart LuCI or the router.

2. Create an interface

Network → Interfaces → Add new interface:

  • Name: dslite (fill in this name in the later traffic-splitting script)
  • Protocol: Dual-Stack Lite (RFC6333)
  • AFTR address: prefer an IPv6 address; do not enter a domain name

When entering a domain name (e.g. dgw.xpass.jp), the router must first resolve the AAAA record before it can establish the tunnel,
and this process depends on wan6’s DNS—if the connection has just been dialed and DNS is not ready yet, resolution fails,
so the DS-Lite interface remains unable to connect. Entering an IP directly skips this step.

ISP AFTR domain AFTR IPv6 address
Rakuten Hikari (Xpass) dgw.xpass.jp 2001:f60:0:200::1:1
transix (IIJ, etc.) gw.transix.jp East Japan 2404:8e00::feed:100, West Japan 2404:8e01::feed:100
v6 Connect dslite.v6connect.net Obtained via DNS resolution

The IP is an address on the carrier side and may theoretically change; if you cannot connect, first use nslookup -type=AAAA dgw.xpass.jp
to confirm the current value (transix may not be found using public DNS; refer to the carrier’s announcement).

Other options:

  • The IPv6 interface on the WAN port (usually wan6) must first obtain an address starting with 240 before DS-Lite can establish the tunnel
  • Firewall zone: select wan
  • Advanced Settings → Use gateway metric: enter 10 (higher priority than backup lines such as apartment networks)

3. Coexist with PPPoE

When both lines are available at the same time, use the metric to set priority: enter 10 for DS-Lite and 20 for PPPoE.
Normally traffic goes through DS-Lite; if it goes down, it automatically falls back to PPPoE. To force a specific machine to use PPPoE, use policy routing; see “Interface Traffic Splitting”.

Pitfalls

  • Port forwarding cannot be used: behind the AFTR is CGNAT, with no public IPv4. To provide services externally, use IPv6.
  • The IPv4 of the DS-Lite interface is a carrier private address; do not use it for local service binding.
  • When you only get one /64 PD, subnets need NAT6 or relay; see “ipv6 nat” and “Assigning public v6 to subnets”.
