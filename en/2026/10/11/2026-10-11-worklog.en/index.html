GT7 (RMX6688) Port Package AOD Fix / Backup Work Log

Device: realme GT7 China hardware RMX6688 (project number 24618), serial number 3B1F5TE6K0YF1PRM, rooted (KernelSU).
Flashed with a port package: International version RMX5061 EX01 → China hardware.

Iron rule: Not a bit of data may be lost. Only read-only operations are performed on the phone. fastboot flash/erase/format/-w/set_active, setprop/resetprop persist, rm or writes to /data, and factory reset must each first obtain the user’s explicit consent. Before flashing, the backup must first pass verification and have already been copied to a second disk.

2. AOD Fix (completed, user has confirmed fixed)

  • Root cause: display_features.xml in the port package’s my_product came from International version 24749 (oha_support / fingeprint_optical_enabled). The fix was to replace it with the China 24618 configuration and remove disable_aod_all_day_mode.
  • Flashing: 2026-10-10, under fastbootd only my_product_b was flashed, image was my_product_B_allday.img (md5 3916e32a6e9e9cbb14165ae22b4f4894, 2557247488 B). This flash was approved by the user (“I agree that you can start flashing”), and the consent is valid only for this one time.
  • fastbootd driver: Requires Google USB driver (VID_18D1&PID_4EE0), r13 version, installed on this computer with pnputil /add-driver … /install.
  • Image location (the original F:\tmp\gt7aod\out has been deleted): O:\GT7_backup_20261010_copy\aod_fix\
    • my_product_B_allday.img: md5 3916e32a…, this is what is currently on the phone.
    • my_product_A_cn_exact.img: md5 39d437f5…, alternative plan A.
    • my_product_ORIGINAL_rollback.img: md5 6ef16441…, 2533498880 B, for rollback.
  • If the port package (flash.bat) is flashed again in the future, it will overwrite my_product back to the old version, and the B version image will need to be flashed again.

4. General-purpose backup scripts

O:\DNA3-36-win\Android_full_backup.ps1 (PowerShell 5.1 / 7, UTF-8 BOM, CRLF)

  • Backup content:
    • When rooted: dd physical partitions (excluding userdata, swap, whole-disk devices, and duplicate devices); logical partitions are exported separately only when -AllLogical or -Only is added; writable mounted partitions are tarred; internal storage; app data under /data (split by app).
    • When not rooted: only backs up /sdcard and third-party app apks.
  • Verification method:
    • Partitions are compared with sha256 against the phone side; when a partition is being written by the system, the result of two consecutive identical reads is used.
    • Large partitions are read in chunks and can resume after interruption.
    • tar archives are compared by file count and byte count; hard links are counted only once by inode.
    • A tar archive must end with two all-zero blocks; otherwise it is considered incomplete.
  • Read-only guarantee: All commands sent to the phone go through a read-only check. Commands are first base64-encoded, then passed through adb exec-out "echo <b64>|base64 -d|su".
  • Issues fixed on 2026-10-11 according to review comments:
    • The read-only check mismatched quotes when encountering '\'' escapes.
    • On adb transfer errors, it now checks the exit code and stderr and retries; after consecutive failures it stops, and rerunning can resume.
    • In -Live mode, if the phone has files but the archive has none, it is no longer accepted.
    • When file names differ only by case, a hash is uniformly added to distinguish them (Clash).
    • Hard link deduplication.
    • Internal storage is all handled as -Live.
    • SHA256SUMS and logs changed to no BOM.
    • Free space check under network paths (UNC).
    • Wait-Device displays adb’s actual state.
    • In the non-root path, the package name of pm path has escaping added.
  • Real-device tests (read-only, -Only misc,frp,persist,nvdata,metadata) all passed.

O:\DNA3-36-win\android_full_backup.py (Python 3.8+, standard library only, cross-platform, LF, no BOM)

  • Functionally equivalent to the ps1. Output directory, file names, .ok markers, and SHA256SUMS are completely identical, and the two scripts can resume each other’s backups.
  • tar verification now uses Python’s tarfile; the RHT.security.selinux pax records generated by toybox can be parsed normally.
  • Porting process: 1 agent implemented, 3 reviewed by direction, 1 fixed, 1 offline tested, all using the default model. The review raised 11 issues, 9 were fixed. The two not changed: one is the tie order in partition sorting, which does not affect the result; the other is the way Clash is determined — actual testing showed that PowerShell hashtables are inherently case-insensitive, and the current implementation behaves the same as the ps1.
  • Offline tests were run with a fake adb and all passed: full backup, rerun skip, --only, non-root, transfer failure retry, truncated tar rejected, partition content changing during read, various special file names, hard links, read-only check.
  • Real-device tests (read-only, same set of partitions) passed. The hashes of misc, frp, and metadata are the same as in the ps1 run; nvdata and persist are written during runtime, so differing between the two runs is normal.
  • Incident record: The implementing agent once ran the script without adding the --adb parameter and connected to the real phone. Only read-only commands were executed (get-state, getprop, cat /proc/mounts, cat /proc/partitions, lpdump); there was no dd and no writing of any kind; the temporary text generated was deleted. The user was truthfully informed.
  • Note: The previously used Python virtual environment F:\tmp\gt7aod\venv was deleted along with tmp; from now on it needs to be run with the system Python.

5. Pitfalls encountered

  • adb stderr under PS 5.1: At ErrorActionPreference=Stop, it is treated as NativeCommandError, and needs to be changed locally to Continue.
  • Multiline here-string in CRLF scripts: \r must be removed before sending to the phone.
  • Checking with bsdtar after packing with toybox: The pax record written by tar --selinux has a trailing NUL, and bsdtar reports “malformed pax attributes”, but the content is intact. To determine whether an archive is complete, look at the two all-zero blocks at the end.
  • The adb service disconnecting midway truncates the tar: This is why transfer checks were added.
  • fastbootd cannot detect the phone: The Google USB driver needs to be installed.
  • Flashing a larger image: Logical partitions automatically expand.
  • Workflow scripts must not contain CR: Write with LF; a single agent’s output must be length-limited, otherwise it will exceed the 32k output limit.
  • Claude Pro quota: No more than 3 top-tier models running in parallel at the same time.

6. To-do / Optional

  • Delete C:\Users\Wray\GT7_backup_20261010\data_full (leftover from the interrupted test), pending the user’s decision.
  • If a complete user data backup is needed in the future, use either script with --no-partitions / -NoPartitions, and confirm the phone is unlocked before backing up.
