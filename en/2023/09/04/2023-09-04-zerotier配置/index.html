Route Forwarding

Enable Kernel Forwarding

sudo sysctl -w net.ipv4.ip_forward=1

The same applies to v6

Better Option

Disable Strict Mode

Explanation

rp_filter

is a network security protection feature of the Linux kernel that checks the source address and source network interface (NIC) of packets:

  • If set to 0 (i.e., disabled), all packets are allowed through.

  • However, some packets that cannot be properly replied to (no corresponding entry in the routing table) will also be sent to applications for processing, consuming extra system resources.

  • However, the extra consumption should be very small, so setting the above two items to 0 is also fine.

  • If set to 1 (strict mode), if the source NIC of a packet is not the optimal NIC for sending this packet (that is, if your local machine were to reply to this address, it would choose a different NIC), then this packet is

dropped

.

  • The source and reply being on different NICs is very common in DN42, so absolutely, definitely, under no circumstances should you set rp_filter to 1!
  • If set to 2 (loose mode),

in theory

, if the packet’s source address is not in the routing table (that is, the local machine does not know how to reply to this address), the packet is dropped.

  • But theory is theory; in newer kernels (5.0+), in actual use, a large number of normal packets with correct source addresses are still dropped. Therefore, do not use this mode; please use 0 consistently.
  • Then, absolutely, definitely, without fail turn off your UFW and other tools that help you simply configure the iptables firewall.
