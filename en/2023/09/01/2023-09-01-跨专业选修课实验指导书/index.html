Experiment 1 Protocols and Data of Computer Networks

Experiment series: Interdisciplinary elective course experiment Experiment object: Undergraduate

Related courses and majors: Computer Networks, Information Security Experiment hours (credits): 4 class hours

Experiment category: In-class computer operation

Experiment developer: Computer Networks

【Experiment Objectives】

Understand and master the basic concepts of protocols and network packets/messages in computer networks, master the interaction process and role of network protocols, as well as the format and significance of network data messages.

【Experiment Content】

By using WireShark software, capture network data packets of protocols such as TCP and FTP transmitted in the network, so as to understand the data structures of various protocols in the TCP/IP protocol stack, the process of session connection establishment and termination, and the variation rules of TCP sequence numbers and acknowledgment numbers.

【Experiment Environment】

  1. Students work in pairs, each with one PC, installed with Windows 7 or Windows XP operating system.

  2. A local area network environment networked with switches or hubs.

【Experiment Equipment】

2 PCs per group, WireShark listening software, and ServU FTP server software.

【Experiment Principles】

(1) Computer network layered model:

The TCP/IP protocol suite is the foundation of the Internet and the most popular networking form today. TCP/IP is a synonym for a group of protocols, including many other protocols, forming the TCP/IP protocol suite. Among the more important ones are SLIP, PPP, IP, ICMP, ARP, TCP, UDP, FTP, DNS, SMTP, etc. The TCP/IP protocol does not completely conform to the OSI seven-layer reference model. The traditional Open Systems Interconnection reference model is a 7-layer abstract reference model for communication protocols, in which each layer performs a specific task. The purpose of this model is to enable various hardware to communicate with each other at the same layer. The TCP/IP communication protocol adopts a 4-layer hierarchical structure, and each layer calls the network provided by the layer below it to fulfill its own requirements. Conceptually, it can be mapped to four layers: the network interface layer, which is responsible for transmitting frames on the line and receiving frames from the line; the Internet layer, which includes the IP protocol. The IP protocol generates Internet datagrams and performs necessary routing algorithms. The IP protocol can actually be divided into four parts: ARP, ICMP, IGMP, and IP; above that is the transport layer, which is responsible for managing sessions between computers. This layer includes two protocols, TCP and UDP. Different protocols can be used for communication according to different application requirements; the last layer is the application layer, which includes the familiar FTP, DNS, TELNET, etc.

(2) TCP protocol

TCP protocol, namely Transmission Control Protocol, provides a reliable data stream service. When transmitting data subject to error interference, or when network failure occurs, or when the network load is too heavy and the basic internet transmission system cannot work normally, other protocols are needed to ensure reliable communication. TCP is such a protocol. TCP uses the “positive acknowledgment with retransmission” technique to achieve transmission reliability, and uses the “sliding window“ flow control mechanism to improve network throughput. TCP communication establishment implements a concept of “virtual circuit“. Before both parties communicate, a link is first established, and then both parties can send data streams on it. This data exchange method can improve efficiency, but establishing the connection in advance and tearing down the connection afterward require overhead.

TCP provides a connection-oriented, reliable byte stream service. Connection-oriented means that two applications using TCP (usually a client and a server) must first establish a TCP connection before exchanging data with each other, namely the “three-way handshake.” This handshake process is very similar to making a phone call: first dial and ring, wait for the other party to pick up and say “hello,” and then explain who you are.

(3) FTP (File Transfer Protocol)

FTP is a standard protocol and the simplest method for exchanging files between computers and networks. Like the HTTP protocol for transmitting web pages and the SMTP protocol for email, FTP is also an application protocol standard that applies TCP/IP. FTP is usually used to upload files by their owners to a server for others to use, and downloading files from a server is also a very common usage. As a user, one can use a very simple DOS command-line interface to use FTP file transfer services, or use a third-party graphical FTP client to update (delete, rename, move, and copy) files on the server. FTP servers generally support anonymous login, allowing users to log in with ANONYMOUS as the username, and usually any password can be used or just pressing Enter.

【Prerequisite Knowledge】

Computer network layered model, computer network protocol concepts, network listening concepts.

【Experiment Steps】

In a local area network environment networked with switches or hubs, two people per group, with two Windows hosts per group.

(1) One Windows host in each group acts as an FTP server, providing file download services. One Windows host acts as a client, using the FTP protocol to connect to the server, and can perform file download operations.

(2) The host acting as the server installs FTP server software—ServU, sets the username and password, and configures related directory access permissions.

(3) The host acting as the client uses FTP client software or a browser to access the server, and installs the network listening tool software WireShark.

(4) Start the WireShark software tool.

(5) Set filter conditions, including source and destination IP addresses, source and destination port numbers, and protocol type. Including: using the client host’s IP address as the source IP address, capture all data packets sent from the student machine, and record the data packet header information. Using the FTP server as the destination IP address, capture all data packets sent to that server. And record the data packet header information. Using UDP and TCP respectively as the protocol type, capture and record the data packet header information; using destination port number 21, capture and record all FTP control connection packet header information.

(6) On the client host, use a browser or FTP client to log in to the specified FTP server.

(7) According to the information returned by the FTP server, enter the username and password in the client.

(8) Observe the password capture situation and record it. The recorded fields include: IP header, transport layer header data, and data captured at the application layer.

【Precautions】

【Experiment Results】

(1) Record and analyze the TCP three-way handshake packets.

(2) Explain and analyze the listened FTP protocol data packets, and find the FTP login account information.

Experiment 2 Building a Simple Local Area Network Using Switches

Experiment series: In-class experiment of “Computer Network Fundamentals” Experiment object: Undergraduate

Related courses and majors: Computer Networks, Information Security Experiment hours (credits): 1 class hour

Experiment category: In-class computer operation

Experiment developer: Computer Networks Course Group

【Experiment Objectives】

Understand and master the types and uses of local area network and wide area network cables, understand and master the basic working principles of switches, as well as the basic methods and related techniques for using switches to build local area networks. Master the basic concepts and configuration methods of IP addresses.

【Experiment Content】

Suppose you are a newly hired network administrator at a company. The company requires you, on the basis of mastering the working principles of switches, to use switches and select the correct LAN twisted-pair cables to form a simple local area network from a group of computers, and correctly configure the computers’ IP addresses. Different computers can communicate with each other through this local area network.

【Experiment Environment】

【Experiment Equipment】

1 Layer 2 switch, 3 computers, several twisted-pair cables.

【Experiment Principles】

(1) Twisted pair and unshielded twisted pair

Twisted pair is formed by twisting a pair of mutually insulated metal wires. In this way, it can not only resist part of the electromagnetic interference from the outside, but also reduce mutual interference between multiple twisted pairs. Twist two insulated wires together. The interference signal acting on these two mutually twisted wires is the same (this interference signal is called a common-mode signal). In the differential circuit that receives the signal, the common-mode signal can be eliminated, thereby extracting the useful signal (differential-mode signal). According to whether there is a shielding layer, twisted pair is divided into shielded twisted pair (Shielded Twisted Pair—STP) and unshielded twisted pair (Unshielded Twisted Pair—UTP).

Unshielded twisted pair (UTP) is a data transmission line, composed of four pairs of differently colored transmission lines, and is widely used in Ethernet and telephone lines. Unshielded twisted pair cables have the following advantages: 1. No shielding jacket, small diameter, saves occupied space, and low cost; 2. Lightweight, easy to bend, easy to install; 3. Minimizes or eliminates crosstalk; 4. Flame retardant; 5. Independent and flexible, suitable for structured cabling. Therefore, in structured cabling systems, unshielded twisted pair is widely used. Common twisted pair types include Category 3, Category 5 and Category 5e, as well as Category 6. The larger the category number and the newer the version, the more advanced the technology and the wider the bandwidth.

(2) Twisted pair wire sequence standards

The most widely used twisted pair wire sequence standards are ANSI/EIA/TIA-568A and ANSI/EIA/TIA-568B. The main difference between these two standards is the difference in core wire sequence:

The wire sequence of EIA/TIA 568A is defined as green-white, green, orange-white, blue, blue-white, orange, brown-white, brown, and its numbering is shown in the following table:

Green-white Green Orange-white Blue Blue-white Orange Brown-white Brown
1 2 3 4 5 6 7 8

The wire sequence of EIA/TIA 568B is defined as orange-white, orange, green-white, blue, blue-white, green, brown-white, brown, and its numbering is shown in the following table:

Orange-white Orange Green-white Blue Blue-white Green Brown-white Brown
1 2 3 4 5 6 7 8

According to the 568A and 568B standards, for the contacts of the RJ-45 connector (commonly known as crystal head) in network connections, their roles for transmission signals are respectively: 1 and 2 are used for transmitting, 3 and 6 are used for receiving, 4, 5, 7, and 8 are bidirectional lines; for the twisted pair connected to it, in order to reduce mutual interference, the standards require that 1 and 2 must be a twisted pair, 3 and 6 must also be a twisted pair, 4 and 5 are twisted with each other, and 7 and 8 are twisted with each other. It can be seen that there is actually no essential difference between the two standards 568A and 568B; only the wire sequence arrangement of the 8 twisted pair wires differs when connecting the RJ-45. In actual network engineering construction, the 568B standard is more commonly used.

(3) Switch

A switch works at the second layer of the OSI reference model, namely the data link layer. When each port is successfully connected, the CPU inside the switch maps MAC addresses to ports to form a MAC table. In future communications, packets sent to that MAC address will be sent only to its corresponding port, not to all ports. Therefore, a switch can be used to divide data link layer broadcasts, that is, collision domains; but it cannot divide network layer broadcasts, that is, broadcast domains.

A switch has a very high-bandwidth backplane bus and internal switching matrix. All ports of the switch are attached to this backplane bus. After the control circuit receives a data packet, the processing port searches the address mapping table in memory to determine which port the NIC (network card) of the destination MAC (network card hardware address) is attached to, and quickly transmits the data packet to the destination port through the internal switching matrix. If the destination MAC does not exist, it broadcasts to all ports. After the receiving port responds, the switch “learns” the new MAC address and adds it to the internal MAC address table. Using a switch can also “segment” the network. By comparing with the IP address table, the switch allows only necessary network traffic to pass through the switch. Through filtering and forwarding by the switch, collision domains can be effectively reduced, but it cannot divide network layer broadcasts, that is, broadcast domains.

The main functions of a switch include physical addressing, network topology, error checking, frame sequencing, and flow control. Switches also have some new functions, such as support for VLAN (virtual local area network), support for link aggregation, and some even have firewall functions.

Learning: Ethernet switch learns the MAC address of the device connected to each port, and maps the address to the corresponding port, storing it in the MAC address table in the switch cache.

Forwarding/filtering: When the destination address of a data frame has a mapping in the MAC address table, it is forwarded to the port connected to the destination node rather than all ports (if the data frame is a broadcast/multicast frame, it is forwarded to all ports).

Loop elimination: When the switch includes a redundant loop, the Ethernet switch avoids the generation of loops through the Spanning Tree Protocol, while allowing a backup path to exist.

(4) IP address

An IP address is used to give a computer on the Internet a number. What we commonly see is that every networked PC needs an IP address to communicate normally. We can compare a “personal computer” to “a telephone,” then an “IP address” is equivalent to a “telephone number.”

Every host on the Internet has a unique IP address. The IP protocol uses this address to transfer information between hosts, and this is the foundation on which the Internet can operate. An IP address is a 32-bit binary number, usually divided into four 8-bit binary numbers (that is, 4 bytes). IP addresses are usually expressed in “dotted decimal“ notation in the form (a.b.c.d), where a, b, c, and d are all decimal integers between 0 and 255. Example: The dotted-decimal IP address (100.4.5.6) is actually the 32-bit binary number (01100100.00000100.00000101.00000110).

An IP address can be divided into two parts: a network identification number and a host identification number. Therefore, an IP address consists of two parts: one part is the network address, and the other part is the host address. IP addresses are divided into classes A, B, C, D, and E. Their applicable types are respectively: large networks; medium networks; small networks; multicast addresses; reserved. Classes B and C are commonly used.

Experiment 3 Basic Configuration of Switches and Routers

Experiment series: In-class experiment of “Computer Network Fundamentals” Experiment object: Undergraduate

Related courses and majors: Computer Networks, Information Security Experiment hours (credits): 1 class hour

Experiment category: In-class computer operation

Experiment developer: Computer Networks Course Group

【Experiment Objectives】

Understand and master the working principles of switches and routers; master the differences between various command-line operation modes of switches and routers; be able to use various help information and perform basic configuration with commands.

【Experiment Content】

Suppose you are a newly hired network administrator at a company. The company requires you to become familiar with network products.

First, you are required to log in to a switch or router, understand and master the command-line operations of switches and routers, and how to use some basic commands to configure devices, including the device name of switches and routers, description information at login, basic configuration of port parameters, and viewing device operating status.

【Experiment Environment】


Switch console connection diagram Router console connection diagram

【Experiment Equipment】

1 switch, 1 router, 1 computer.

【Experiment Principles】

The management methods of switches and routers (hereinafter referred to as devices) are basically divided into two types: in-band management and out-of-band management. Managing a device through the device’s Console port belongs to out-of-band management, does not occupy the device’s network interface, and is characterized by the need to use a configuration cable and configure at close range. When configuring a switch or router for the first time, the Console port must be used for configuration.

The command-line operation modes of switches or routers mainly include: user mode, privileged mode, global configuration mode, port mode, etc.

  • User mode: The first operation mode obtained after entering the device. In this mode, you can simply view the device’s software and hardware version information and perform simple tests. The user mode prompt is switch> or router>

  • Privileged mode: The next-level mode entered from user mode. In this mode, you can manage the device’s configuration file, view the device’s configuration information, perform network testing and debugging, etc. The privileged mode prompt is switch# or router#

  • Global configuration mode: The next-level mode (submode) of privileged mode. In this mode, you can configure global parameters of the device (such as device name, login information, etc.). In this mode, you can enter the next-level configuration mode to configure specific functions of the device. The global configuration mode prompt is switch(config)# or router(config)#

  • Port configuration mode: The next-level mode (submode) of global configuration mode. In this mode, you can configure parameters for the network ports of a switch or router. The port mode prompt is switch(config-if)# or router(config-if)#

Basic operation commands of switches or routers include:

The Exit command returns to the previous operation mode.

The End command means the user directly returns to privileged mode from a level below privileged mode.

The command line of switches and routers supports obtaining help information, command abbreviation, automatic command completion, and shortcut key functions. Configuring the switch’s device name and configuring the switch’s description information must be performed in global configuration mode.

Hostname configures the device name of switches and routers. When a user logs in to a switch or router, you may need to tell the user some necessary information. You can achieve this by setting banners. You can create two types of banners: message of the day and login banner.

  • Banner motd configures the daily prompt information of switches and routers. motd is the abbreviation of message of the day.

  • Banner login configures the login prompt information of switches and routers, located after the daily prompt information.

To view system and configuration information of a switch or router, the corresponding view commands must be executed in privileged mode.

  1. Show version views the version information of a switch or router. You can view the hardware version information and software version information of the switch or router, which serves as the basis for upgrading the switch/router operating system.

  2. Show mac-address-table views the current MAC address table information of the switch.

  3. Show ip route views the routing table information in the router.

  4. Show running-config views the currently effective configuration information of the switch/router.

【Experiment Principles】

(1) Using VLANs to implement isolation:

VLAN (Virtual Local Area Network) refers to logical division within a physical network segment into several virtual local area networks. The greatest characteristic of VLAN is that it is not restricted by physical location and can be divided flexibly. A VLAN has the characteristics of a physical network segment. Hosts in the same VLAN can directly access each other. Access between hosts in different VLANs must be forwarded through routing devices. Broadcast data packets can only propagate within the local VLAN and cannot be transmitted to other VLANs.

Port VLAN is one of the ways to implement VLAN. Port VLAN uses switch ports to divide VLANs, and a port can belong to only one VLAN.

Tag VLAN follows the IEEE 802.1q protocol standard. When using an interface configured with Tag VLAN for data transmission, 4 bytes of 802.1q tag information need to be added to the data frame to identify which VLAN the data frame belongs to, so that the peer switch can accurately filter after receiving the data frame.

【Experiment Principles】

(1) Basic routing concepts

A router is a network layer device that can select an optimal path based on the information in the IP header and forward data packets. It implements mutual access between hosts on different network segments.

A router performs route selection and forwarding based on the routing table. The routing table is composed of individual pieces of routing information. There are generally 3 ways in which a routing table is generated:

  • Directly connected route: Configure an IP address for a router interface, and the router automatically generates route information for the network segment where this interface IP resides.

  • Static route: In networks with simple topology, the network administrator manually configures route information for network segments unknown to the router, thereby implementing connections between different network segments.

  • Routes generated by dynamic routing protocol learning: In large-scale networks or when the network topology is relatively complex, by running dynamic routing protocols on routers, routers automatically learn from each other to generate routing information.

(2) Static routes:

Static routes refer to routing information manually configured by a user or network administrator, including the network address, subnet mask, and next-hop address.

Static routes have different purposes in different network environments:
When the network structure is relatively simple, configuring static routes alone can make the network work normally; in complex network environments, configuring static routes can improve network performance and guarantee bandwidth for important applications; static routes can be used in VPN instances, mainly for VPN route management.

Static routes use less bandwidth than dynamic routes and do not consume CPU resources to calculate and analyze routing updates. However, when a network failure occurs or the topology changes, static routes will not automatically update and must be manually reconfigured.

Static route configuration mainly involves 5 main parameters: destination address and mask, outbound interface and next hop, and priority.

【Experiment Principles】

  1. Characteristics of static routes:

  • Manual configuration

  • Fixed routing path (unless manually modified)

  • Not advertised: It will not actively advertise to other routers. However, the administrator can introduce static routes into the dynamic routing of the local device and then advertise them as routes of the corresponding dynamic protocol.

  • Unidirectionality: It only provides routing for data along the direction of the next hop and does not provide a reverse route. To enable bidirectional communication between the source node and the destination network, a return static route must also be configured.

  • Relay nature: If a static route passes through more than 1 hop in the middle (the route passes through 3 or more routing nodes), then static routes to the same destination node or destination network must be configured in sequence on other routers except the last router.

(2) Role of static routes

The greatest role of static routes is security. Dynamic routing requires frequent exchange of routing tables between routers, and analysis of routing tables can reveal information such as network topology and network addresses. Therefore, networks may also use static routes for security considerations.

(3) Disadvantages of static routes

Large and complex network environments are usually not suitable for static routes. On the one hand, it is difficult for network administrators to fully understand the topology of the entire network; on the other hand, when the network topology and link status change, the static route information in routers needs to be adjusted on a large scale, and the difficulty and complexity of this work are very high.

【Experiment Principles】

OSPF (Open Shortest Path First) is an IGP (Interior Gateway Protocol) that was applied earlier and is more commonly used. It is suitable for medium-to-large homogeneous networks and is a typical link-state protocol. The OSPF protocol has become one of the most widely adopted and applied routing protocols in current Internet WANs and Intranet enterprise networks. The OSPF protocol was proposed by the IETF (Internet Engineering Task Force) IGP working group and is a routing protocol based on the SPF algorithm.

The OSPF routing protocol is generally used within the same routing domain. Here, a routing domain refers to an autonomous system, Autonomous System—AS. In an AS, all OSPF routers maintain the same database describing the structure of this AS. This database stores the state information of the corresponding links in the routing domain, and OSPF routers calculate their OSPF routing tables precisely through this database. OSPF transmits link state advertisement packets LSA (Link State Advertisement) to all routers within a certain area, which differs from distance-vector routing protocols. Routers running distance-vector routing protocols pass part or all of their routing tables to neighboring routers.

The SPF algorithm (also known as Dijkstra’s algorithm) is the foundation of the OSPF routing protocol. The SPF algorithm takes each router as the root (ROOT) to calculate its distance to each destination router. Each router calculates a topology diagram of the routing domain based on a unified database. This structure diagram is similar to a tree and is called the shortest path tree in the SPF algorithm.

In the OSPF routing protocol, the trunk length of the shortest path tree, that is, the distance from an OSPF router to each destination router, is called the OSPF Cost. Its formula is: Cost = 100×106/link bandwidth. Here, link bandwidth is expressed in bps. In other words, OSPF Cost is inversely proportional to link bandwidth. The higher the bandwidth, the smaller the Cost, indicating that the OSPF distance to the destination is closer. For example, the Cost of FDDI or Fast Ethernet is 1, the Cost of a 2M serial link is 48, and the Cost of 10M Ethernet is 10, etc.
