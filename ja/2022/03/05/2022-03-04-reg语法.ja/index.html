.reg ファイルには次の構文があります:

RegistryEditorVersion
Blank line
[RegistryPath1]
“DataItemName1”=”DataType1:DataValue1”
DataItemName2”=”DataType2:DataValue2”
Blank line
[RegistryPath2]
“DataItemName3”=”DataType3:DataValue3”

ここで:

RegistryEditorVersion は “Windows Registry Editor Version 5.00” (Windows 2000、Windows XP、Windows Server 2003 の場合) または “REGEDIT4” (Windows 98、Windows NT 4.0 の場合) です。”REGEDIT4” ヘッダーは、Windows 2000、Windows XP、Windows Server 2003 ベースのコンピューターにも適用されます。

Blank line は空行です。これは新しいレジストリ パスの開始を示します。各キーまたはサブキーは新しいレジストリ パスです。.reg ファイルに複数のキーがある場合、空白行は内容の確認と問題のトラブルシューティングに役立ちます。

RegistryPathx は、インポートする最初の値を保持するサブキーのパスです。パスを角かっこで囲み、階層の各レベルをバックスラッシュで区切ります。例:
[HKEY_LOCAL_ MACHINE\SOFTWARE\Policies\Microsoft\Windows\System]
1 つの .reg ファイルに複数のレジストリ パスを含めることができます。パス ステートメントの基になる階層がレジストリに存在しない場合は、新しいサブキーが作成されます。レジストリ ファイルの内容は、入力された順序でレジストリに送信されます。したがって、別のサブキーを含むサブキーを新しく作成する場合は、正しい順序で行を入力する必要があります。

DataItemNamex は、インポートするデータ項目の名前です。ファイル内のデータ項目がレジストリに存在しない場合、.reg ファイルはそのデータ項目とその値を追加します。データ項目が存在する場合、.reg ファイル内の値は既存の値を上書きします。データ項目の名前は引用符で囲みます。データ項目名の直後に等号 (=) を付けます。

DataTypex はレジストリ値のデータ型で、等号の直後に続きます。REG_SZ (文字列値) 以外のすべてのデータ型では、データ型の直後にコロンが続きます。データ型が REG_SZ の場合は、データ型の値またはコロンは含まれません。この場合、Regedit.exe はデータ型を REG_SZ と見なします。次の表に、一般的なレジストリ データ型を示します:

データ型 .reg 内のデータ型
REG_BINARY hexadecimal
REG_DWORD dword
REG_EXPAND_SZ hexadecimal(2)
REG_MULTI_SZ hexadecimal(7)

名前 データ型 説明

バイナリ値 REG_BINARY 生のバイナリ データ。ほとんどのハードウェア コンポーネント情報はバイナリ データとして格納され、16 進数形式でレジストリ エディタに表示されます。

DWORD 値 REG_DWORD 4 バイト長 (32 ビット整数) の数値で表されるデータ。デバイス ドライバーとサービスの多くのパラメーターがこの型で、2 進数、16 進数、または 10 進数形式でレジストリ エディタに表示されます。関連する値は、DWORD_LITTLE_ENDIAN (最下位バイトが最下位アドレスにある) と REG_DWORD_BIG_ENDIAN (最下位バイトが最上位アドレスにある) です。

展開可能な文字列値 REG_EXPAND_SZ 可変長のデータ文字列。このデータ型には、プログラムまたはサービスがそのデータを使用するときに解析される変数が含まれます。

複数文字列値 REG_MULTI_SZ 複数文字列。ユーザーが読むことができるリストまたは複数の値を含む値は、通常この型です。各エントリはスペース、コンマ、またはその他のマーカーで区切られます。

文字列値 REG_SZ 固定長のテキスト文字列。

バイナリ値 REG_RESOURCE_LIST 入れ子になった配列のシリーズで、ハードウェア デバイス ドライバーまたはそれが制御する物理デバイスが使用するリソース リストを格納するために使用されます。このデータはシステムによって検出され、\ResourceMap ツリーに書き込まれ、バイナリ値として 16 進数形式でレジストリ エディタに表示されます。

バイナリ値 REG_RESOURCE_REQUIREMENTS_LIST 入れ子になった配列のシリーズで、デバイス ドライバーまたはそれが制御する物理デバイスが使用できる可能性のあるハードウェア リソースのリストを格納するために使用されます。システムはこのリストのサブセットを \ResourceMap ツリーに書き込みます。このデータはシステムによって検出され、バイナリ値として 16 進数形式でレジストリ エディタに表示されます。

バイナリ値 REG_FULL_RESOURCE_DESCRIPTOR 入れ子になった配列のシリーズで、物理ハードウェア デバイスが使用するリソース リストを格納するために使用されます。このデータはシステムによって検出され、\HardwareDescription ツリーに書き込まれ、バイナリ値として 16 進数形式でレジストリ エディタに表示されます。

なし REG_NONE 特定の型がないデータ。このデータはシステムまたはアプリケーションによってレジストリに書き込まれ、バイナリ値として 16 進数形式でレジストリ エディタに表示されます。

リンク REG_LINK シンボリック リンクに名前を付ける Unicode 文字列。

QWORD 値 REG_QWORD 64 ビット整数の数値で表されるデータ。このデータはバイナリ値としてレジストリ エディタに表示され、最初に Windows 2000 で使用されました。

DataValuex はコロン (REG_SZ の場合は等号) の直後にあり、正しい形式 (文字列や 16 進数など) である必要があります。バイナリ データ項目には 16 進数形式を使用します。
注: 同じレジストリ パスに複数のデータ項目行を入力できます。
レジストリ サブキーの追加、またはレジストリ値の追加と変更
レジストリ サブキーを追加するか、レジストリ値を追加/変更するには、レジストリで適切な変更を行い、対応する 1 つ以上のサブキーをエクスポートします。エクスポートされたレジストリ サブキーは自動的に .reg ファイルとして保存されます。レジストリに変更を加え、変更を .reg ファイルにエクスポートするには、次の手順に従います:

  1. 「スタート」をクリックし、「ファイル名を指定して実行」をクリックし、「名前」ボックスに regedit と入力して、「OK」をクリックします。
  2. 変更するレジストリ キーが格納されているサブキーを見つけてクリックします。
  3. 「ファイル」をクリックし、次に「エクスポート」をクリックします。

この手順では、変更を加える前にサブキーをバックアップします。加えた変更で問題が発生した場合は、後でこのファイルをレジストリに再インポートできます。

  1. 「ファイル名」ボックスに、元のレジストリ キーを含む .reg ファイルを保存するためのファイル名を入力し、「保存」をクリックします。

注: 内容がわかる名前 (たとえば、そのサブキーを参照する名前) を使用してください。
5. 右側のウィンドウで、必要なレジストリ キーを追加または変更します。
6. 手順 3 と 4 を繰り返し、そのサブキーを再度エクスポートしますが、その .reg ファイルには別のファイル名を使用します。この .reg ファイルを使用して、他のコンピューターのレジストリに変更を加えることができます。
7. ローカル コンピューターで加えた変更をテストします。問題が発生した場合は、元のレジストリ データのバックアップが含まれるファイルをダブルクリックして、レジストリを元の状態に戻します。変更が期待どおりに機能する場合は、この記事の「レジストリの変更を配布する」セクションの方法を使用して、手順 6 で作成した .reg ファイルを他のコンピューターに配布できます。

レジストリ キーと値の削除
.reg ファイルを使用してレジストリ キーを削除するには、.reg ファイル内のレジストリ パスの前にハイフン (-) を配置します。たとえば、次のレジストリ キーから Test サブキーを削除するには:
HKEY_LOCAL_MACHINE\Software
.reg ファイル内の次のレジストリ キーの前にハイフンを配置します:
HKEY_LOCAL_MACHINE\Software\Test
次の例は、このタスクを実行できる .reg ファイルです。
[-HKEY_LOCAL_MACHINE\Software\Test]
.reg ファイルを使用してレジストリ値を削除するには、.reg ファイル内のデータ項目名の後の等号の後にハイフン (-) を配置します。たとえば、次のレジストリ キーから TestValue レジストリ値を削除するには:
HKEY_LOCAL_MACHINE\Software\Test
.reg ファイル内の “TestValue”= の後にハイフンを配置します。次の例は、このタスクを実行できる .reg ファイルです。
HKEY_LOCAL_MACHINE\Software\Test
“TestValue”=-
.reg ファイルを作成するには、Regedit.exe を使用して削除するレジストリ キーをエクスポートし、メモ帳を使用して .reg ファイルを編集してハイフンを挿入します。

レジストリ キーと値の名前変更
キーまたは値の名前を変更するには、そのキーまたは値を削除し、新しい名前を持つ新しいキーまたは値を作成します。

注: レジストリでファイル パスを使用する必要がある場合、ファイル パスのバックスラッシュ \ は二重バックスラッシュ \ にする必要があります。

システム変数を使用する場合は、システム変数内のバックスラッシュを二重バックスラッシュに置き換える必要があります。

Windows Registry Editor Version 5.00

[HKEY_LOCAL_MACHINE\SOFTWARE\Classes*\shell]

[HKEY_LOCAL_MACHINE\SOFTWARE\Classes*\shell\EditPlus 2]

@=”EditPlus 2”

[HKEY_CLASSES_ROOT*\shell\EditPlus 2\command]
@=”C:\Program Files (x86)\EditPlus 2\EditPlus.exe %1”

この例で、パスを変数に置き換えると

@=”%PROGRAMFILES(x86)%\EditPlus 2\EditPlus.exe %1” 実際の結果は @=”C:\Program Files (x86)\EditPlus 2\EditPlus.exe %1”

これは正しくなく、システムはファイルを見つけることができません。

reg ファイルを生成するには DOS バッチ処理を使用する必要があります。ここでは、テキスト置換コマンドを使用して単一のバックスラッシュを二重バックスラッシュに置き換えます。次のとおりです。

@echo off
echo “默认使用86文件夹，兼容32位系统执行”
set var=%PROGRAMFILES%
if “%PROCESSOR_ARCHITECTURE%”==”AMD64” set “var=%PROGRAMFILES(x86)%”
set “var=%var:=\%”
echo Windows Registry Editor Version 5.00 >menu.reg
echo. >>menu.reg
echo [HKEY_LOCAL_MACHINE\SOFTWARE\Classes*\shell] >>menu.reg
echo. >>menu.reg
echo [HKEY_LOCAL_MACHINE\SOFTWARE\Classes*\shell\EditPlus 2] >>menu.reg
echo. >>menu.reg
echo @=”EditPlus 2” >>menu.reg
echo. >>menu.reg
echo [HKEY_CLASSES_ROOT*\shell\EditPlus 2\command]>>menu.reg
echo. >>menu.reg
echo @=”%var%\EditPlus 2\EditPlus.exe %%1”>>menu.reg

regedit /s menu.reg
