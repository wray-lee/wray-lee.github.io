経由したルータでエラーが発生するとエラーパケットが返される。TTL タイムアウトエラーを利用し、TTL を徐々に増やしていけば、返ってくるエラーパケットに基づいてルータのアドレスを順に取得できる

UDP ベース

30000 より大きいポートに送信し、返ってくるエラーが TTL タイムアウト（まだ宛先ホストに到達していない）か、ポート到達不能（宛先ホストに到達した）かを確認する

返されるサーバー情報を含むパケット名は time-to-live exceeded、すなわち ttl exceeded

ttl exceeded の IP ヘッダを変更して traceroute の返却情報を変更できる<IP 包头欺骗（IP Spoofing）>

パケット内の ttl-1 で自分のルートを隠せる

パケット内の ttl を変更し、同時に DNat を設定すればルート情報を変更できる

B 上のクライアントが rlogin を実行し、A 上の rlogind と通信すると仮定する：

  1. B は SYN フラグ付きのデータセグメントを送信して、A に TCP 接続を確立する必要があることを通知する。そして TCP ヘッダ内の sequence number を

自分自身の今回の接続の初期値 ISN に設定する。

  1. A は B に SYS+ACK フラグ付きのデータセグメントを返し、自分の ISN を伝え、B から送られてきた最初のデータセグメントを確認し

、acknowledge number を B の ISN+1 に設定する。

  1. B は受信した A のデータセグメントを確認し、acknowledge number を A の ISN+1 に設定する。

B —- SYN —-> A
B <—- SYN+ACK —- A
B —- ACK —-> A

TCP が使用する sequence number は 32 ビットのカウンタで、0～4294967295 の範囲である。TCP は各接続ごとに
初期シーケンス番号 ISN を選択する。遅延や再送などによって三次ハンドシェイクが乱れるのを防ぐため、ISN は勝手に選んではならない。システムごとに
異なるアルゴリズムがある。TCP が ISN をどのように割り当てるか、また ISN が時間とともに変化する規則を理解することは、IP スプーフィング攻撃を成功させるうえで非常に
重要である。

リモートプロシージャコール RPC に基づくコマンド、たとえば rlogin、rcp、rsh などは、/etc/hosts.equiv および
$HOME/.rhosts ファイルに基づいて安全検証を行う。その実質は、送信元 IP アドレスのみに基づいてユーザー身元確認を行い、ユーザーの RPC を許可
または拒否することである。

ICMP ベース

icmp エコー要求（echo request）パケットを送信すると、クライアントは受信すると icmp エコー応答（icmp reply）パケットを送信する

最初のルータの TTL=1、その後 1 ずつ増やし、ttl のタイムアウトエラーに基づいて、icmp reply を得るまで、経路上のルータアドレスを順に取得する
