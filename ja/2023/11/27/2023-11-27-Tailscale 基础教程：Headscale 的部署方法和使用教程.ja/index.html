    現在、中国工業情報化部は三大通信事業者に IPv6 の発展を強力に推進させており、家庭用ブロードバンドで利用できる IPv4 パブリック IP はますます少なくなっています。一部の地域では、たとえパブリック IPv4 アドレスを取得しても、それは大規模な内部ネットワークアドレスであり、真のパブリック IP ではまったくなく、家庭内ネットワークのリソースへのアクセスはますます困難になっていくでしょう。

    一部の仲間は、frp など特定のプロトコルとポートを対象とした内網穿透（NAT 越え）ソリューションを選ぶかもしれませんが、この方法ではまだ物足りず、家庭内ネットワークの任意のデバイスの任意のポートにアクセスできません。より良い選択は、やはり VPN で大規模な内部ネットワークを構築することです。どの VPN を選ぶかといえば、間違いなく WireGuard です。WireGuard は VPN の未来です。私は何度も皆さんに WireGuard の使用を勧めてきました。もう疲れました、これ以上話したくありません。勝手にクソみたいな OpenVPN などを使えばいいですよ、あなたが楽しければそれでいい。

    WireGuard が従来の VPN と比べた核心的な利点は、VPN ゲートウェイがなく、すべてのノード間でピアツーピア（P2P）接続ができることです。つまり、以前に私が言及した 全接続モード（full mesh），效率更高，速度更快，成本更低。 です。

    WireGuard の現在最大の痛点は、上位アプリケーションの機能が十分に整っていないことです。なぜなら WireGuard は Unix の哲学を重んじており、WireGuard 自体はカーネルレベルのモジュールにすぎず、単なるデータプレーンであり、上位のより高度な機能（鍵交換メカニズム、UDP ホールパンチング、ACL など）はユーザー空間のアプリケーションによって実現する必要があるからです。

    そのため、WireGuard をベースにより完璧な VPN ツールを実現するために、現在多くのプロジェクトがしのぎを削っています。筆者はしばらく前まで Netmaker，它通过可视化界面来配置 WireGuard の全接続モードを推していました。これは UDP ホールパンチング、マルチテナントなど各種の高度な機能をサポートし、ほぼすべてのプラットフォームに対応しており、非常に強力です。しかし現実世界は複雑で、すべての NAT でホールパンチングが成功する保証はなく、また Netmaker には現在 fallback メカニズムがないため、ホールパンチングに失敗した場合、中継ノード経由に fallback することができません。Tailscale はこの点で Netmaker よりはるかに優れており、fallback メカニズムをサポートし、全接続モードを最大限実現できます。一部のノードでホールパンチングが成功しなくても、中継ノードを通じてこの仮想ネットワーク内を問題なく通行できます。

    そう、私は心変わりしました。Netmaker 陣営から Tailscale に乗り換えたのです。クズ男で間違いありません。

    Tailscale とは

    Tailscale は WireGuard をベースにした仮想ネットワーク構築ツールで、Netmaker に似ています。最大の違いは、Tailscale がユーザー空間で WireGuard プロトコルを実装しているのに対し、Netmaker はカーネル空間の WireGuard を直接使用していることです。そのため Tailscale はカーネル空間の WireGuard と比べて性能がいくらか劣りますが、OpenVPN の類と比べれば何十街も先を行っています。Tailscale は性能面で多少の妥協をしていますが、機能と使いやすさでは間違いなく他のツールを圧倒します：

    1. すぐに使える
    • ファイアウォールの設定が不要
    • 追加の設定がない
    1. 高い安全性/プライバシー
    • 自動鍵ローテーション
    • ピアツーピア接続
    • エンドツーエンドのアクセス記録をユーザーが監査可能
    1. 既存の ICE、STUN などの UDP プロトコルに加えて、DERP TCP プロトコルを実装して NAT 穿透を実現
    2. パブリックネットワーク上のコントロールサーバーが ACL と設定を配信し、ノードの動的更新を実現
    3. サードパーティ（Google など）の SSO サービスを通じてユーザーと秘密鍵を生成し、本人認証を実現

    要するに、Tailscale はより使いやすく、機能がより充実した WireGuard と見なすことができます。

    これだけでは十分ではありません。ただ乗り派として、私がより気にするのは無料とオープンソースです。

    Tailscale は商用製品ですが、個人ユーザーはただ乗りできます。個人ユーザーは接続デバイスが 20 台以下であれば無料で使用できます（ただし、サブネットセグメントをカスタマイズできない、複数のサブネットを設定できないなど、いくつかの制限があります）。Windows と macOS の GUI アプリケーションを除き、他の Tailscale クライアントのコンポーネント（Android クライアントを含む）は BSD ライセンスの下でオープンソースプロジェクトとして開発されています。彼らの GitHub リポジトリ找到各个操作系统的客户端源码。 で確認できます。

    ほとんどのユーザーにとって、Tailscale をただ乗りするだけで十分です。カスタムネットワークセグメントなど、より高い要件がある場合は、有料版を選択できます。

    私はお金を払いたくない、それでもいい？いいですよ、ただし以下を読み続けてください。

    Headscale とは

    Tailscale のコントロールサーバーはオープンソースではなく、無料ユーザーに多くの制限があります。これは彼らのドル箱なので理解できます。幸いなことに、現在 Headscale，这也是唯一的一款，希望能发展壮大。 というオープンソースの実装があります。

    Headscale は欧州宇宙機関の Juan Font によって Go 言語で開発され、BSD ライセンスの下で公開されています。Tailscale コントロールサーバーのすべての主要機能を実装しており、企業内にデプロイでき、デバイス数の制限がまったくなく、すべてのネットワークトラフィックを自分で制御できます。

    現在 Headscale には可視化インターフェースがまだありません。今後のアップデートに期待しましょう。

    macOS

    macOS には 3 つのインストール方法があります：

    • 直接 App Store からインストール、アドレス： https://apps.apple.com/ca/app/tailscale/id1475387142。前提是你**需要一个美区 ID**。。。
    • インストールパッケージ直接安装，绕过应用商店。 をダウンロード
    • オープンソースのコマンドラインツール tailscale と tailscaled をインストール。関連リンク： https://github.com/tailscale/tailscale/wiki/Tailscaled-on-macOS。

    これら 3 つのインストールパッケージのコアとなるデータパケット処理コードは同じで、唯一の違いはパッケージ方法とシステムとの相互作用方法です。

    App Store のアプリは アプリサンドボックス中，与系统的其他部分隔离。在沙箱内，应用可以是一个 内で実行され、ネットワーク拡張，以实现 を使用して VPN または VPN 類似の機能を提供します。ネットワーク拡張で実装された機能は、App Store 以外のアプリには効果がありません。

    macOS 10.15 から システム拡張，说白了就是运行在用户态的内核扩展，它相比于传统的网络扩展增强了很多功能，比如内容过滤、透明代理、DNS が追加されました。プロキシなどです。Tailscale の App Store 以外のインストールパッケージが使用するのはシステム拡張で、DMG または zip 圧縮パッケージで配布されます。

    App Store 版と独立配布版を同時にインストールしないでください。同時にインストールできるのは 1 つだけです。

    一方、コマンドラインツールはネットワーク拡張もシステム拡張も使用せず、utun インターフェース，相比于 を使用します。そのため GUI 版と比べて MagicDNS や Taildrop など一部の機能が欠けています。

    ローカルエリアネットワークの接続を確立する

    これまでは単にポイントツーポイントの Mesh ネットワークを構築しただけで、各ノード間は WireGuard のプライベートネットワーク IP を通じて直接接続できます。しかし、もっと大胆にできます。記事の冒頭で私が言及した家庭内ネットワークのリソースへのアクセスを覚えていますか？適切な設定により、各ノードが他のノードの LAN IP にアクセスできるようにできます。この使用シーンはかなり多く、家庭内ネットワークの NAS や、内部ネットワークの任意のサービスに直接アクセスできます。さらに上級のプレイヤーはこの方法を使用して、クラウド上の Kubernetes クラスタの Pod IP と Service IP にアクセスできます。

    あなたの家庭内ネットワークに Linux ホスト（例えば OpenWrt）があり、Tailscale クライアントがインストールされていると仮定します。他の Tailscale クライアントが、家庭内の LAN IP（例えば 192.168.100.0/24）を通じて家庭内ネットワークの任意のデバイスに直接アクセスできるようにしたいとします。

    まとめ

    現在、安定性から見ると、Tailscale は Netmaker よりやや優れており、Netmaker のように時々 ping が通らなくなることは基本的にありません。これは、Tailscale がユーザー空間で NAT 穿透に対して行ったさまざまな最適化によるものです。彼らは NAT 穿透の原理， 中国語版翻译自国内的 を紹介する記事をわざわざ書いており、eBPF の大御所である趙亜楠氏によるもので、ぜひ読むことを強くお勧めします。一枚の図で雰囲気を感じてみてください：
