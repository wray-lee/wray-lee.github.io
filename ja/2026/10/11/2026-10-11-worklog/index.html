GT7 (RMX6688) 移植パッケージ AOD 修正 / バックアップ 作業記録

デバイス：realme GT7 中国版ハードウェア RMX6688（プロジェクト番号 24618）、シリアル番号 3B1F5TE6K0YF1PRM、root 済み（KernelSU）。
書き込んだのは移植パッケージ：国際版 RMX5061 EX01 → 中国版ハードウェア。

鉄則：データを一切失ってはならない。 スマートフォンに対しては読み取り専用操作のみを行う。fastboot flash/erase/format/-w/set_active、setprop/resetprop persist、/data への rm または書き込み、工場出荷状態への復元は、その都度必ずユーザーの明確な同意を先に得ること。書き込み前に、バックアップは先に検証を通し、かつ2台目のディスクへコピー済みでなければならない。

1. スマートフォンの現在のバージョン構成（2026-10-11 確認）

層 バージョン
上位層（system / product など） 国際版 MY 593、fingerprint oplus/ossi/ossi:15/AP3A.240617.008/1755013304553
my_manifest 中国版 802：RMX6688_15.0.1.802(CN01)、ota RMX6688_11.A.38_0380_202509082012
下位層（vendor） 中国版 A.01、realme/RMX6688/RE602AL1…
tee_b 中国版 802
init_boot KernelSU パッチ版
vbmeta flags=3（検証を無効化、オフセット 123 バイト位置）
  • A/B パーティション + Virtual A/B、現在のスロットは b。
  • 国際版には 802 のベースパッケージがないため、移植パッケージの下位層には中国版パッケージを使用している。
  • システム OTA 更新は使わないこと：my_manifest が中国版 802 なので、中国版 OTA が配信される可能性がある。これは推測であり、実測していない。

2. AOD 修正（完了、ユーザーが修正済みと確認）

  • 根本原因：移植パッケージの my_product 内の display_features.xml が国際版 24749（oha_support / fingeprint_optical_enabled）由来。修正方法は中国版 24618 の設定に置き換え、disable_aod_all_day_mode を削除すること。
  • 書き込み：2026-10-10、fastbootd で my_product_b のみを書き込み、イメージは my_product_B_allday.img（md5 3916e32a6e9e9cbb14165ae22b4f4894、2557247488 B）。今回の書き込みはユーザーの同意を得て実施（「書き込みを開始することに同意する」）。同意は今回限り有効。
  • fastbootd ドライバー：Google USB ドライバー（VID_18D1&PID_4EE0）、r13 版が必要で、pnputil /add-driver … /install を使ってこの PC にインストール済み。
  • イメージの場所（元の F:\tmp\gt7aod\out は削除済み）：O:\GT7_backup_20261010_copy\aod_fix\
    • my_product_B_allday.img：md5 3916e32a…、現在のスマートフォン上はこれ。
    • my_product_A_cn_exact.img：md5 39d437f5…、代替案 A。
    • my_product_ORIGINAL_rollback.img：md5 6ef16441…、2533498880 B、ロールバック用。
  • 今後移植パッケージ（flash.bat）を再書き込みすると、my_product が旧版に上書きされるため、B 版イメージをもう一度書き込む必要がある。

4. 汎用バックアップスクリプト

O:\DNA3-36-win\Android_full_backup.ps1（PowerShell 5.1 / 7、UTF-8 BOM、CRLF）

  • バックアップ内容：
    • root 時：物理パーティションを dd（userdata、swap、ディスク全体のデバイス、重複デバイスを除外）；論理パーティションは -AllLogical または -Only を付けた場合のみ個別にエクスポート；書き込み可能なマウントパーティションを tar 化；内部ストレージ；/data 配下のアプリデータ（アプリごとに分割）。
    • 未 root 時：/sdcard とサードパーティアプリの apk のみバックアップ。
  • 検証方式：
    • パーティションはスマートフォン側と sha256 を比較；パーティションがシステムにより書き込み中の場合は、連続2回の読み取りが一致した結果を採用。
    • 大きなパーティションはブロック単位で読み取り、レジューム可能。
    • tar パッケージはファイル数とバイト数を比較、ハードリンクは inode ごとに1回のみカウント。
    • tar パッケージの末尾には全ゼロブロックが2つ必要で、なければ不完全とみなす。
  • 読み取り専用保証：スマートフォンへ送るすべてのコマンドは読み取り専用チェックを通す。コマンドは先に base64 エンコードし、その後 adb exec-out "echo <b64>|base64 -d|su" 経由。
  • 2026-10-11 にレビュー指摘に従い修正した問題：
    • 読み取り専用チェックで '\'' エスケープに遭遇すると引用符の対応を誤る。
    • adb 転送エラー時は、終了コードと stderr を確認して再試行するようになった；連続失敗で停止し、再実行でレジューム可能。
    • -Live モードで、スマートフォン上にファイルがあるのにパッケージ内に1つもない場合は、受け入れないようになった。
    • ファイル名が大文字小文字のみ異なる場合、統一してハッシュを付けて区別（Clash）。
    • ハードリンクを重複排除。
    • 内部ストレージはすべて -Live として処理。
    • SHA256SUMS とログは BOM なしに変更。
    • ネットワークパス（UNC）下の空き容量チェック。
    • Wait-Device が adb の実際の状態を表示。
    • 非 root パス内の pm path のパッケージ名にエスケープを追加。
  • 実機テスト（読み取り専用、-Only misc,frp,persist,nvdata,metadata）はすべて通過。

O:\DNA3-36-win\android_full_backup.py（Python 3.8+、標準ライブラリのみ、クロスプラットフォーム、LF、BOM なし）

  • ps1 と機能同等。出力ディレクトリ、ファイル名、.ok マーカー、SHA256SUMS は完全に一致し、2つのスクリプトは相互にレジューム可能。
  • tar 検証は Python の tarfile に変更；toybox が生成した RHT.security.selinux pax レコードを正常に解析可能。
  • 移植過程：1 個の agent が実装、3 個が方向別レビュー、1 個が修正、1 個がオフラインテスト、すべてデフォルトモデル使用。レビューで 11 件の問題が提出され、9 件を修正。修正しなかった2件：1つ目はパーティションソートの同順位の順序で、結果に影響しない；2つ目は Clash の判定方法で、実測では PowerShell のハッシュテーブルはもともと大文字小文字を区別しないため、現在の書き方と ps1 の動作は一致している。
  • オフラインテストは偽 adb で実行し、すべて通過：全量、再実行時スキップ、--only、非 root、転送失敗再試行、tar 切り詰めの拒否、パーティション内容の読み取り中変化、各種特殊ファイル名、ハードリンク、読み取り専用チェック。
  • 実機テスト（読み取り専用、同一パーティション群）通過。misc、frp、metadata のハッシュは ps1 の時と同じ；nvdata、persist は実行時に書き込まれるため、2回で異なるのは正常。
  • 事故記録：実装担当 agent が一度、--adb パラメータを付けずにスクリプトを実行し、実機スマートフォンに接続した。実行されたのは読み取り専用コマンドのみ（get-state、getprop、cat /proc/mounts、cat /proc/partitions、lpdump）で、dd も一切の書き込みもなし；生成された一時テキストは削除済み。ユーザーにはありのまま伝えた。
  • 注意：以前使用していた Python 仮想環境 F:\tmp\gt7aod\venv は tmp とともに削除済み、今後はシステム Python で実行する必要がある。

5. ハマったポイント

  • PS 5.1 での adb の stderr：ErrorActionPreference=Stop 時に NativeCommandError と見なされるため、局所的に Continue に変更する必要がある。
  • CRLF スクリプト内の複数行 here-string：スマートフォンへ送る前に \r を除去する必要がある。
  • toybox でパッケージ後に bsdtar で検査：tar --selinux が書いた pax レコードの末尾に NUL が付き、bsdtar は “malformed pax attributes” を報告するが、内容は正常。パッケージが完全かどうかは末尾の全ゼロブロック2つで判断する。
  • adb サービスが途中で切断されると tar が切り詰められる：これが転送チェックを追加した理由。
  • fastbootd がスマートフォンを認識しない：Google USB ドライバーのインストールが必要。
  • より大きなイメージの書き込み：論理パーティションは自動拡張される。
  • Workflow スクリプトに CR を含められない：LF で書く；単一 agent の出力は長さを制限する必要があり、そうしないと 32k 出力上限を超える。
  • Claude Pro クォータ：トップモデルの同時並列は3個まで。

6. 未対応 / 任意

  • C:\Users\Wray\GT7_backup_20261010\data_full を削除（中断テストの残留物）、ユーザーの判断待ち。
  • 今後完全なユーザーデータバックアップが必要な場合は、任意のスクリプトに --no-partitions / -NoPartitions を付けて実行し、バックアップ前にスマートフォンがロック解除済みであることを確認する。
