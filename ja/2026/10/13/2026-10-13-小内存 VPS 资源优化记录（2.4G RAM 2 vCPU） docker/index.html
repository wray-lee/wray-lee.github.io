小メモリ VPS リソース最適化記録（2.4G RAM / 2 vCPU）

インスタンス：RackNerd VPS（Ubuntu 22.04）、2026-10-13

最適化前後

指標 最適化前 最適化後
負荷 (load average) 4.5–5 0.4–0.5
利用可能メモリ (MemAvailable) ~515 MB ~880 MB
openclaw 再起動所要時間 ~15 分 ~2 分
openclaw RSS 1.0–1.24 GB（メモリプレッシャー警告をトリガー） ~0.9 GB
zerotier CPU ~50% 単一コア <1%
eth0 包速率 ~25,000 pps ~80 pps

1. ZeroTier：多 IPv6 地址导致路径探测风暴（CPU 杀手）

现象：zerotier-one 常驻 ~50% CPU，eth0 每秒几万个 71/166 字节的 UDP 包，zt 接口本身几乎没流量。

原因：eth0 配了 20 个 IPv6（/etc/network/interfaces 静态配置），ZeroTier 默认在每个本地地址 × 3 个端口上绑定，
并与对端（也是多地址 IPv6 家宽）的所有地址/端口组合做打洞和保活，组合爆炸。
它还绑定了 docker 网桥、netbird wt0、warp，出现 ZT 套 netbird 的双重隧道。

修复：/var/lib/zerotier-one/local.conf

調査方法：top -H -p $(pidof zerotier-one) でスレッドを確認、/proc/net/dev で2回サンプリングして pps を計算、
tcpdump -ni eth0 -c 20000 -q でポート分布を集計。

2. OpenClaw

2.1 毎回起動時の doctor をスキップ（再起動 15 分 → 2 分）

公式イメージのエントリポイント /app/docker-entrypoint.mjs は、フォアグラウンドで gateway を起動する前に無条件に
openclaw doctor --fix --non-interactive を実行する（無効化できる環境変数はない）。非力なマシンでは十数分かかる。

2.2 不要なプラグインを無効化（ロード数 16 → 7 個、起動が約 30 秒短縮）

プラグイン 役割 無効化の理由
anthropic / xai / ollama 各社のモデルプロバイダー カスタム openai-completions プロバイダーのみを使用
canvas Control UI 内の A2UI ダッシュボードコンポーネント Telegram/Slack のみを使用
cua-computer デスクトップを直接操作（Computer Use） コンテナにデスクトップなし
device-pair / geolocation / talk-voice デバイスペアリング / 位置情報 / 音声 未使用
github Control UI 内の公開リポジトリリンクのプレビュー 未使用

保持：browser、file-transfer、linux-node、memory-core、openai、slack、telegram。
必要に応じて plugins enable <id> で復元。設定バックアップ：data/openclaw.json.pre-memopt。

2.3 メモリ増加の制限

RSS は V8 ヒープ（約 1GB 対 約 290MB）よりはるかに大きく、大部分はネイティブメモリ：worker スレッド、SQLite、プラグイン。
さらに絞るには機能を無効にする（browser、memory-core など）しかない。

3. システムレベル

3.1 fwupd を無効化（-141 MB）

ファームウェア更新サービス。VPS では不要だが常に 141MB を占有：

3.2 zram 圧縮 swap

ディスク swap zram
位置 ディスクファイル メモリ（圧縮）
ページ置き換え遅延 ミリ秒級。VPS のディスク IO は共有かつ帯域制限あり マイクロ秒級
容量 ディスクを占有 zstd で約 1/3 に圧縮。1GB 満杯時の実メモリ使用量は約 300–400MB
代償 IO により他サービスが低速化 少量の CPU
  • ディスク swap（8G ファイル + 1.2G パーティション）はフォールバックとして保持。
  • ディスク swap 上にある古いページは能動的に移行されず、読み戻された後に再度スワップアウトされる際に自然と zram に入る；
    移行を目的として swapoff /swap しないこと。数百 MB が一度にメモリへ読み戻される。

4. 実測：fgc（free-games-claimer）のメモリピーク

fgc を再起動すると全サイトのログインチェックが実行され、約 3 秒ごとにサンプリング：

段階 fgc の使用量 システムの利用可能メモリ
平常時 25–56 MB ~730 MB
チェック中（約 70 秒、サイトごとに Chromium を起動） ピーク時 約 520 MB 最低 約 520 MB
終了 低下 ~730 MB

結論：短時間のピークは約 500MB で、2.4G マシンなら十分に耐えられる。これのために個別に移行する価値はない。

5. 現在のメモリ予算

コンポーネント 常駐
openclaw ~900 MB
sub2api + postgres + redis ~95 MB
ArchiSteamFarm ~65 MB
workbuddy2api / line_backend / whisper ~55 MB
fgc ~50 MB（毎日一時的に約 500 MB）
dockerd / netbird / zerotier など ~100 MB

6. 将来的にマシンを変更すべきか

2026 年のメモリ価格上昇（Hetzner CAX +31%、Netcup +40%、多くが在庫切れ）の中、最適化後のこのマシンで足りているので、当面はこのまま我慢。
ブラックフライデー（11/27）に更新時も同価格の 8GB プラン（年 ≤ $60–90）が見つかれば、その時にまるごと移行する。
注意：安価な ARM（Ampere Altra）のシングルコア性能は新しい EPYC/Ryzen より弱く、openclaw（主に Node のシングルスレッド）は速くならない。
ARM の利点は同一価格でより多くのコアと大きなメモリが得られる点にある。
