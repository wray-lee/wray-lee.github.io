Location

ユーザーリクエストパス location 設定 proxy_pass 設定 バックエンドが受け取る実際のパス 説明
/api/test location /api/ http://host (スラッシュなし) /api/test パススルー：パスを一切変更しない
/api/test location /api/ http://host/ (スラッシュあり) /test 置換：/api/ が切除される
/api/test location /api/ http://host/new/ /newtest 連結：/api/ が切除され、残りの部分はそのまま /new の後ろに連結される (注意：/new の後にスラッシュがないとつながってしまう可能性がある)
/api/test location /api/ http://host/new/ /new/test ディレクトリ連結：最も確実なサブディレクトリプロキシ方式

location {content}

{content}はアンカーであり、マッチする内容を決定し、{content}から後ろのすべての内容にマッチする

proxy__pass の uri が完全かどうかによって、マッチが完全に連結されるかを判断する。完全な uri の場合は、{content}およびその前の内容を除去した後続内容を連結する

完全でない uri の場合は、マッチした内容をすべて連結する

location /{content}/ を処理し、ユーザーが https://host/{content}/123，则透传123到proxy_pass http://host/new にアクセスすると、最初の / を探した結果は http://host/new123 になる

つまり location は切り詰めに使用し、proxy_pass はパススルーに使用する

/apiは /api1 /api2 /api/sth /api2/sth にマッチできる

/api/は /api /api/sth のみにマッチできる

= /apiは /api のみにマッチする

proxy_pass

http://url/api/content时 にアクセスする

前者は http://localhost:3000//content にアクセスする

後者は http://localhost:3000/content にアクセスする

前者が完全でない uri の場合、http://url/api/content时，实际访问http://localhost:3000/api/content にアクセスする

後者が完全な uri の場合、http://url/api/content时，实际访问http://localhost:3000/content にアクセスする
