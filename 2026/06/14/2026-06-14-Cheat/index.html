    1. 核心与对象系统 (Core & UObject System)

    这些函数用于获取游戏世界实例、判断对象类型以及获取类模板。

    函数名 代码中的用法 说明
    UWorld::GetWorld() UWorld::GetWorld() 获取当前的全局世界指针（UWorld*），是一切逻辑的入口。
    AActor::IsA(...) Actor->IsA(...) 判断一个 Actor 是否属于某个特定的类（如判断是否为怪物或玩家）。
    UClass::StaticClass() APlayer_char_main_C::StaticClass() 获取某个类的反射对象（UClass*），常配合 IsA 使用。
    UObject::GetDefaultObj() APlayer_char_main_C::GetDefaultObj() 获取某个类的默认对象（CDO）。代码中用它来读取默认的移动速度和基础数值，以便计算倍率。

    2. 坐标与空间 (Actor & Spatial)

    这些函数用于获取或设置物体在游戏世界中的位置、距离。

    函数名 代码中的用法 说明
    AActor::K2_GetActorLocation() Actor->K2_GetActorLocation() 获取 Actor 当前的世界坐标（FVector）。
    注：带 K2_ 前缀通常是暴露给蓝图的版本，C++原生是 GetActorLocation()，SDK中常用 K2 版本。
    AActor::K2_SetActorLocation(...) Actor->K2_SetActorLocation(TargetLoc, ...) 瞬移 Actor 到指定坐标。代码中用于魔法子弹（把子弹瞬移到敌人头上）。
    AActor::GetDistanceTo(...) MyChar->GetDistanceTo(Actor) 计算两个 Actor 之间的 3D 距离（单位通常是厘米）。
    USceneComponent::K2_GetComponentLocation() Monster->see_Scene->K2_GetComponentLocation() 获取组件（如怪物的视野组件）的世界坐标。
    USkinnedMeshComponent::GetSocketLocation(...) Monster->Mesh->GetSocketLocation(...) 获取骨骼网格体上指定骨骼或插槽（Socket）的世界坐标。代码中用于获取怪物头部骨骼 bone_head 的位置。

    3. 控制器与摄像机 (Controller & Camera)

    这些函数涉及玩家视角的控制以及 3D 世界到 2D 屏幕的转换。

    函数名 代码中的用法 说明
    APlayerController::ProjectWorldLocationToScreen(...) PC->ProjectWorldLocationToScreen(...) 世界转屏幕（W2S）。将 3D 坐标转换为屏幕 2D 坐标，是绘制 ESP 和自瞄准星的核心函数。
    APlayerCameraManager::GetCameraLocation() PC->PlayerCameraManager->GetCameraLocation() 获取摄像机当前的绝对世界坐标（用于计算自瞄角度的起点）。
    AController::GetControlRotation() PC->GetControlRotation() 获取玩家当前的视角旋转角度（Aim Angles）。
    AController::SetControlRotation(...) PC->SetControlRotation(FinalRot) 设置玩家的视角旋转角度。代码中用于自瞄（强制改变视角朝向敌人）。

    4. 数学库 (Kismet Math Library)

    使用了 UE 封装好的数学库来进行复杂的向量和角度计算，替代了手写的数学函数。

    函数名 代码中的用法 说明
    UKismetMathLibrary::FindLookAtRotation(...) UKismetMathLibrary::FindLookAtRotation(Start, Target) 计算从起点看向终点所需的旋转角度（Rotator）。代码中用于计算自瞄的理想角度。
    UKismetMathLibrary::RLerp(...) UKismetMathLibrary::RLerp(Current, Target, Alpha, ...) 旋转插值。用于平滑自瞄，让准星不是瞬间锁死，而是平滑过渡到目标角度。

    Unity

    如果我们将目标从 Unreal Engine (UE) 转向 Unity，底层的编程范式会从 C++ (UE SDK) 变为 C# (Unity API / Mono)。

    虽然逻辑核心（如计算距离、自瞄角度）是一样的，但API 名称、对象结构和坐标系会有很大不同。

    以下是你代码中用到的 UE 函数在 Unity 中的对应关系总结：

    1. 核心系统与对象获取 (Core & Object)

    UE 是基于 UWorld -> Level -> Actor 的层级，而 Unity 是基于 Scene -> GameObject -> Component。

    UE 原生函数 (C++) Unity 对应 API (C#) 说明
    UWorld::GetWorld() SceneManager.GetActiveScene() Unity 没有单一的 World 指针，通常通过场景管理器访问。
    UWorld->PersistentLevel->Actors Object.FindObjectsOfType<T>()
    或 GameObject.FindGameObjectsWithTag()    		 这是最大的区别。Unity 也就是所谓“遍历GObjectList”。通常需要遍历所有对象列表来找敌人。
    Actor->IsA(Class) obj is EnemyClass
    或 obj.GetComponent<EnemyClass>() != null    		 C# 的类型判断更直观，直接用 is 关键字，或者判断是否挂载了某个脚本组件。
    GetDefaultObj() (CDO) Prefab (预制体) Unity 没有 CDO 概念。通常直接读取 Prefab 资源或者硬编码基础数值。
    Actor GameObject 游戏中的实体基类。
    APlayerController 无严格对应，通常分散在 Update() 玩家输入逻辑通常写在挂在主角身上的 MonoBehaviour 脚本里。

    2. 坐标与空间 (Transform & Spatial)

    注意坐标系差异：UE 是 Z轴向上 (Right-handed/Left-handed 混用)，Unity 是 Y轴向上 (Left-handed)。

    UE 原生函数 Unity 对应 API 说明
    FVector Vector3 基础向量结构体 (x, y, z)。
    K2_GetActorLocation() transform.position 获取世界坐标。
    K2_SetActorLocation(...) transform.position = newPos 设置世界坐标（实现瞬移/Magic Bullet）。
    GetDistanceTo(Actor) Vector3.Distance(posA, posB) 计算两点间距离。
    GetSocketLocation(BoneName) animator.GetBoneTransform(HumanBodyBones.Head).position 骨骼获取。如果不是标准人型，则是通过 transform.Find("Root/Spine/Head") 遍历子物体找到头部节点。
    K2_GetComponentLocation() component.transform.position 组件也是依附于 GameObject 的，直接取其 transform。

    3. 摄像机与屏幕转换 (Camera & W2S)

    这是做 ESP 和自瞄最关键的部分。

    UE 原生函数 Unity 对应 API 说明
    ProjectWorldLocationToScreen Camera.main.WorldToScreenPoint(pos) W2S 核心。注意：Unity 屏幕原点 (0,0) 在左下角，而 ImGui/绘制库原点通常在左上角。需要手动计算 Y 轴翻转：screen.y = Screen.height - screen.y。
    GetCameraLocation() Camera.main.transform.position 获取主摄像机位置。
    GetControlRotation() Camera.main.transform.eulerAngles
    或 transform.localEulerAngles    		 Unity 没有强制的“控制器旋转”。通常直接读取摄像机的欧拉角。
    SetControlRotation() transform.eulerAngles = new Vector3(...) 设置摄像机角度（实现自瞄）。

    4. 数学与自瞄计算 (Math & Aimbot)

    Unity 内部使用四元数 (Quaternion) 处理旋转，但为了方便通常对外暴露欧拉角 (Euler Angles/Vector3)。

    UE 原生函数 Unity 对应 API 说明
    FRotator Quaternion (内部) / Vector3 (外部) UE 的 Rotator 是 (Pitch, Yaw, Roll)，Unity 的 Vector3 是 (x, y, z) 对应 (Pitch, Yaw, Roll)。
    FindLookAtRotation(Start, End) Quaternion.LookRotation(Target - Start)
    或 transform.LookAt(Target)    		 计算朝向目标的旋转四元数。
    RLerp / RInterpTo Quaternion.Slerp(curr, target, t)
    或 Quaternion.RotateTowards(...)    		 平滑自瞄。Slerp 是球形插值，比 Lerp 更适合旋转。
    ClampAngles (自定义) Mathf.Clamp / Mathf.DeltaAngle Unity 的 Mathf.DeltaAngle 自动处理 -180 到 180 的角度差问题，非常方便，不用手写那堆 while > 180 的逻辑。

    总结 Unity Hook 的不同点

    1. 骨骼位置 (Head Position):

      • UE: 通过 Mesh->GetSocketLocation("head")。
      • Unity: 骨骼就是普通的 GameObject。你需要遍历层级找到名为 “Head” 的子物体，或者如果用了 Animator，可以用 animator.GetBoneTransform(HumanBodyBones.Head)。

    2. 世界转屏幕 (W2S) 的坑:

      • Unity 的 WorldToScreenPoint 返回的 Z 轴是深度。
      • 必须判断 result.z > 0 才是摄像机前方的物体（这点和 UE 的 return bool 类似）。
      • 必须翻转 Y 轴：如果你用 ImGui 绘制，Unity 的 y 是从底部开始算的，ImGui 是从顶部开始算的。
      • 代码：screenPos.y = Screen.height - screenPos.y;

    3. 查找列表:

      • UE 逆向通常是找 GWorld -> Level -> ActorArray 的偏移。
      • Unity 逆向 (Mono) 通常是找 BaseEntity 类的静态链表，或者直接 Hook GameObject 的特定函数来收集对象列表。

    Source

    起源引擎 (Source Engine) 是 Valve 开发的引擎（代表作：CS:GO/CS2, Apex Legends, L4D2, TF2）。

    从 Unreal Engine 转向 Source Engine，你会发现最大的区别在于：UE 高度依赖 反射系统 (UObject/Reflection)，而 Source Engine 高度依赖 虚函数接口 (Virtual Interfaces) 和 网络变量 (Netvars)。

    以下是你用到的功能在 Source Engine 中的对应方式：

    1. 核心系统与对象获取 (Interfaces vs UWorld)

    UE 有一个全局的 UWorld，里面存着所有 Actor。
    Source Engine 使用 接口模式 (Interface Pattern)。你需要获取引擎暴露出的全局接口指针。

    UE 原生函数 Source Engine 对应接口/方法 说明
    UWorld::GetWorld() 无单一入口，通常获取 IClientEntityList 和 IVEngineClient 你需要通过 CreateInterface 导出函数来获取这些全局接口。
    PersistentLevel->Actors IClientEntityList::GetClientEntity(index) Source 的实体存放在一个索引数组中。Index 0 是世界，1~64 是玩家，64+ 是实体/武器。你需要写个 for 循环遍历 0 到 GetHighestEntityIndex()。
    Actor C_BaseEntity / IClientEntity 所有物体的基类。
    IsA(...) GetClientClass()->m_pNetworkName Source 通过 ClientClass 链表判断类型。通常比较 ClassID（如 CCSPlayer）。
    APlayerController C_BasePlayer (Local) 本地玩家通常通过 GetClientEntity(GetLocalPlayerIndex()) 获取。

    2. 坐标与空间 (Vectors & Netvars)

    UE 的属性（如 HP, Pos）通常是类成员变量。
    Source Engine 的属性通常是 Netvars (网络变量)，通过读取内存偏移（Offset）或 RecvTable 获取。

    UE 原生函数 Source Engine 对应 说明
    FVector (X, Y, Z) Vector (x, y, z) 也是 Z 轴向上。
    FRotator (Pitch, Yaw, Roll) QAngle (Pitch, Yaw, Roll) 专门用于角度的结构体。
    K2_GetActorLocation() GetAbsOrigin() 或读取 m_vecOrigin 获取坐标。
    K2_SetActorLocation(...) 无法直接 Set。 Source 是强服务器验证。修改本地坐标通常会被拉回。瞬移通常靠利用漏洞（如 L4D2 的 warp）或发送特定数据包。
    GetSocketLocation(...) (骨骼) SetupBones + m_dwBoneMatrix 这是难点。Source 需要调用 SetupBones 更新骨骼矩阵，然后从矩阵数组中通过骨骼索引（如 8=Head）读取坐标。
    HP_current (成员变量) m_iHealth (Netvar) 需要通过 Netvar Manager 扫描 DT_BasePlayer 表找到 m_iHealth 的偏移。

    3. 摄像机与输入 (CreateMove vs SetControlRotation)

    这是 Source Engine Hook 的精髓所在。
    在 UE 中，你直接改 Controller 的 Rotation。
    在 Source 中，通常 Hook CreateMove 函数。

    UE 原生函数 Source Engine 对应 说明
    SetControlRotation CUserCmd::viewangles 在 CreateMove 中，每一帧客户端都会生成一个 CUserCmd 发给服务器。直接修改 cmd->viewangles 即可实现自瞄。
    GetControlRotation IVEngineClient::GetViewAngles 获取当前视角。
    优势 Silent Aim (静默自瞄) 在 Source 中，你可以修改发送给服务器的 viewangles 但不修改本地摄像机的角度。结果是：你看着前方，子弹却飞向侧面的敌人。UE 很难做到这一点（通常需要改 Bone Transform）。

    4. 世界转屏幕 (W2S)

    Source Engine 的 W2S 需要依赖 ViewMatrix (视图矩阵)。

    UE 原生函数 Source Engine 对应 说明
    ProjectWorldLocationToScreen WorldToScreen (手写) 你需要从 IVEngineClient 或渲染器中找到 ViewMatrix (4x4 矩阵)。然后进行标准的矩阵乘法运算将 3D 转 2D。
    Debug 绘制 ISurface 接口 Source 提供了一个 ISurface 接口，可以画线、画字、画矩形，比 ImGui 更原生（但在现代作弊中 ImGui 更流行）。

    5. 射线检测 (RayCast / Visibility)

    判断敌人是否在墙后。

    UE 原生函数 Source Engine 对应 说明
    LineTraceSingle IEngineTrace::TraceRay 这是一个非常强大的接口。你需要构建 Ray_t 和 CTraceFilter，然后调用引擎的 TraceRay 来检测可见性。

    总结 Source Engine Hook 的特点

    1. 更“底层”: 没有 UE 那么多封装好的 K2_ 函数，很多时候要操作矩阵和向量。
    2. Netvars (网络变量): 必须理解 RecvTable，所有游戏数据都是通过网络表同步的，逆向时主要是 dump 这些表的偏移。
    3. CreateMove: 这是 Source 辅助的核心，所有的 连跳(Bhop)、自瞄(Aimbot)、假身(Anti-Aim)、自动扳机(Triggerbot) 都在这里实现。
    4. Dormant (休眠): Source 为了优化网络，不会发送远处的敌人数据给客户端。如果 IsDormant() == true，你甚至无法知道敌人在哪（这是防透视的天然屏障，而 UE 默认通常会把所有 Actor 发送过来，除非开启了 Relevancy 优化）。
