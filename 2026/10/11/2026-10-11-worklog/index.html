GT7 (RMX6688) 移植包 AOD 修复 / 备份 工作记录

设备：realme GT7 国行硬件 RMX6688（项目号 24618），序列号 3B1F5TE6K0YF1PRM，已 root（KernelSU）。
刷的是移植包：国际版 RMX5061 EX01 → 国行硬件。

铁律：数据一点不能丢。 对手机只做只读操作。fastboot flash/erase/format/-w/set_active、setprop/resetprop persist、对 /data 的 rm 或写入、恢复出厂，每一次都必须先得到用户的明确同意。刷机前，备份必须先校验通过，并且已复制到第二块盘。

1. 手机当前的版本构成（2026-10-11 核实）

层 版本
上层（system / product 等） 国际版 MY 593，fingerprint oplus/ossi/ossi:15/AP3A.240617.008/1755013304553
my_manifest 国行 802：RMX6688_15.0.1.802(CN01)，ota RMX6688_11.A.38_0380_202509082012
底层（vendor） 国行 A.01，realme/RMX6688/RE602AL1…
tee_b 国行 802
init_boot KernelSU 修补版
vbmeta flags=3（关闭校验，在偏移 123 字节处）
  • A/B 分区加 Virtual A/B，当前槽位是 b。
  • 国际版没有 802 底包，所以移植包底层用的是国行包。
  • 不要用系统 OTA 更新：my_manifest 是国行 802，可能会被推送国行 OTA。这是推断，没有实测。

2. AOD 修复（已完成，用户已确认修好）

  • 根因：移植包 my_product 里的 display_features.xml 来自国际版 24749（oha_support / fingeprint_optical_enabled）。修法是换成国行 24618 的配置，并去掉 disable_aod_all_day_mode。
  • 刷入：2026-10-10，在 fastbootd 下只刷了 my_product_b，镜像是 my_product_B_allday.img（md5 3916e32a6e9e9cbb14165ae22b4f4894，2557247488 B）。这次刷写经过用户同意（”我同意你开始刷”），同意只对这一次有效。
  • fastbootd 驱动：需要 Google USB 驱动（VID_18D1&PID_4EE0），r13 版，已用 pnputil /add-driver … /install 装在这台电脑上。
  • 镜像位置（原来的 F:\tmp\gt7aod\out 已删）：O:\GT7_backup_20261010_copy\aod_fix\
    • my_product_B_allday.img：md5 3916e32a…，当前手机上就是这个。
    • my_product_A_cn_exact.img：md5 39d437f5…，备选方案 A。
    • my_product_ORIGINAL_rollback.img：md5 6ef16441…，2533498880 B，回滚用。
  • 以后如果重刷移植包（flash.bat），会把 my_product 覆盖回旧版，需要再刷一次 B 版镜像。

3. 备份

分区 + 挂载分区（已完成并校验）

  • C:\Users\Wray\GT7_backup_20261010\
    • partitions\：103 个物理分区加 super.img，都和手机端 sha256 比对过。partitions\SHA256SUMS 里 nvdata 出现了两行，以最后一行 ffd951a8… 为准。
    • 另有 logical\、mounted\、super_chunks\、_incomplete\。
    • data_ps1\：挂载分区的 tar 包已校验；内部存储只备份了一部分，当时 adb 服务中途断开，Android.tar 被截断。
    • data_full\：2026-10-11 测试时中断留下的，约 392MB，不完整，可以删。
    • data\：空目录。
  • 第二块盘的副本：O:\GT7_backup_20261010_copy\，124 个文件已校验，另含 aod_fix\ 和 SHA256SUMS_copy.txt。
  • O:\DNA3-36-win\GT7_backup_20261010\：只有文本清单和少量目录，是早期的产物。
  • 用户数据（内部存储约 33GB，应用数据 65GB 以上）：用户说之前已经备份过，这次不再做全量备份。

7z 包（在 O:\DNA3-36-win\）

文件 说明
Realme GT7 For_EX01.7z 原始移植包，没动过
Realme GT7 For_EX01_本机一致版.7z 7742841918 B，已用 7zr t 测试并比对 CRC。和手机当前状态一致：my_product 是修复版，flash.bat 增加了 my_company_a / my_manifest_a，tee 是 802，init_boot 是 KernelSU，另附 init_boot_stock_A01.img 和 修改说明.txt。用 lpdump 记录的位置从 super 里切出各逻辑分区比对过，刷写目标和槽位 b 一致（vbmeta 的 flag 除外）。
GT7_本机专属分区_3B1F5TE6K0YF1PRM_20261010.7z 118514412 B，已校验。包含 22 个本机专属分区镜像：nvdata、nvcfg、nvram、protect1/2、md_sec、persist、proinfo、seccfg、sec1、otp、oplusreserve1/2/3/5/6、metadata、para、boot_para、dram_para、expdb、frp；另有 5 个挂载分区的 tar 包、说明.txt、SHA256SUMS.txt、getprop、by-name。只能刷回这台手机。
Realme GT7 For_EX01_AOD修复版.7z 已被本机一致版取代，已不在目录里（用户已删）。
  • tee 不是每台机器各不相同：tee 镜像是厂商签名的通用固件。每台机器自己的密钥和数据在 nvdata、protect、md_sec 这些分区里（上面那个本机专属包里有）。

4. 通用备份脚本

O:\DNA3-36-win\Android_full_backup.ps1（PowerShell 5.1 / 7，UTF-8 BOM，CRLF）

  • 备份内容：
    • root 时：物理分区 dd（排除 userdata、swap、整盘设备和重复设备）；逻辑分区只在加 -AllLogical 或 -Only 时单独导出；可写挂载分区打 tar 包；内部存储；/data 下的应用数据（按应用分包）。
    • 未 root 时：只备份 /sdcard 和第三方应用的 apk。
  • 校验方式：
    • 分区和手机端比对 sha256；分区正被系统写入时，采用连续两次读取一致的结果。
    • 大分区分块读取，可以断点续传。
    • tar 包比对文件数和字节数，硬链接按 inode 只算一次。
    • tar 包结尾必须有两个全零块，否则视为不完整。
  • 只读保证：所有发往手机的命令都经过只读检查。命令先 base64 编码，再走 adb exec-out "echo <b64>|base64 -d|su"。
  • 2026-10-11 按审查意见修复的问题：
    • 只读检查遇到 '\'' 转义时会配错引号。
    • adb 传输出错时，现在会检查退出码和 stderr 并重试；连续失败就停止，重跑可续传。
    • -Live 模式下，手机上有文件而包里一个都没有时，不再接受。
    • 文件名只差大小写时，统一加哈希区分（Clash）。
    • 硬链接去重。
    • 内部存储全部按 -Live 处理。
    • SHA256SUMS 和日志改为不带 BOM。
    • 网络路径（UNC）下的剩余空间检查。
    • Wait-Device 显示 adb 的实际状态。
    • 非 root 路径里 pm path 的包名加了转义。
  • 实机测试（只读，-Only misc,frp,persist,nvdata,metadata）全部通过。

O:\DNA3-36-win\android_full_backup.py（Python 3.8+，只用标准库，跨平台，LF，无 BOM）

  • 和 ps1 功能对等。输出目录、文件名、.ok 标记、SHA256SUMS 完全一致，两个脚本可以互相续传。
  • tar 校验改用 Python 的 tarfile；toybox 生成的 RHT.security.selinux pax 记录能正常解析。
  • 移植过程：1 个 agent 实现，3 个按方向审查，1 个修复，1 个离线测试，都用默认模型。审查提出 11 个问题，修了 9 个。没改的两个：一是分区排序的并列顺序，不影响结果；二是 Clash 的判断方式，实测 PowerShell 的哈希表本来就不区分大小写，现在的写法和 ps1 行为一致。
  • 离线测试用假 adb 跑，全部通过：全量、重跑跳过、--only、非 root、传输失败重试、tar 截断被拒收、分区内容读取中变化、各种特殊文件名、硬链接、只读检查。
  • 实机测试（只读，同一组分区）通过。misc、frp、metadata 的哈希和 ps1 那次相同；nvdata、persist 运行时会被写入，两次不同属正常。
  • 事故记录：负责实现的 agent 有一次没加 --adb 参数就运行了脚本，连到了真手机。只执行了只读命令（get-state、getprop、cat /proc/mounts、cat /proc/partitions、lpdump），没有 dd，也没有任何写入；产生的临时文本已删除。已如实告知用户。
  • 注意：之前用的 Python 虚拟环境 F:\tmp\gt7aod\venv 已随 tmp 一起删除，以后需要用系统 Python 运行。

5. 踩过的坑

  • PS 5.1 下 adb 的 stderr：在 ErrorActionPreference=Stop 时会被当成 NativeCommandError，需要在局部改成 Continue。
  • CRLF 脚本里的多行 here-string：发给手机前要去掉 \r。
  • toybox 打包后用 bsdtar 检查：tar --selinux 写的 pax 记录末尾带 NUL，bsdtar 会报 “malformed pax attributes”，但内容是完好的。判断包是否完整要看结尾的两个全零块。
  • adb 服务中途断开会让 tar 被截断：这就是加传输检查的原因。
  • fastbootd 识别不到手机：需要装 Google USB 驱动。
  • 刷入更大的镜像：逻辑分区会自动扩容。
  • Workflow 脚本不能含 CR：用 LF 写；单个 agent 的输出要限制长度，否则会超过 32k 输出上限。
  • Claude Pro 配额：顶级模型同时并行不超过 3 个。

6. 待办 / 可选

  • 如果以后需要完整的用户数据备份，用任意一个脚本加 --no-partitions / -NoPartitions，备份前先确认手机已解锁。
