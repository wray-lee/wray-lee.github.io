### 1. コアとオブジェクトシステム (Core & UObject System)
これらの関数は、ゲームワールドインスタンスの取得、オブジェクト型の判定、クラステンプレートの取得に使用する。

| 関数名                         | コード内での用法                           | 説明                                                         |
| :----------------------------- | :------------------------------------- | :----------------------------------------------------------- |
| **`UWorld::GetWorld()`**       | `UWorld::GetWorld()`                   | 現在のグローバルワールドポインタ（`UWorld*`）を取得する。すべてのロジックの入口。      |
| **`AActor::IsA(...)`**         | `Actor->IsA(...)`                      | Actorが特定のクラスに属するかどうかを判定する（モンスターかプレイヤーかなど）。 |
| **`UClass::StaticClass()`**    | `APlayer_char_main_C::StaticClass()`   | あるクラスのリフレクションオブジェクト（UClass*）を取得する。よく `IsA` と組み合わせて使用する。         |
| **`UObject::GetDefaultObj()`** | `APlayer_char_main_C::GetDefaultObj()` | あるクラスの**デフォルトオブジェクト（CDO）**を取得する。コード内では、倍率を計算するためにデフォルトの移動速度と基礎数値を読み取るのに使う。 |

### 2. 座標と空間 (Actor & Spatial)
これらの関数は、ゲームワールド内のオブジェクトの位置や距離を取得または設定するのに使用する。

| 関数名                                              | コード内での用法                                    | 説明                                                         |
| :-------------------------------------------------- | :---------------------------------------------- | :----------------------------------------------------------- |
| **`AActor::K2_GetActorLocation()`**                 | `Actor->K2_GetActorLocation()`                  | Actorの現在のワールド座標（`FVector`）を取得する。<br>*注：`K2_` 接頭辞が付くものは通常ブループリントに公開されたバージョンで、C++ネイティブは `GetActorLocation()`、SDKではK2バージョンがよく使われる。* |
| **`AActor::K2_SetActorLocation(...)`**              | `Actor->K2_SetActorLocation(TargetLoc, ...)`    | Actorを指定座標へテレポートする。コード内では**魔法の弾丸**（弾丸を敵の頭上へテレポートする）に使用。 |
| **`AActor::GetDistanceTo(...)`**                    | `MyChar->GetDistanceTo(Actor)`                  | 2つのActor間の3D距離を計算する（単位は通常センチメートル）。            |
| **`USceneComponent::K2_GetComponentLocation()`**    | `Monster->see_Scene->K2_GetComponentLocation()` | コンポーネント（モンスターの視界コンポーネントなど）のワールド座標を取得する。                     |
| **`USkinnedMeshComponent::GetSocketLocation(...)`** | `Monster->Mesh->GetSocketLocation(...)`         | スケルタルメッシュ上の指定**ボーンまたはソケット（Socket）**のワールド座標を取得する。コード内ではモンスターの頭部ボーン `bone_head` の位置取得に使用。 |

### 3. コントローラーとカメラ (Controller & Camera)
これらの関数は、プレイヤー視点の制御および3Dワールドから2Dスクリーンへの変換に関わる。

| 関数名                                                     | コード内での用法                                   | 説明                                                         |
| :--------------------------------------------------------- | :--------------------------------------------- | :----------------------------------------------------------- |
| **`APlayerController::ProjectWorldLocationToScreen(...)`** | `PC->ProjectWorldLocationToScreen(...)`        | **ワールドtoスクリーン（W2S）**。3D座標をスクリーン2D座標へ変換する。ESPやエイムクロスヘア描画の中核関数。 |
| **`APlayerCameraManager::GetCameraLocation()`**            | `PC->PlayerCameraManager->GetCameraLocation()` | カメラの現在の絶対ワールド座標を取得する（エイム角度計算の起点に使用）。     |
| **`AController::GetControlRotation()`**                    | `PC->GetControlRotation()`                     | プレイヤーの現在の視点回転角度（Aim Angles）を取得する。                   |
| **`AController::SetControlRotation(...)`**                 | `PC->SetControlRotation(FinalRot)`             | プレイヤーの視点回転角度を設定する。コード内では**エイムボット**（視点を強制的に敵へ向ける）に使用。 |

### 4. 数学ライブラリ (Kismet Math Library)
UEがラップした数学ライブラリを使用して、複雑なベクトルと角度の計算を行い、手書きの数学関数を置き換えている。

| 関数名                                            | コード内での用法                                             | 説明                                                         |
| :------------------------------------------------ | :------------------------------------------------------- | :----------------------------------------------------------- |
| **`UKismetMathLibrary::FindLookAtRotation(...)`** | `UKismetMathLibrary::FindLookAtRotation(Start, Target)`  | 始点から終点を見るために必要な回転角度（Rotator）を計算する。コード内ではエイムの理想角度計算に使用。 |
| **`UKismetMathLibrary::RLerp(...)`**              | `UKismetMathLibrary::RLerp(Current, Target, Alpha, ...)` | **回転補間**。スムーズなエイムに使用し、クロスヘアを瞬間的に固定するのではなく、目標角度へ滑らかに移行させる。 |



## Unity

対象をUnreal Engine (UE)から**Unity**へ移すと、基盤となるプログラミングパラダイムは**C++ (UE SDK)**から**C# (Unity API / Mono)**へ変わる。

論理の中核（距離計算、エイム角度など）は同じだが、**API名**、**オブジェクト構造**、**座標系**は大きく異なる。

以下は、あなたのコードで使用されているUE関数のUnityにおける対応関係のまとめである：

### 1. コアシステムとオブジェクト取得 (Core & Object)

UEは `UWorld` -> `Level` -> `Actor` の階層に基づき、Unityは `Scene` -> `GameObject` -> `Component` に基づく。

| UEネイティブ関数 (C++)                 | Unity対応API (C#)                                          | 説明                                                         |
| :-------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| `UWorld::GetWorld()`              | `SceneManager.GetActiveScene()`                              | Unityには単一のWorldポインタはなく、通常はシーンマネージャー経由でアクセスする。        |
| `UWorld->PersistentLevel->Actors` | `Object.FindObjectsOfType<T>()`<br>または `GameObject.FindGameObjectsWithTag()` | **これが最大の違い**。Unityではいわゆる「GObjectListの走査」を行う。通常、敵を見つけるにはすべてのオブジェクトリストを走査する必要がある。 |
| `Actor->IsA(Class)`               | `obj is EnemyClass`<br>または `obj.GetComponent<EnemyClass>() != null` | C#の型判定はより直感的で、`is` キーワードを直接使うか、あるスクリプトコンポーネントがアタッチされているかを判定する。 |
| `GetDefaultObj()` (CDO)           | `Prefab` (プレハブ)                                            | UnityにはCDOの概念がない。通常はPrefabリソースを直接読むか、基礎数値をハードコードする。 |
| `Actor`                           | `GameObject`                                                 | ゲーム内のエンティティ基底クラス。                                           |
| `APlayerController`               | 厳密な対応はなく、通常は `Update()` に分散している                            | プレイヤー入力ロジックは通常、主人公にアタッチされた `MonoBehaviour` スクリプトに書かれる。  |

### 2. 座標と空間 (Transform & Spatial)

**座標系の違いに注意**：UEは**Z軸が上**（Right-handed/Left-handed混用）、Unityは**Y軸が上**（Left-handed）。

| UEネイティブ関数                   | Unity対応API                                            | 説明                                                         |
| :---------------------------- | :-------------------------------------------------------- | :----------------------------------------------------------- |
| `FVector`                     | `Vector3`                                                 | 基本ベクトル構造体 (x, y, z)。                                   |
| `K2_GetActorLocation()`       | `transform.position`                                      | ワールド座標を取得する。                                               |
| `K2_SetActorLocation(...)`    | `transform.position = newPos`                             | ワールド座標を設定する（テレポート/魔法の弾丸を実現）。                      |
| `GetDistanceTo(Actor)`        | `Vector3.Distance(posA, posB)`                            | 2点間の距離を計算する。                                             |
| `GetSocketLocation(BoneName)` | `animator.GetBoneTransform(HumanBodyBones.Head).position` | **ボーン取得**。標準人型でない場合は、`transform.Find("Root/Spine/Head")` で子オブジェクトを走査して頭部ノードを見つける。 |
| `K2_GetComponentLocation()`   | `component.transform.position`                            | コンポーネントもGameObjectに付随しているので、そのtransformを直接取得する。           |

### 3. カメラとスクリーン変換 (Camera & W2S)

これはESPとエイムボットを行う上で最も重要な部分である。

| UEネイティブ関数                    | Unity対応API                                               | 説明                                                         |
| :----------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| `ProjectWorldLocationToScreen` | `Camera.main.WorldToScreenPoint(pos)`                        | **W2Sの中核**。注意：Unityのスクリーン原点 `(0,0)` は**左下**にあり、ImGui/描画ライブラリの原点は通常**左上**である。**Y軸反転を手動で計算する必要がある**：`screen.y = Screen.height - screen.y`。 |
| `GetCameraLocation()`          | `Camera.main.transform.position`                             | メインカメラの位置を取得する。                                           |
| `GetControlRotation()`         | `Camera.main.transform.eulerAngles`<br>または `transform.localEulerAngles` | Unityには強制的な「コントローラー回転」はない。通常はカメラのオイラー角を直接読み取る。   |
| `SetControlRotation()`         | `transform.eulerAngles = new Vector3(...)`                   | カメラ角度を設定する（エイムボットを実現）。                   |

### 4. 数学とエイム計算 (Math & Aimbot)

Unity内部では回転を**クォータニオン (Quaternion)**で処理するが、便宜上、通常は**オイラー角 (Euler Angles/Vector3)**を外部に公開する。

| UEネイティブ関数                      | Unity対応API                                               | 説明                                                         |
| :------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| `FRotator`                       | `Quaternion` (内部) / `Vector3` (外部)                       | UEのRotatorは (Pitch, Yaw, Roll)、UnityのVector3は (x, y, z) が (Pitch, Yaw, Roll) に対応する。 |
| `FindLookAtRotation(Start, End)` | `Quaternion.LookRotation(Target - Start)`<br>または `transform.LookAt(Target)` | 目標へ向く回転クォータニオンを計算する。                                   |
| `RLerp` / `RInterpTo`            | `Quaternion.Slerp(curr, target, t)`<br>または `Quaternion.RotateTowards(...)` | **スムーズエイム**。Slerpは球面補間で、Lerpより回転に適している。         |
| `ClampAngles` (カスタム)           | `Mathf.Clamp` / `Mathf.DeltaAngle`                           | Unityの `Mathf.DeltaAngle` は -180 から 180 の角度差問題を自動処理するので非常に便利で、あの `while > 180` のロジックを手書きする必要がない。 |

### コード移行例 (C++ UE -> C# Unity)

簡単な**エイムボット (Aimbot)**ロジックを実装すると仮定した場合、コードスタイルの変化は以下のとおり：

#### UE (C++)
```cpp
FVector CamLoc = PC->PlayerCameraManager->GetCameraLocation();
FVector TargetLoc = EnemyHeadPos;

// 计算角度
FRotator TargetRot = UKismetMathLibrary::FindLookAtRotation(CamLoc, TargetLoc);

// 设置角度
PC->SetControlRotation(TargetRot);
```

#### Unity (C#)
```csharp
Vector3 CamLoc = Camera.main.transform.position;
Vector3 TargetLoc = EnemyHeadPos; // 获取方式见下文

// 计算方向向量
Vector3 Direction = TargetLoc - CamLoc;

// 计算目标旋转 (四元数)
Quaternion TargetRot = Quaternion.LookRotation(Direction);

// 设置角度 (通常设置摄像机或玩家身体的欧拉角)
// Unity 中 Pitch 是 X轴, Yaw 是 Y轴
Camera.main.transform.rotation = TargetRot; 

// 或者如果只想要平滑移动：
Camera.main.transform.rotation = Quaternion.Slerp(Camera.main.transform.rotation, TargetRot, Time.deltaTime * SmoothSpeed);
```

### Unity Hookの相違点まとめ

1.  **ボーン位置 (Head Position)**:
    *   **UE**: `Mesh->GetSocketLocation("head")` を使用。
    *   **Unity**: ボーンは普通のGameObjectである。階層を走査して "Head" という名前の子オブジェクトを見つけるか、`Animator` を使っている場合は `animator.GetBoneTransform(HumanBodyBones.Head)` を使える。

2.  **ワールドtoスクリーン (W2S) の落とし穴**:
    *   Unityの `WorldToScreenPoint` が返すZ軸は深度である。
    *   **`result.z > 0` を判定する必要がある**。そうして初めてカメラ前方のオブジェクトとなる（この点はUEのreturn boolに似ている）。
    *   **Y軸を反転する必要がある**：ImGuiで描画する場合、Unityの `y` は下端から計算し、ImGuiは上端から計算する。
    *   コード：`screenPos.y = Screen.height - screenPos.y;`

3.  **リスト検索**:
    *   UEリバースでは通常、`GWorld` -> `Level` -> `ActorArray` のオフセットを探す。
    *   Unityリバース (Mono) では通常、`BaseEntity` クラスの静的リンクリストを探すか、`GameObject` の特定関数を直接Hookしてオブジェクトリストを収集する。

## エイムボット

````cpp
bool bAimbot = false;
bool bMagicBullet = false;
float fAimbotFOV = 150.0f;  // 自瞄范围
float fAimbotSmooth = 1.0f; // 平滑度 (1.0 = 锁死)
bool bDrawFOV = true;       // 绘制 FOV 圈

auto MyController = GetPlayerController();
//通过for循环遍历附近敌人
if (bAimbot || bMagicBullet)
{
   for (AActor *Actor : Actors)
   {
       if (!Actor || Actor == MyChar)
           continue;

       // 筛选: 必须是怪物类型
       if (GetActorType(Actor) != EActorType::Enemy)
           continue;

       auto Monster = static_cast<AMG_AI_actor_master_C *>(Actor);
       if (Monster->is_death || Monster->HP_current <= 0)
           continue;

       // 获取头部位置
       FVector HeadPos = GetEnemyHeadPos(Actor);
       FVector2D ScreenPos;

       // 转换并判断是否在 FOV 内
       if (PC->ProjectWorldLocationToScreen(HeadPos, &ScreenPos, true))
       {
           float Dist = Math::GetDistance2D(ScreenCenter, ScreenPos);
           if (Dist < BestDist)
           {
               BestDist = Dist;
               BestTarget = Actor;
           }
       }
   }
   CurrentTarget = BestTarget; // 更新全局目标
}
// 如果没有目标，后续都不执行
if (!CurrentTarget) return;
FVector TargetLoc = GetEnemyHeadPos(CurrentTarget);
//获取相机与敌人坐标
FVector CamLoc = MyController->PlayerCameraManager->GetCameraLocation();
FRotator CurrentRot = MyController->GetControlRotation();

FRotator TargetRot = UKismetMathLibrary::FindLookAtRotation(CamLoc, TargetLoc);
FRotator FinalRot = UKismetMathLibrary::RLerp(CurrentRot, TargetRot, fAimbotSmooth, true);
````

## ノークリップ

```markdown
// --- 定义在 namespace menu 里或者 Loop 外面的静态变量 ---
    static bool bNoclip = false;       // 开关
    static float fNoclipSpeed = 20.0f; // 飞行速度 (根据游戏单位调整，通常 10-50 之间)
    
    // ==========================================
    // 将以下代码放入 Loop() 函数内部
    // ==========================================

    if (bNoclip)
    {
        // 1. 关闭碰撞 (穿墙的关键)
        // 如果 SDK 没有生成 SetActorEnableCollision，你需要手动修改内存或用 ProcessEvent
        // 绝大多数 Dumper-7 SDK 都有这个函数
        MyChar->SetActorEnableCollision(false);

        // 2. 获取当前数据
        // 获取相机的旋转角度（你看向哪里）
        FRotator CameraRot = MyController->GetControlRotation(); 
        // 获取当前坐标
        FVector CurrentPos = MyChar->K2_GetActorLocation();
        
        FVector NextPos = CurrentPos;

        // 3. 计算方向向量
        FVector ForwardVec = GetForwardVector(CameraRot); // 准星方向
        FVector RightVec = GetRightVector(CameraRot);     // 侧身方向

        // 4. 处理按键输入 (W/A/S/D/Space/Ctrl)
        bool bIsMoving = false;

        // W: 向准星方向飞
        if (GetAsyncKeyState('W') & 0x8000) {
            NextPos.X += ForwardVec.X * fNoclipSpeed;
            NextPos.Y += ForwardVec.Y * fNoclipSpeed;
            NextPos.Z += ForwardVec.Z * fNoclipSpeed;
            bIsMoving = true;
        }
        // S: 向后退
        if (GetAsyncKeyState('S') & 0x8000) {
            NextPos.X -= ForwardVec.X * fNoclipSpeed;
            NextPos.Y -= ForwardVec.Y * fNoclipSpeed;
            NextPos.Z -= ForwardVec.Z * fNoclipSpeed;
            bIsMoving = true;
        }
        // D: 向右飞
        if (GetAsyncKeyState('D') & 0x8000) {
            NextPos.X += RightVec.X * fNoclipSpeed;
            NextPos.Y += RightVec.Y * fNoclipSpeed;
            NextPos.Z += RightVec.Z * fNoclipSpeed; // 加上Z轴分量可以倾斜飞行，如果不加就是水平横移
            bIsMoving = true;
        }
        // A: 向左飞
        if (GetAsyncKeyState('A') & 0x8000) {
            NextPos.X -= RightVec.X * fNoclipSpeed;
            NextPos.Y -= RightVec.Y * fNoclipSpeed;
            NextPos.Z -= RightVec.Z * fNoclipSpeed;
            bIsMoving = true;
        }

        // Space: 垂直上升 (可选，方便调整高度)
        if (GetAsyncKeyState(VK_SPACE) & 0x8000) {
            NextPos.Z += fNoclipSpeed;
            bIsMoving = true;
        }
        // Ctrl: 垂直下降
        if (GetAsyncKeyState(VK_CONTROL) & 0x8000) {
            NextPos.Z -= fNoclipSpeed;
            bIsMoving = true;
        }

        // 5. 应用新坐标
        if (bIsMoving) {
            // 参数2: bSweep (是否检测碰撞)，设为 false
            // 参数3: SweepHitResult，设为 nullptr
            // 参数4: bTeleport，设为 true (告诉物理引擎这是瞬移，不要计算速度/动量)
            MyChar->K2_SetActorLocation(NextPos, false, nullptr, true);
        }
    }
    else
    {
        // 6. 关闭 Noclip 时，恢复碰撞
        // 使用静态变量确保只执行一次恢复操作，避免每帧重复调用消耗性能
        static bool last_bNoclipState = false;
        if (last_bNoclipState != bNoclip) {
            if (!bNoclip) {
                MyChar->SetActorEnableCollision(true);
                // 可选：如果关掉时卡在墙里，可能会被弹飞，这是正常物理现象
            }
            last_bNoclipState = bNoclip;
        }
    }
```

1. **ImGui::End()**：Begin() の if の**外側**に書く（つまり、Beginが何を返しても必ずEndを呼び出す）。

```cpp
            // if (Player->Is_death_ || Player->Is_down_) break; // 死了不画

            break;
        }

        case EActorType::Enemy:
        {
            if (!bEspMonster)
                break;

            auto Monster = static_cast<AMG_AI_actor_master_C *>(Actor);
            if (Monster->is_death)
                break; // 死了不画

            char Buf[64];
            // 可以在这里根据 Monster->monster_type 进一步 switch 显示不同怪名字
            sprintf_s(Buf, "Enemy [%.0fm]\nHP: %d", Distance, (int)Monster->HP_current);

            // 红色显示
            DrawText3D(PC, Pos + FVector(0, 0, 100), Buf, col_Monster);
            break;
        }

        case EActorType::Chest:
        {
            if (!bEspLT)
                break; // 假设 LT 也是控制掉落的

            // 黄色显示
```

# 数学ライブラリ（エンジンネイティブ関数がない場合に使用）

```cpp
namespace Math
{
    float GetDistance2D(FVector2D A, FVector2D B)
    {
        return sqrt(pow(A.X - B.X, 2) + pow(A.Y - B.Y, 2));
    }

    FRotator VectorToRotator(FVector Start, FVector Target)
    {
        FVector Delta = Target - Start;
        float Hyp = sqrt(Delta.X * Delta.X + Delta.Y * Delta.Y);
        FRotator Rot;
        Rot.Yaw = atan2(Delta.Y, Delta.X) * (180.0f / M_PI);
        // ue中pitch相反
        Rot.Pitch = -atan2(Delta.Z, Hyp) * (180.0f / M_PI);
        Rot.Roll = 0.0f;
        return Rot;
    }

    // 将角度标准化到 -180 ~ 180
    // 有引擎原生 FRotator Delta = UKismetMathLibrary::NormalizedDeltaRotator(Target, Current);
    // Result.Normalize();
    FRotator ClampAngles(FRotator Rot)
    {
        // 1. 先处理 Yaw 的归一化
        while (Rot.Yaw > 180.0f)
            Rot.Yaw -= 360.0f;
        while (Rot.Yaw < -180.0f)
            Rot.Yaw += 360.0f;

        // 2. 先处理 Pitch 的归一化，再进行 Clamp
        // 如果不加这个，当 Delta 超过 180 度时（比如 360），会被错误地截断成 89
        while (Rot.Pitch > 180.0f)
            Rot.Pitch -= 360.0f;
        while (Rot.Pitch < -180.0f)
            Rot.Pitch += 360.0f;

        // 3. 最后再限制俯仰角在合法范围内
        if (Rot.Pitch > 89.0f)
            Rot.Pitch = 89.0f;
        if (Rot.Pitch < -89.0f)
            Rot.Pitch = -89.0f;

        Rot.Roll = 0.0f;
        return Rot;
    }

    // 平滑插值
    FRotator SmoothAngle(FRotator Current, FRotator Target, float Smooth)
    {
        FRotator Delta = Target - Current;
        Delta = ClampAngles(Delta);
        return ClampAngles(Current + Delta * Smooth);
    }
    // noclip

    FVector GetCameraForward(FRotator Rot)
    {
        float sp = sin(DEG2RAD(Rot.Pitch));
        float cp = cos(DEG2RAD(Rot.Pitch));
        float sy = sin(DEG2RAD(Rot.Yaw));
        float cy = cos(DEG2RAD(Rot.Yaw));
        return {cp * cy, cp * sy, sp};
    }

    FVector GetCameraRight(FRotator Rot)
    {
        float sy = sin(DEG2RAD(Rot.Yaw));
        float cy = cos(DEG2RAD(Rot.Yaw));
        return {-sy, cy, 0.0f};
    }
}
```

# Source

**起源エンジン (Source Engine)** はValveが開発したエンジン（代表作：CS:GO/CS2, Apex Legends, L4D2, TF2）。

Unreal EngineからSource Engineへ移ると、最大の違いは次の点にある：UEは**リフレクションシステム (UObject/Reflection)**に強く依存し、Source Engineは**仮想関数インターフェース (Virtual Interfaces)**と**ネットワーク変数 (Netvars)**に強く依存する。

以下は、あなたが使用した機能のSource Engineにおける対応方法である：

### 1. コアシステムとオブジェクト取得 (Interfaces vs UWorld)
UEにはグローバルな `UWorld` があり、その中にすべてのActorが格納されている。
Source Engineは**インターフェースパターン (Interface Pattern)**を使用する。エンジンが公開しているグローバルインターフェースポインタを取得する必要がある。

| UEネイティブ関数               | Source Engine対応インターフェース/メソッド                                  | 説明                                                         |
| :------------------------ | :----------------------------------------------------------- | :----------------------------------------------------------- |
| `UWorld::GetWorld()`      | 単一の入口はなく、通常は **`IClientEntityList`** と **`IVEngineClient`** を取得する | これらのグローバルインターフェースを取得するには、`CreateInterface` のエクスポート関数を使う必要がある。    |
| `PersistentLevel->Actors` | **`IClientEntityList::GetClientEntity(index)`**              | Sourceのエンティティはインデックス配列に格納されている。Index 0はワールド、1~64はプレイヤー、64+はエンティティ/武器。`for` ループを書いて0から `GetHighestEntityIndex()` まで走査する必要がある。 |
| `Actor`                   | **`C_BaseEntity`** / `IClientEntity`                         | すべてのオブジェクトの基底クラス。                                             |
| `IsA(...)`                | `GetClientClass()->m_pNetworkName`                           | Sourceは `ClientClass` リンクリストで型を判定する。通常はClassID（例：`CCSPlayer`）を比較する。 |
| `APlayerController`       | `C_BasePlayer` (Local)                                       | ローカルプレイヤーは通常 `GetClientEntity(GetLocalPlayerIndex())` で取得する。 |

### 2. 座標と空間 (Vectors & Netvars)
UEの属性（HP、Posなど）は通常クラスメンバ変数である。
Source Engineの属性は通常**Netvars (ネットワーク変数)**であり、メモリオフセット（Offset）またはRecvTableを読み取って取得する。

| UEネイティブ関数                     | Source Engine対応                    | 説明                                                         |
| :------------------------------ | :------------------------------------ | :----------------------------------------------------------- |
| `FVector` (X, Y, Z)             | **`Vector`** (x, y, z)                | これもZ軸が上。                                              |
| `FRotator` (Pitch, Yaw, Roll)   | **`QAngle`** (Pitch, Yaw, Roll)       | 角度専用の構造体。                                       |
| `K2_GetActorLocation()`         | `GetAbsOrigin()` または `m_vecOrigin` を読み取る | 座標を取得する。                                                   |
| `K2_SetActorLocation(...)`      | 直接Setはできない。                        | Sourceはサーバー検証が強い。ローカル座標を変更しても通常は引き戻される。テレポートは通常、脆弱性の悪用（L4D2のwarpなど）か特定パケットの送信による。 |
| `GetSocketLocation(...)` (ボーン) | **`SetupBones`** + `m_dwBoneMatrix`   | **これが難点**。Sourceでは `SetupBones` を呼び出してボーン行列を更新し、その後、行列配列からボーンインデックス（例：8=Head）で座標を読み取る必要がある。 |
| `HP_current` (メンバ変数)         | `m_iHealth` (Netvar)                  | Netvar Managerで `DT_BasePlayer` テーブルをスキャンし、`m_iHealth` のオフセットを見つける必要がある。 |

### 3. カメラと入力 (CreateMove vs SetControlRotation)
これがSource Engine Hookの真髄である。
UEではControllerのRotationを直接変更する。
Sourceでは通常、**`CreateMove`** 関数をHookする。

| UEネイティブ関数          | Source Engine対応              | 説明                                                         |
| :------------------- | :------------------------------ | :----------------------------------------------------------- |
| `SetControlRotation` | **`CUserCmd::viewangles`**      | `CreateMove` では、毎フレームクライアントが `CUserCmd` を生成してサーバーへ送る。`cmd->viewangles` を直接変更すればエイムボットを実現できる。 |
| `GetControlRotation` | `IVEngineClient::GetViewAngles` | 現在の視点を取得する。                                               |
| **利点**             | **Silent Aim (サイレントエイム)**       | Sourceでは、サーバーへ送る `viewangles` を変更しつつ、ローカルカメラの角度を**変更しない**ことができる。結果として、前方を見ているのに弾丸は横の敵へ飛ぶ。UEでこれを行うのは難しい（通常はBone Transformを変更する必要がある）。 |

### 4. ワールドtoスクリーン (W2S)
Source EngineのW2Sは**ViewMatrix (ビュー行列)**に依存する必要がある。

| UEネイティブ関数                    | Source Engine対応         | 説明                                                         |
| :----------------------------- | :------------------------- | :----------------------------------------------------------- |
| `ProjectWorldLocationToScreen` | **`WorldToScreen` (手書き)** | `IVEngineClient` またはレンダラーから **ViewMatrix** (4x4行列) を見つける必要がある。その後、標準的な行列乗算で3Dを2Dへ変換する。 |
| Debug描画                     | `ISurface` インターフェース            | Sourceは `ISurface` インターフェースを提供しており、線、文字、矩形を描画できる。ImGuiよりネイティブだが（現代のチートではImGuiの方が流行っている）。 |

### 5. レイキャスト (RayCast / Visibility)
敵が壁の後ろにいるかどうかを判定する。

| UEネイティブ関数       | Source Engine対応           | 説明                                                         |
| :---------------- | :--------------------------- | :----------------------------------------------------------- |
| `LineTraceSingle` | **`IEngineTrace::TraceRay`** | これは非常に強力なインターフェースである。`Ray_t` と `CTraceFilter` を構築し、エンジンのTraceRayを呼び出して可視性を検出する必要がある。 |

### Source Engine Hookの特徴まとめ

1.  **より「低レベル」**: UEほど多くのラップ済み `K2_` 関数はなく、多くの場合、行列とベクトルを操作する必要がある。
2.  **Netvars (ネットワーク変数)**: RecvTableを理解する必要がある。すべてのゲームデータはネットワークテーブル経由で同期され、リバース時は主にこれらのテーブルのオフセットをdumpする。
3.  **CreateMove**: これがSourceチートの中核であり、すべての連続ジャンプ(Bhop)、エイムボット(Aimbot)、Anti-Aim、自動トリガー(Triggerbot)はここで実装される。
4.  **Dormant (休眠)**: Sourceはネットワーク最適化のため、遠くの敵データをクライアントへ送らない。もし `IsDormant() == true` なら、敵がどこにいるかすら分からない（これは透視対策の天然の障壁であり、UEは通常、Relevancy最適化が有効でない限りすべてのActorを送ってくる）。
