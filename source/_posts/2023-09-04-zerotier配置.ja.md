## ルーティング転送

### カーネル転送機能を有効にする

`sudo sysctl -w net.ipv4.ip_forward=1`

v6 も同様

---

より良い選択

```bash
echo "net.ipv4.ip_forward=1" >> /etc/sysctl.conf
echo "net.ipv6.conf.default.forwarding=1" >> /etc/sysctl.conf
echo "net.ipv6.conf.all.forwarding=1" >> /etc/sysctl.conf
sysctl -p
```

厳格モードを無効にする

```bash
echo "net.ipv4.conf.default.rp_filter=0" >> /etc/sysctl.conf
echo "net.ipv4.conf.all.rp_filter=0" >> /etc/sysctl.conf
sysctl -p
```

#### 説明

​			**`rp_filter `**

​			Linux カーネルのネットワーク向けネットワークセキュリティ保護機能で、パケットの送信元アドレスと送信元ネットワークインターフェース（NIC）を検査します：

- 0（つまり無効）に設定すると、すべてのパケットを通過させます。

- ただし、正常に応答できない（ルーティングテーブルに対応する項目がない）一部のパケットもアプリケーションに渡されて処理され、余分なシステムリソースを消費します。
- ただし、余分な消費はごくわずかであるはずなので、上記2項目を0に設定しても問題ありません。
- 1（厳格モード）に設定すると、パケットの送信元 NIC がこのパケットを送信するための最適な NIC でない場合（つまり、このアドレスに応答する際に別の NIC を選ぶ場合）、このパケットを

破棄

します。

- 送信元と応答が異なる NIC であることは DN42 内で**非常に一般的な状況**であるため、**絶対に 必ず 断固として** `rp_filter` を 1 に設定してはいけません！
- 2（ルーズモード）に設定すると、

理論上は

、パケットの送信元アドレスがルーティングテーブルにない場合（つまり、本機がこのアドレスにどう応答すればよいか分からない場合）、このパケットを破棄します。

- しかし、理論は理論として、新しいバージョン（5.0+）のカーネルでは、実際の使用においても送信元アドレスが正しい正常なパケットが大量に破棄されます。したがって、このモードは使用せず、統一して 0 を使用してください。
- 次に、**絶対に 必ず 断固として** あなたの UFW など、iptables ファイアウォールを簡単に設定してくれるツールを無効にしてください。

### ファイアウォールルールを追加する

```bash
sudo iptables -t nat -A POSTROUTING -o $PHY_IFACE -j MASQUERADE
sudo iptables -A FORWARD -i $PHY_IFACE -o $ZT_IFACE -m state --state RELATED,ESTABLISHED -j ACCEPT
sudo iptables -A FORWARD -i $ZT_IFACE -o $PHY_IFACE -j ACCEPT
iptables-save	#保存
```
