## 演算子

```
>`	输出重定向，右移，实际上是`1>` `将左边语句的输出覆盖写入到右边文件内，相当于`** | tee some_text.txt
>>`	输出追加重定向，右右移，将左边语句的输出添加到右边文件末尾，相当于`** | tee -a some_text.txt
```

`<`	入力リダイレクト	`command < file`	ファイルから読み込む

`<<`	入力追記リダイレクト	`command << EOF`	後続の入力を `EOF` まで読み込む	（命令に終了条件を追加するのに使える）

```shell
 cat << EOF > tmp
 1
 2
 3
 EOF
 
 #则tmp中为
 1
 2
 3
```



`|`	パイプ、左側の文の出力を右側の文の入力とする

`||`	OR OR、左側の文の実行が失敗した場合にのみ右側の文を実行する

`&`	AND、左側の文の実行が失敗しても成功しても右側の文を実行する、AND でつないだすべての文を実行する。	末尾に置くとプログラムをバックグラウンド実行させる

`&&`	AND AND、左側の文の実行が失敗すると右側の文は実行されず、成功すれば右側の文を実行する

`!` 	条件式の否定



`>&`	ファイル操作記号,	例:`2>&1`	, `2>1`はエラー出力を「1」という名前のファイルへリダイレクトする, `&`は後続の `1` がファイル記述子であることを定義するため

```
&<
```

​	用法：`echo "hello" > a.log 2>&1`	1 は a.log にリダイレクトされ、2 は a.log にリダイレクトされ、2 が 1 にリダイレクトされることに等しい。目的は log に正常出力とエラー出力を記録すること

​			省略して `echo "hello" >&log`	または	`echo "hello" &>log` と書ける

*`2&>1 >log `	は無効な入力であり、error が 1 ファイルに書き込まれる原因になる*



`-a`	条件式の並列（AND）

`-o`	条件式の OR

`$`	後ろに変数名を続けると全体で 1 つの変数を表す

```
""
''
 `` ``   反引号，指令内部嵌套指令使用，可以用$(command)代替
```

`echo -e`	エスケープ文字を認識できる

## 権限

Linux のセキュリティシステムは SELinux（Security-Enhanced Linux）で、ファイル権限を管理できる

### `ls -lZht`

```bash
-rw-r--r--.  1 user group unconfined_u:object_r:user_home_t:s0 4096 Sep 27 10:30 file.txt
```

`unconfined_u:object_r:user_home_t:s0` はファイルとディレクトリのセキュリティコンテキストである。これには、ファイルまたはディレクトリが属するユーザー、ロール、オブジェクトクラス、およびセキュリティレベルに関する情報が含まれる。

1. `unconfined_u`：そのファイルまたはディレクトリが属する SELinux ユーザーを表す。`unconfined_u` は特別なユーザー識別子で、制限されていないユーザー、つまり厳格な SELinux ポリシー制限を受けていないことを表す。
2. `object_r`：そのファイルまたはディレクトリが属する SELinux オブジェクトロールを表す。オブジェクトロールは、SELinux ポリシーでそのオブジェクトの操作を許可されるロールの集合を定義する。
3. `user_home_t`：そのファイルまたはディレクトリの SELinux オブジェクトタイプを表す。オブジェクトタイプは、ファイルまたはディレクトリの用途と許可される操作を定義する。`user_home_t` は一般的なオブジェクトタイプで、ユーザーのホームディレクトリを表すために使われる。
4. `s0`：そのファイルまたはディレクトリの SELinux セキュリティレベルを表す。セキュリティレベルはオブジェクトのアクセス権限を制御し、アクセス規則に従って制限するために使われる。

例:

`systemd_unit_file_t` は SELinux のオブジェクトタイプの 1 つで、systemd ユニットファイルのセキュリティコンテキストを表すために使われる。



#### SELinux ファイル権限の変更`chcon`

1. ファイルのセキュリティコンテキストを変更する：

    ```bash
    chcon unconfined_u:object_r:user_home_t:s0 file.txt
    ```

2. ディレクトリとそのすべてのサブディレクトリおよびファイルのセキュリティコンテキストを再帰的に変更する：

    ```bash
    chcon -R unconfined_u:object_r:user_home_t:s0 directory/
    ```

3. シンボリックリンクのセキュリティコンテキストを変更する：

    ```bash
    chcon -h unconfined_u:object_r:user_home_t:s0 symlink
    ```

4. 対象のセキュリティコンテキストタイプを設定する：

    ```bash
    chcon -t httpd_sys_content_t index.html
    ```



##### chown との違い

`chown` は基本的なファイル `所有者:组` 権限を変更するために使われ、基本ファイルシステムの権限である

`chcon` は SELinux 上でファイル権限を変更する

## 文法

### 正規表現

> 実行中は一度に 1 文字しかマッチできない	（キューのように）順にマッチ・検索し、飛ばすことはできない

#### 演算子の優先順位（上から下へ低くなる）

> エスケープが最優先	括弧が 2 番目	量指定子（演算子）が 3 番目	位置指定子が 4 番目	OR が最低

```bash
\ 				转义符
() []			括号
* + {x,y}		限定符
^ $ \字符       定位点
|				或
```



`&` は内容なしで、処理しない（実際には & はパターンスペース、つまり現在処理している行/マッチした行、すなわち内容そのもの）

```bash
^								# 标记内容开头，必须放在匹配内容首
$								# 标记内容结尾，必须放在匹配内容尾

# 限制符  只作用于前面的相邻的一个内容
.*	{0,}						# 匹配所有内容 0次或多次	（用于匹配所有内容）
.+ .{1,}						# 匹配所有内容 1次或多次
.? .{0,1}						# 匹配所有内容 0次或1次
.{0,3}  						# 匹配所有内容 0到3次
##

?								# 放在限制符后匹配模式为非贪婪(决定于限制符)
# eg:对于"oooo" 
# o+	匹配所有o	oooo
# o+?	匹配一个o	o

(?)								# 用作条件判断
(?=)							# 正向肯定预查
(?:)							# 正向或预查    不进行存储，使用后即销毁
(?!)							# 正向否定预查

(?<=)							# 反向肯定预查
(?<:)							# 反向或预查
(?<!)							# 反向否定预查
{
	[windows(?=xp|10|11)]	# 匹配windowsxp windows10 windows11
	[(?<=xp|10|11)windows]	# 匹配xpwindows 10windows 11windows
# 根据与字符绑定情况的位置不同
}



[0-9] 							# 表示所有数字
[a-z]							# 表示所有小写字母
[A-Za-z]						# 表示所有英文字母
\p{L}							# 匹配任何字母（使用unicode字母字符类）
[[:alpha:]] 任意字母
[[:upper:]] 任意大写字母
[[:lower:]] 任意小写字母

[[:digit:]] 任意数字
[[:xdigit:]] 任意16进制数字

[[:alnum:]]	任意字母和数字

[[:punct:]] 任意标点符号
[[:space:]] 任意空格



[x|y]							# 匹配x或y
[xx|xy] [x(?:x|y)]				# 匹配xx或xy
[x]								# 匹配x
[^x] 							# 匹配不包含x的
```
