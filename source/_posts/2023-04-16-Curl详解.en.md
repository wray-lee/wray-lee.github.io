# Curl Detailed Explanation

## `curl -kfsSL`

- `-k/--insecure`	Allow connecting to SSL sites without using certificates
- `-f/--fail`    Do not display HTTP errors when connection fails. On server errors, prevent an HTML page indicating the cause of the error from being returned, and instead have the curl command return error code 22 to indicate the error (to avoid returned HTML being inconvenient for debugging)
- `-s/--silent`    Silent mode. Output nothing. Will not output error and progress information.
- `-S/--show-error`    Show errors. Specify to output only error messages, usually used together with `-s`.
- `-L/--location`    Makes HTTP requests follow server redirects. curl does not follow redirects by default.

curl -fsSL means when using the curl command to download files, do not display progress and error information, stop immediately if the download fails, and automatically follow redirects. This is usually a quiet, safe, and stable way to download files.

## Differences

- `-l/--list-only`    List file names in the ftp directory
- `-F `   The parameter is used to upload binary files to the server.

## Other Commands

`-o`		The parameter saves the server response as a file, equivalent to the `wget` command.

`curl -o example.html https://www.example.com`

`-O`		The parameter saves the server response as a file and uses the last part of the URL as the filename. (No need to name it)

`curl -O https://www.example.com/foo/bar.html`

`--limit-rate` is used to limit the bandwidth of HTTP requests and responses, simulating a slow network environment.

`curl --limit-rate 200k https://google.com`

# curl Usage Guide

Author: [Ruan Yifeng](https://www.ruanyifeng.com/)

Date: [September 5, 2019](https://www.ruanyifeng.com/blog/2019/09/)

## Introduction

curl is a commonly used command-line tool for making requests to web servers. Its name means the URL tool of the client (client).

Its functionality is very powerful, with dozens of command-line parameters. If you are proficient, it can completely replace graphical interface tools like Postman.

![img](https://www.wangbase.com/blogimg/asset/201909/bg2019090501.jpg)

This article introduces its main command-line parameters as a daily reference for easy lookup. The content is mainly translated from [curl cookbook](https://catonmat.net/cookbooks/curl). To save space, the examples below do not include runtime output. Beginners can first read my previously written [curl Beginner Tutorial](https://www.ruanyifeng.com/blog/2011/09/curl.html).

When no parameters are provided, curl sends a GET request.

> 
>
> ```bash
> $ curl https://www.example.com
> ```

The above command sends a GET request to `www.example.com`, and the content returned by the server will be output on the command line.

## **-A**

The `-A` parameter specifies the client's user agent header, i.e. `User-Agent`. curl's default user agent string is `curl/[version]`.

> ```bash
> $ curl -A 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/76.0.3809.100 Safari/537.36' https://google.com
> ```

The above command changes `User-Agent` to the Chrome browser.

> ```bash
> $ curl -A '' https://google.com
> ```

The above command removes the `User-Agent` header.

You can also directly specify the header via the `-H` parameter to change `User-Agent`.

> ```bash
> $ curl -H 'User-Agent: php/1.0' https://google.com
> ```

## **-b**

The `-b` parameter is used to send cookies to the server.

> ```bash
> $ curl -b 'foo=bar' https://google.com
> ```

The above command generates a header `Cookie: foo=bar`, sending a cookie named `foo` with value `bar` to the server.

> ```bash
> $ curl -b 'foo1=bar;foo2=bar2' https://google.com
> ```

The above command sends two cookies.

> ```bash
> $ curl -b cookies.txt https://www.google.com
> ```

The above command reads the local file `cookies.txt`, which contains cookies set by the server (see the `-c` parameter), and sends them to the server.

## **-c**

The `-c` parameter writes cookies set by the server to a file.

> ```bash
> $ curl -c cookies.txt https://www.google.com
> ```

The above command writes the cookies set in the server's HTTP response to the text file `cookies.txt`.

## **-d**

The `-d` parameter is used to send the data body of a POST request.

> ```bash
> $ curl -d'login=emma＆password=123'-X POST https://google.com/login
> # 或者
> $ curl -d 'login=emma' -d 'password=123' -X POST  https://google.com/login
> ```

After using the `-d` parameter, the HTTP request will automatically add the header `Content-Type : application/x-www-form-urlencoded`. It will also automatically convert the request to the POST method, so `-X POST` can be omitted.

The `-d` parameter can read data from a local text file and send it to the server.

> ```bash
> $ curl -d '@data.txt' https://google.com/login
> ```

The above command reads the contents of the `data.txt` file and sends it to the server as the data body.

## **--data-urlencode**

The `--data-urlencode` parameter is equivalent to `-d`, sending the data body of a POST request, except that it automatically URL-encodes the sent data.

> ```bash
> $ curl --data-urlencode 'comment=hello world' https://google.com/login
> ```

In the above code, the sent data `hello world` contains a space and needs URL encoding.

## **-e**

The `-e` parameter is used to set the HTTP header `Referer`, indicating the source of the request.

> ```bash
> curl -e 'https://google.com?q=example' https://www.example.com
> ```

The above command sets the `Referer` header to `https://google.com?q=example`.

The `-H` parameter can achieve the same effect by directly adding the header `Referer`.

> ```bash
> curl -H 'Referer: https://google.com?q=example' https://www.example.com
> ```

## **-F**

The `-F` parameter is used to upload binary files to the server.

> ```bash
> $ curl -F 'file=@photo.png' https://google.com/profile
> ```

The above command adds the header `Content-Type: multipart/form-data` to the HTTP request, and then uploads the file `photo.png` as the `file` field.

The `-F` parameter can specify the MIME type.

> ```bash
> $ curl -F 'file=@photo.png;type=image/png' https://google.com/profile
> ```

The above command specifies the MIME type as `image/png`; otherwise curl will set the MIME type to `application/octet-stream`.

The `-F` parameter can also specify the filename.

> ```bash
> $ curl -F 'file=@photo.png;filename=me.png' https://google.com/profile
> ```

In the above command, the original filename is `photo.png`, but the filename received by the server is `me.png`.

## **-G**

The `-G` parameter is used to construct the URL query string.

> ```bash
> $ curl -G -d 'q=kitties' -d 'count=20' https://google.com/search
> ```

The above command sends a GET request, and the actual requested URL is `https://google.com/search?q=kitties&count=20`. If `--G` is omitted, a POST request will be sent.

If the data needs URL encoding, you can combine it with the `--data--urlencode` parameter.

> ```bash
> $ curl -G --data-urlencode 'comment=hello world' https://www.example.com
> ```

## **-H**

The `-H` parameter adds an HTTP request header.

> ```bash
> $ curl -H 'Accept-Language: en-US' https://google.com
> ```

The above command adds the HTTP header `Accept-Language: en-US`.

> ```bash
> $ curl -H 'Accept-Language: en-US' -H 'Secret-Message: xyzzy' https://google.com
> ```

The above command adds two HTTP headers.

> ```bash
> $ curl -d '{"login": "emma", "pass": "123"}' -H 'Content-Type: application/json' https://google.com/login
> ```

The above command adds the HTTP request header `Content-Type: application/json`, and then uses the `-d` parameter to send JSON data.

## **-i**

The `-i` parameter prints out the HTTP headers of the server response.

> ```bash
> $ curl -i https://www.example.com
> ```

After receiving the server response, the above command first outputs the headers of the server response, then leaves a blank line, and then outputs the source code of the webpage.

## **-I**

The `-I` parameter sends a HEAD request to the server, and then prints out the HTTP headers returned by the server.

> ```bash
> $ curl -I https://www.example.com
> ```

The above command outputs the server's response to the HEAD request.

The `--head` parameter is equivalent to `-I`.

> ```bash
> $ curl --head https://www.example.com
> ```

## **-k**

The `-k` parameter specifies to skip SSL verification.

> ```bash
> $ curl -k https://www.example.com
> ```

The above command will not check whether the server's SSL certificate is correct.

## **-L**

The `-L` parameter makes HTTP requests follow server redirects. curl does not follow redirects by default.

> ```bash
> $ curl -L -d 'tweet=hi' https://api.twitter.com/tweet
> ```

## **--limit-rate**

`--limit-rate` is used to limit the bandwidth of HTTP requests and responses, simulating a slow network environment.

> ```bash
> $ curl --limit-rate 200k https://google.com
> ```

The above command limits the bandwidth to 200K bytes per second.

## **-o**

The `-o` parameter saves the server response as a file, equivalent to the `wget` command.

> ```bash
> $ curl -o example.html https://www.example.com
> ```

The above command saves `www.example.com` as `example.html`.

## **-O**

The `-O` parameter saves the server response as a file and uses the last part of the URL as the filename.

> ```bash
> $ curl -O https://www.example.com/foo/bar.html
> ```

The above command saves the server response as a file, with the filename `bar.html`.

## **-s**

The `-s` parameter will not output error and progress information.

> ```bash
> $ curl -s https://www.example.com
> ```

Once an error occurs, the above command will not display error information. If no error occurs, the running result will be displayed normally.

If you want curl to produce no output, you can use the following command.

> ```bash
> $ curl -s -o /dev/null https://google.com
> ```

## **-S**

The `-S` parameter specifies to output only error messages, usually used together with `-s`.

> ```bash
> $ curl -s -o /dev/null https://google.com
> ```

The above command has no output unless an error occurs.

## **-u**

The `-u` parameter is used to set the username and password for server authentication.

> ```bash
> $ curl -u 'bob:12345' https://google.com/login
> ```

The above command sets the username to `bob` and the password to `12345`, then converts them into the HTTP header `Authorization: Basic Ym9iOjEyMzQ1`.

curl can recognize the username and password in the URL.

> ```bash
> $ curl https://bob:12345@google.com/login
> ```

The above command can recognize the username and password in the URL and convert them into the HTTP header from the previous example.

> ```bash
> $ curl -u 'bob' https://google.com/login
> ```

The above command only sets the username; after execution, curl will prompt the user to enter the password.

## **-v**

The `-v` parameter outputs the entire communication process, used for debugging.

> ```bash
> $ curl -v https://www.example.com
> ```

The `--trace` parameter can also be used for debugging, and will also output the raw binary data.

> ```bash
> $ curl --trace - https://www.example.com
> ```

## **-x**

The `-x` parameter specifies the proxy for HTTP requests.

> ```bash
> $ curl -x socks5://james:cats@myproxy.com:8080 https://www.example.com
> ```

The above command specifies that the HTTP request is sent through the socks5 proxy at `myproxy.com:8080`.

If no proxy protocol is specified, the default is HTTP.

> ```bash
> $ curl -x james:cats@myproxy.com:8080 https://www.example.com
> ```

In the above command, the proxy for the request uses the HTTP protocol.

## **-X**

The `-X` parameter specifies the method of the HTTP request.

> ```bash
> $ curl -X POST https://www.example.com
> ```

The above command sends a POST request to `https://www.example.com`.
