## 再起動後にネットワークがない

特定のCPUアーキテクチャ（一部のMediaTek、Realtekソリューション、または古いx86 NICなど）では、OpenWrtのオープンソースドライバが不完全である。システムのソフト再起動時に、NICチップへリセット（Reset）命令を正常に送信できなかった

```bash
# 强制重启一次网络服务
/etc/init.d/network restart
/etc/init.d/firewall reload
```

## インターフェース分流

### MWAN3

すべてのハードウェアアクセラレーション、ファイアウォール&wedをオフにする

> ipv6はNAT越えの理由により、nat6でない場合は負荷分散しない方がよい

1. **インターフェースを登録：** 分流したいすべてのインターフェースを登録する

2. **メンバーを追加：** mwanのインターフェースを作成し、ホップ（優先度）、重み（トラフィック比率）を設定する
3. **ポリシーを設定：** 必要なメンバー（一緒に分流する必要があるもの）を1つのポリシーに束ねる。グローバルIP割り当ての場合はここで個別ポリシーを設定する必要がある
4. **ルールを設定：** 宛先アドレス`0.0.0.0/0`、すなわちすべての外部ネットワークIPを分流する。グローバルIP割り当ての場合はここで送信元アドレスフィルタを設定する必要がある。

ルールが最終的な効果を決定する。テストが必要な場合は、単一インターフェースにバインドしたポリシーを作成し、ルールを作成して最上部に移動する



> インターフェースのテスト：mwan3 use {interface} curl api.ipify.org

###  手動設定

#### 外部アクセスを保持

ルーティングテーブルを作成する（登録名をファイルに書き込む必要がある場合）

`echo "101 pppoe" >> /etc/iproute2/rt_tables`

`/etc/nftables.d/99-pppoe-mark.nft`

```bash
table inet fw4 {
    chain mangle_prerouting_custom {
        type filter hook prerouting priority mangle; policy accept;
        
        # 将来自 pppoe-wan 的所有新连接，在连接状态(connmark)上打上 0x300 标记
        iifname "pppoe-wan" ct state new ct mark set 0x300
        
        # 状态继承：将连接标记(connmark)强行赋予当前流经的数据包(fwmark)
        ct mark != 0x0 meta mark set ct mark
    }

    # 挂载点2：本机回程拦截 (OUTPUT)
    chain mangle_output_custom {
        type route hook output priority mangle; policy accept;
        
        # 本机发起的响应流量，同样继承该连接的标记
        ct mark != 0x0 meta mark set ct mark
    }
}
```

`/etc/hotplug.d/iface/99-pppoe-policy-route`

```bash
#!/bin/sh

# 1. 过滤非 pppoe-wan 上线事件
[ "$ACTION" = "ifup" ] || exit 0
[ "$INTERFACE" = "pppoe-wan" ] || exit 0

# 2. 清理旧的 fwmark 策略（彻底清空，防止堆积）
while ip rule del fwmark 0x300 table pppoe 2>/dev/null; do :; done
ip route flush table pppoe 2>/dev/null

# 3. 注入 fwmark 策略路由
# 逻辑：所有携带 0x300 标记的包，强制查表 pppoe，从 pppoe-wan 出站
ip rule add fwmark 0x300 table pppoe
ip route add default dev pppoe-wan table pppoe
```

## ipv6 マルチWAN設定

### v4

`* * * * * /root/failover.sh`

```bash
#!/bin/sh

# 1. 填入你的乐天 DS-Lite 接口名称
IFACE_RAK="dslite"

# 2. 测试连通性的目标 IP（Google DNS）
TEST_IP="8.8.8.8"

# 强制使用乐天接口发送 3 个探测包
ping -c 3 -W 2 -I $IFACE_RAK $TEST_IP >/dev/null 2>&1

if [ $? -eq 0 ]; then
    # 【乐天存活】：恢复/保持乐天的默认路由（跃点 10）
    # 如果路由已存在，命令会静默失败，对系统零消耗
    ip route add default dev $IFACE_RAK metric 10 2>/dev/null
else
    # 【乐天断网】：拔掉乐天的默认路由
    # 此时系统的底层路由表只剩下跃点为 20 的公寓网，流量瞬间切换
    ip route del default dev $IFACE_RAK metric 10 2>/dev/null
fi
```

### v6

`* * * * * /root/failover_v6.sh`

```bash
#!/bin/sh

# ================= 配置区 =================
IFACE_RAK="wan6"                 # 乐天光 IPv6 接口名（或者是 pppoe-wan / dslite，根据实际获取到240开头的接口填）
TEST_IP="2001:4860:4860::8888"   # Google 公共 DNS IPv6 节点
# ==========================================

# 1. 动态抓取乐天光当前的 IPv6 网关
GW=$(ip -6 route show default dev "$IFACE_RAK" | awk '/via/ {print $3; exit}')

# 如果连网关都拿不到，说明物理层彻底断开，直接切除路由，回落到公寓网
if [ -z "$GW" ]; then
    ip -6 route del default dev "$IFACE_RAK" 2>/dev/null
    exit 0
fi

# 2. 核心锚点：建立一条只属于探针的静态主机路由，防止删除默认路由后无法探测外网
ip -6 route add "$TEST_IP" via "$GW" dev "$IFACE_RAK" metric 1 2>/dev/null

# 3. 强制通过固定宿主路径向外发射 3 个探测包
ping6 -c 3 -W 2 "$TEST_IP" >/dev/null 2>&1

if [ $? -eq 0 ]; then
    # 【乐天光 IPv6 正常】：将其默认路由以高优先级（metric 10）强行注入（如果已存在则静默跳过）
    ip -6 route add default via "$GW" dev "$IFACE_RAK" metric 10 2>/dev/null
else
    # 【乐天光 IPv6 断流】：精准切除乐天光的默认路由
    # 此时主路由表只剩下公寓网的默认路由（metric 20），流量瞬间无缝转移
    ip -6 route del default via "$GW" dev "$IFACE_RAK" 2>/dev/null
fi
```





## 外部アクセス

ルーター自体のサービスは通信ルール内でインバウンドを設定する

サブネット内のサービスはポート転送で転送を設定する



サブネットのグローバルIPv6を外部公開したい場合は通信ルールを設定する

### グローバルIPv6をサブネットに割り当てる（/64 PDのみの場合に必要）

> `/64` は最小の物理ブロードキャストドメイン（subnet）であり、つまり/64はネットワークノードが直接通信する（ndpに応答、同一リンクon-link）と見なされるため、ndpプロキシが必要
>
> `/60 /56` などより大きなrangeはデフォルトでルーティング可能であり、転送できる
>
> 転送状態はnext-hop、終端状態はon-link

wan6でdhcpサーバーを有効にする：指定した主インターフェースを有効にし、ra dhcp ndpをすべてリレーに変更する

lan v6設定：ra dhcp ndpをすべてリレーに変更する

> グローバルIPv6を1つだけ使用する場合、ファイアウォールwan内の詳細設定でipv6マスカレード（nat66）を有効にする
