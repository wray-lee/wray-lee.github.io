## Local site setup

### Create website directory

```shell
sudo mkdir -p /var/www/mywebsite
sudo chown -R $USER:$USER /var/www/mywebsite
```

### Edit website content

`vim /var/www/mywebsite/index.html`

```html
<!DOCTYPE html>
<html>
<head>
    <title>My Website</title>
</head>
<body>
    <h1>Welcome to My Website</h1>
    <p>This is a sample webpage.</p>
</body>
</html>
```

### nginx configuration

```shell
sudo nano /etc/nginx/sites-available/mywebsite
```

````nginx
server {
    listen 80;
    server_name localhost;

    root /var/www/mywebsite;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}

上述配置指示 Nginx 监听端口 80，并将请求根路径 `/` 映射到 `/var/www/mywebsite` 目录下的 `index.html` 文件。
````

### Enable website configuration

```shell
sudo ln -s /etc/nginx/sites-available/mywebsite /etc/nginx/sites-enabled/
```

### Restart service

```shell
sudo nginx -t
sudo systemctl restart nginx
```

## Location

| **User request path** | **location configuration** | **proxy_pass configuration**     | **Actual path received by the backend** | **Description**                                                     |
| ---------------- | ----------------- | ----------------------- | ---------------------- | ------------------------------------------------------------ |
| `/api/test`      | `location /api/`  | `http://host` (no slash)  | `/api/test`            | **Pass-through**: the path is not modified at all                                   |
| `/api/test`      | `location /api/`  | `http://host/` (with slash) | `/test`                | **Replacement**: `/api/` is removed                                     |
| `/api/test`      | `location /api/`  | `http://host/new/`      | `/newtest`             | **Concatenation**: `/api/` is removed, and the remaining part is directly appended after `/new` (note that no slash after `/new` may cause them to be joined together) |
| `/api/test`      | `location /api/`  | `http://host/new/`      | `/new/test`            | **Directory concatenation**: the most reliable subdirectory proxy method                         |

**location {content}**

{content} is the anchor that determines the matched content, matching all content from {content} onward.

Based on whether the URI of proxy__pass is complete, determine whether the match is fully concatenated. For a complete URI, concatenate the subsequent content after **removing {content} and the preceding content**.

For an incomplete URI, concatenate all matched content.

> Process location /{content}/; when a user accesses https://host/{content}/123，则透传123到proxy_pass http://host/new, find the first /, and the result is http://host/new123
>
> That is, location is used for trimming, and proxy_pass is used for pass-through.



```bash
location /api

location /api/

location = /api
```


`/api` can match `/api1` `/api2` `/api/sth` `/api2/sth`

`/api/` can only match `/api` `/api/sth`

`= /api` only matches `/api`

### proxy_pass

```nginx
location /api {
    proxy_pass http://localhost:3000/
}

location /api/ {
    proxy_pass http://localhost:3000/
}
```

Access http://url/api/content时

The former will access http://localhost:3000//content

The latter will access http://localhost:3000/content



```nginx
location /api/ {
    proxy_pass http://localhost:3000
}

location /api/ {
    proxy_pass http://localhost:3000/
}
```

The former is an incomplete URI, so it accesses http://url/api/content时，实际访问http://localhost:3000/api/content

The latter is a complete URI, so it accesses http://url/api/content时，实际访问http://localhost:3000/content

**General**

```nginx
stream {
    # 定义上游 DoT 服务器 (这里以 Cloudflare 为例)
    upstream dot_upstream {
        server 1.1.1.1:853;
        server 1.0.0.1:853;
    }

    server {
        listen 853 ssl; # DoT 标准端口
        
        # 你的证书路径
        ssl_certificate /etc/nginx/cert/yourdomain.crt;
        ssl_certificate_key /etc/nginx/cert/yourdomain.key;

        # 握手优化
        ssl_session_cache shared:SSL:10m;
        ssl_session_timeout 10m;
        
        # 反代设置
        proxy_pass dot_upstream;
        proxy_ssl on; # 如果上游也是 DoT，需要开启 SSL
        
        # 关键：开启 SNI，否则上游可能拒绝连接 (针对 Cloudflare/Google 等)
        proxy_ssl_server_name on;
        proxy_ssl_name one.one.one.one; 
    }
}

# --- DoH 配置 (Layer 7, Port 443) ---
http {
    # ... 其他标准 http 配置 ...

    server {
        listen 443 ssl http2; # 必须开启 http2，DoH 强依赖
        server_name dns.yourdomain.com;

        ssl_certificate /etc/nginx/cert/yourdomain.crt;
        ssl_certificate_key /etc/nginx/cert/yourdomain.key;

        location /dns-query {
            # 反代到 Cloudflare DoH
            proxy_pass https://1.1.1.1/dns-query;
            
            # 传递必要的 Header
            proxy_set_header Host cloudflare-dns.com;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            
            # 保持连接
            proxy_http_version 1.1;
            proxy_set_header Connection "";
            
            # 同样需要处理上游 SNI
            proxy_ssl_server_name on;
            proxy_ssl_name cloudflare-dns.com;
        }
    }
}
```

```nginx
server {
    listen 443 ssl;
    server_name docker.yourdomain.com;

    # SSL 证书配置 (请替换为你自己的路径)

        proxy_ssl_protocols TLSv1.2 TLSv1.3;
        
        # 处理 Docker 的特殊 Header
        proxy_set_header Authorization $http_authorization;
        proxy_pass_header  Authorization;
    }
```
