.reg files have the following syntax:

RegistryEditorVersion
Blank line
[RegistryPath1]
"DataItemName1"="DataType1:DataValue1"
DataItemName2"="DataType2:DataValue2"
Blank line
[RegistryPath2]
"DataItemName3"="DataType3:DataValue3"

Where:

RegistryEditorVersion is "Windows Registry Editor Version 5.00" (for Windows 2000, Windows XP, and Windows Server 2003) or "REGEDIT4" (for Windows 98 and Windows NT 4.0). The "REGEDIT4" header also applies to computers based on Windows 2000, Windows XP, and Windows Server 2003.

Blank line is just an empty line. It marks the beginning of a new registry path. Each key or subkey is a new registry path. If there are multiple keys in a .reg file, blank lines can help you inspect the contents and troubleshoot problems in them.

RegistryPathx is the path of the subkey that holds the first value to import. Enclose the path in square brackets, and separate each level of the hierarchy with a backslash. For example:
[HKEY_LOCAL_ MACHINE\SOFTWARE\Policies\Microsoft\Windows\System]
A .reg file can contain multiple registry paths. If the underlying hierarchy in the path statement does not exist in the registry, a new subkey will be created. The contents of the registry file are sent to the registry in the order in which they are entered. Therefore, if you want to create a new subkey that contains another subkey, you must enter the lines in the correct order.

DataItemNamex is the name of the data item to import. If the data item in the file does not exist in the registry, the .reg file will add the data item and its value. If the data item exists, the value in the .reg file will overwrite the existing value. The data item name is enclosed in quotation marks. The data item name is immediately followed by an equals sign (=).

DataTypex is the data type of the registry value, immediately after the equals sign. For all data types other than REG_SZ (string value), the data type is immediately followed by a colon. If the data type is REG_SZ, the data type value or colon is not included. In this case, Regedit.exe assumes the data type is REG_SZ. The following table lists typical registry data types:

| Data type | Data type in .reg |
|---|---|
| REG_BINARY | hexadecimal |
| REG_DWORD | dword |
| REG_EXPAND_SZ | hexadecimal(2) |
| REG_MULTI_SZ | hexadecimal(7) |

| Name | Data type | Description |
|---|---|---|
| Binary value | REG_BINARY | Raw binary data. Most hardware component information is stored as binary data and is displayed in hexadecimal format in Registry Editor. |
| DWORD value | REG_DWORD | Data represented by a 4-byte-long (32-bit integer) number. Many parameters of device drivers and services are of this type, displayed in binary, hexadecimal, or decimal format in Registry Editor. The related values are DWORD_LITTLE_ENDIAN (least significant byte at the lowest address) and REG_DWORD_BIG_ENDIAN (least significant byte at the highest address). |
| Expandable string value | REG_EXPAND_SZ | A variable-length data string. This data type includes variables that are resolved when a program or service uses the data. |
| Multi-string value | REG_MULTI_SZ | Multiple strings. Values that contain a list or multiple values that users can read are usually of this type. Entries are separated by spaces, commas, or other marks. |
| String value | REG_SZ | A fixed-length text string. |
| Binary value | REG_RESOURCE_LIST | A series of nested arrays that stores a resource list used by a hardware device driver or one of the physical devices it controls. This data is detected by the system and written to the \ResourceMap tree, and is displayed as a binary value in hexadecimal format in Registry Editor. |
| Binary value | REG_RESOURCE_REQUIREMENTS_LIST | A series of nested arrays that stores a list of possible hardware resources that a device driver or one of the physical devices it controls can use; the system writes a subset of this list to the \ResourceMap tree. This data is detected by the system and displayed as a binary value in hexadecimal format in Registry Editor. |
| Binary value | REG_FULL_RESOURCE_DESCRIPTOR | A series of nested arrays that stores a resource list used by a physical hardware device. This data is detected by the system and written to the \HardwareDescription tree, and is displayed as a binary value in hexadecimal format in Registry Editor |
| None | REG_NONE | Data with no specific type. This data is written to the registry by the system or an application, and is displayed as a binary value in hexadecimal format in Registry Editor |
| Link | REG_LINK | A Unicode string that names a symbolic link. |
| QWORD value | REG_QWORD | Data represented by a 64-bit integer number. This data is displayed as a binary value in Registry Editor and was first used in Windows 2000. |

DataValuex immediately follows the colon (or, for REG_SZ, the equals sign), and must be in the correct format (for example, a string or hexadecimal). Use hexadecimal format for binary data items.
Note: You can enter multiple data item lines for the same registry path.
Add a registry subkey or add and change registry values
To add a registry subkey or add/change registry values, make the corresponding changes in the registry, and then export the corresponding subkey or subkeys. Exported registry subkeys are automatically saved as .reg files. To make changes to the registry and export the changes to a .reg file, follow these steps:
1. Click Start, click Run, type regedit in the Open box, and then click OK.
2. Locate and click the subkey that contains the registry key you want to change.
3. Click File, and then click Export.

This step backs up the subkey before you make changes. If the changes cause problems, you can later import this file back into the registry.

4. In the File name box, type the file name to use to save the .reg file containing the original registry key, and then click Save.

Note: Use a name that indicates its contents, for example, one that references the name of the subkey.
5. In the right pane, add or modify the registry keys you want.
6. Repeat steps 3 and 4 to export the subkey again, but use a different file name for the .reg file. You can use this .reg file to make changes to the registry on other computers.
7. Test the changes on the local computer. If they cause problems, double-click the file that contains the backup of the original registry data to return the registry to its original state. If the changes work as expected, you can use the method in the "Distributing registry changes" section of this article to distribute the .reg file you created in step 6 to other computers.

Delete registry keys and values
To delete a registry key using a .reg file, place a hyphen (-) before the registry path in the .reg file. For example, to delete the Test subkey from the following registry key:
HKEY_LOCAL_MACHINE\Software
place a hyphen before the following registry key in the .reg file:
HKEY_LOCAL_MACHINE\Software\Test
The following example is a .reg file that can perform this task.
[-HKEY_LOCAL_MACHINE\Software\Test]
To delete a registry value using a .reg file, place a hyphen (-) after the equals sign following the data item name in the .reg file. For example, to delete the TestValue registry value from the following registry key:
HKEY_LOCAL_MACHINE\Software\Test
place a hyphen after "TestValue"= in the .reg file. The following example is a .reg file that can perform this task.
HKEY_LOCAL_MACHINE\Software\Test
"TestValue"=-
To create a .reg file, use Regedit.exe to export the registry key you want to delete, then use Notepad to edit the .reg file and insert the hyphen.

Rename registry keys and values
To rename a key or value, delete the key or value, and then create a new key or value with the new name.

Note: If you need to use a file path in the registry, the slash \ in the file path needs to use a double slash \\

If you use system variables, you need to replace the slashes in the system variables with double slashes

Windows Registry Editor Version 5.00

[HKEY_LOCAL_MACHINE\SOFTWARE\Classes\*\shell]

[HKEY_LOCAL_MACHINE\SOFTWARE\Classes\*\shell\EditPlus 2]

@="EditPlus 2"

[HKEY_CLASSES_ROOT\*\shell\EditPlus 2\command]
@="C:\\Program Files (x86)\\EditPlus 2\\EditPlus.exe %1"

In this example, if you replace the path with a variable
@="%PROGRAMFILES(x86)%\\EditPlus 2\\EditPlus.exe %1" the actual result is @="C:\Program Files (x86)\\EditPlus 2\\EditPlus.exe %1"
This is wrong, and the system will not be able to find the file
You should use a DOS batch file to generate the reg file; here you need to use a text replacement command to replace single slashes with double slashes, as follows

@echo off
echo "默认使用86文件夹，兼容32位系统执行"
set var=%PROGRAMFILES%
if "%PROCESSOR_ARCHITECTURE%"=="AMD64" set "var=%PROGRAMFILES(x86)%"
set "var=%var:\=\\%"
echo Windows Registry Editor Version 5.00 >menu.reg
echo. >>menu.reg
echo [HKEY_LOCAL_MACHINE\SOFTWARE\Classes\*\shell] >>menu.reg
echo. >>menu.reg
echo [HKEY_LOCAL_MACHINE\SOFTWARE\Classes\*\shell\EditPlus 2] >>menu.reg
echo. >>menu.reg
echo @="EditPlus 2" >>menu.reg
echo. >>menu.reg
echo [HKEY_CLASSES_ROOT\*\shell\EditPlus 2\command]>>menu.reg
echo. >>menu.reg
echo @="%var%\\EditPlus 2\\EditPlus.exe %%1">>menu.reg

regedit /s menu.reg
