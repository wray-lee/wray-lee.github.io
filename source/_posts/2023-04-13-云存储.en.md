## Linux

### Automatically Mount WebDAV at Boot

After a normal mount, upon reboot you will find that the disk mounted via WebDAV is gone, which means every time you restart the Linux system, you need to mount it again. At this point, you need to change a few settings to enable automatic mounting at boot.

**Step 1: Edit the davfs2.conf configuration file and change use_locks from 1 to 0**

```shell
vim /etc/davfs2/davfs2.conf 
```

![image-20211012153936525](https://cdn.lincloud.pro/blog/images/202110121401.jpg)

**Step 2: Modify the secrets file and add account information**

```shell
vim /etc/davfs2/secrets
```

Add account information at the bottom, such as

```shell
https://pan.cloud.com/dav user password
```

**Step 3: Add boot mount command**

```shell
vim /etc/rc.local
```

##### arch

Before writing the startup script, you need to write a service:

1. First switch the user to root, then enter the /etc/systemd/system directory

2. Create a .service file, name it as you like; in this example it is **AutoExec.service**

3. Set permissions:

   ```
   chmod 644 AutoExec.service
   ```

4. Add the following content to AutoExec.service

```
[Unit]
Description=AutoExec
[Service]
ExecStart=/root/AutoExec.sh
[Install]
WantedBy=multi-user.target
```

1. The above ExecStart=/root/AutoExec.sh indicates that /root/AutoExec.sh will be executed at boot, so just write the commands in it. Of course, the file can be specified arbitrarily; changing it to something like /etc/rc.local is also fine.
2. Link to multi-user.target.wants:
   ln -s AutoExec.service multi-user.target.wants/
   (Note: This step is to make this service start automatically at boot; the effect is equivalent to systemctl enable AutoExec.service.)
3. Create /root/AutoExec.sh and write the commands you want to start at boot into it,

and set permissions:

```
chmod 744 /root/AutoExec.sh
```



(The file path and file name can be changed freely, but you must add executable permissions.)

That completes the setup. With **systemctl start AutoExec.service**, you can see the commands in **AutoExec.sh** executed. Of course, they will also be executed automatically at every boot.

#### /etc/fstab

### Using fstab

To define how the webdav resource should be mounted into the filesystem, [append](https://wiki.archlinux.org/title/Append) a [fstab](https://wiki.archlinux.org/title/Fstab) entry under the following format:

```
/etc/fstab
https://webdav.example/path /mnt/webdav davfs rw,user,uid=username,noauto 0 0
```

where *username* is the owner of the mounted file system. It may be a numeric ID or a user name and only *root* can mount a uid different from the mounting user. `_netdev` mount option could be used to automount network drives.

---

Add the mount command at the end, just like mounting a USB drive

```shell
mount -t davfs https://pan.cloud.com/dav /cloud
```

Reboot and it will mount automatically.

**Final step: Test**

Enter ` df -h` to check whether it succeeded

### rclone Capacity Size Display

If it is only for displaying the total size, you can manually set the total size via `--vfs-disk-space-total-size` when rClone mounts, and use `--vfs-used-is-size` to make rClone actively calculate the used space. However, this is only for convenient display. If the WebDAV server does not actively implement the attribute required by rClone about, then when mounting you cannot know information such as used space or total file count. If you want to work with rClone's Union backend, there is still no way to select a remote based on remaining space or used space.

### Write Scripts

After adding environment variables, write a vbs script to facilitate process creation

```vbscript
' start_alist.vbs
Dim ws
Set ws = Wscript.CreateObject("Wscript.Shell")
ws.run "alist server",vbhide
```



```vbscript
' stop_alist.vbs
Dim ws
Set ws = Wscript.CreateObject("Wscript.Shell")
ws.run "taskkill /f /im alist.exe",0
Wscript.quit
```



``` vbscript
' mount.vbs
dim alist
set alist = Wscript.CreateObject("Wscript.Shell")
alist.run "rclone mount alist:/  G: --cache-dir D:\OneDriveTemp --vfs-cache-mode writes",vhide
```



```vbscript
' unmount.vbs
dim alist
set alist = Wscript.CreateObject("Wscript.Shell")
alist.run "taskkill /f /im rclone.exe",vhide
```
