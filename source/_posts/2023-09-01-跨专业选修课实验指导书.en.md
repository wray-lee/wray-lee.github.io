# Experiment 1 Protocols and Data of Computer Networks

Experiment series: Interdisciplinary elective course experiment. Experiment target: Undergraduate

Related courses and majors: Computer Networks, Information Security. Experiment hours (credits): **4** class hours

Experiment category: In-class computer lab

Experiment developer teacher: Computer Networks

**【Experiment Objectives】**

Understand and master the basic concepts of protocols and network packets/messages in computer networks, master the interaction process and role of network protocols, as well as the format and meaning of network data packets.

**【Experiment Content】**

By using WireShark software, capture network data packets of protocols such as TCP and FTP transmitted in the network, so as to understand the data structures of various protocols in the TCP/IP protocol stack, the process of session connection establishment and termination, and the changing rules of TCP sequence numbers and acknowledgment sequence numbers.

**【Experiment Environment】**

1.  Students work in pairs, each person has one PC, with Windows 7 or Windows XP operating system installed.

2.  A local area network environment networked with switches or hubs.

**【Experiment Equipment】**

2 PCs per group, listening software WireShark and FTP server software ServU.

**【Experiment Principles】**

(1) Computer network layered model:

The TCP/IP protocol suite is the foundation of the Internet and also the most popular networking form today. TCP/IP is a collective term for a group of protocols, including many other protocols, forming the TCP/IP protocol suite. Among them, the more important ones include SLIP protocol, PPP protocol, IP protocol, ICMP protocol, ARP protocol, TCP protocol, UDP protocol, FTP protocol, DNS protocol, SMTP protocol, etc. TCP/IP protocol does not completely conform to the OSI seven-layer reference model. The traditional Open Systems Interconnection reference model is a 7-layer abstract reference model for communication protocols, in which each layer performs a specific task. The purpose of this model is to enable various hardware to communicate with each other at the same layer. The TCP/IP communication protocol adopts a 4-layer hierarchical structure, and each layer calls the network provided by its next layer to fulfill its own requirements. Conceptually, it can be mapped to four layers: the network interface layer, which is responsible for transmitting frames on the line and receiving frames from the line; the Internet layer, which includes the IP protocol. The IP protocol generates Internet datagrams and performs necessary routing algorithms. The IP protocol can actually be divided into four parts: ARP, ICMP, IGMP, and IP; above that is the transport layer, which is responsible for managing sessions between computers. This layer includes two protocols, TCP and UDP. Different protocols can be used for communication according to different application requirements; the last layer is the application layer, which includes the familiar FTP, DNS, TELNET, etc.

(2) TCP protocol

TCP protocol is the Transmission Control Protocol. It provides a reliable [data stream](https://baike.baidu.com/item/%E6%95%B0%E6%8D%AE%E6%B5%81) service. When transmitting data subject to error interference, or when [network failures](https://baike.baidu.com/item/%E7%BD%91%E7%BB%9C%E6%95%85%E9%9A%9C/1391028) occur, or when the network load is too heavy and the basic internet transmission system cannot work normally, other protocols are needed to ensure communication reliability. [TCP](https://baike.baidu.com/item/TCP/33012) is such a protocol. TCP uses the "positive acknowledgment with retransmission" technique to achieve transmission reliability, and uses the "[sliding window](https://baike.baidu.com/item/%E6%BB%91%E5%8A%A8%E7%AA%97%E5%8F%A3)" [flow control](https://baike.baidu.com/item/%E6%B5%81%E9%87%8F%E6%8E%A7%E5%88%B6) mechanism to improve network throughput. TCP communication establishment implements a concept of "[virtual circuit](https://baike.baidu.com/item/%E8%99%9A%E7%94%B5%E8%B7%AF/1609903)". Before the two parties communicate, they first establish a link, and then both parties can send data streams on it. This data exchange method can improve efficiency, but establishing the connection in advance and tearing it down afterward requires overhead.

TCP provides a connection-oriented, reliable byte stream service. Connection-oriented means that two applications using TCP (usually a client and a server) must first establish a TCP connection before exchanging data with each other, that is, the "three-way handshake". This handshake process is very similar to making a phone call: first dial and ring, wait for the other party to pick up and say "hello", and then explain who you are.

(3) FTP (File Transfer Protocol)

FTP is a standard protocol and is the simplest method for exchanging files between computers and networks. Just like the HTTP protocol for transmitting web pages and the SMTP protocol for email, FTP is also an application protocol standard for the TCP/IP protocol. FTP is usually used to upload files by their owners to a server for others to use, and downloading files from a server is also a very common usage. As a user, you can use a very simple DOS command interface to use FTP file transfer services, or you can use a graphical interface FTP client provided by a third party to update (delete, rename, move, and copy) files on the server. FTP servers generally support anonymous login, allowing users to log in with ANONYMOUS as the username, and usually any password can be used or you can just press Enter.

**【Experiment Principles】**

(1) Twisted pair and unshielded twisted pair

Twisted pair is formed by twisting a pair of mutually [insulated](https://baike.baidu.com/item/%E7%BB%9D%E7%BC%98/13466698) [metal](https://baike.baidu.com/item/%E9%87%91%E5%B1%9E) wires. In this way, it can not only resist part of electromagnetic interference from the outside, but also reduce mutual interference between multiple pairs of twisted wires. Twist two [insulated](https://baike.baidu.com/item/%E7%BB%9D%E7%BC%98) wires together. Interference signals acting on these two intertwined wires are consistent (this interference signal is called a common-mode signal). In the differential circuit receiving the signal, the common-mode signal can be eliminated, thereby extracting the useful signal (differential-mode signal). According to whether there is a shielding layer, twisted pair is divided into [shielded twisted pair](https://baike.baidu.com/item/%E5%B1%8F%E8%94%BD%E5%8F%8C%E7%BB%9E%E7%BA%BF) (Shielded Twisted Pair—STP) and [unshielded twisted pair](https://baike.baidu.com/item/%E9%9D%9E%E5%B1%8F%E8%94%BD%E5%8F%8C%E7%BB%9E%E7%BA%BF) (Unshielded Twisted Pair—UTP).

Unshielded twisted pair ([UTP](https://baike.baidu.com/item/UTP)) is a data [transmission line](https://baike.baidu.com/item/%E4%BC%A0%E8%BE%93%E7%BA%BF), composed of four pairs of transmission lines of different colors, and is widely used in Ethernet and [telephone lines](https://baike.baidu.com/item/%E7%94%B5%E8%AF%9D%E7%BA%BF). Unshielded twisted pair cables have the following advantages: 1. No shielding jacket, small diameter, saves occupied space, and low cost; 2. Light weight, easy to bend, easy to install; 3. Minimizes or eliminates crosstalk; 4. Flame retardant; 5. Independent and flexible, suitable for [structured cabling](https://baike.baidu.com/item/%E7%BB%93%E6%9E%84%E5%8C%96%E7%BB%BC%E5%90%88%E5%B8%83%E7%BA%BF). Therefore, in structured cabling systems, unshielded twisted pair is widely used. Common twisted pairs include Category 3 cable, [Category 5 cable](https://baike.baidu.com/item/%E4%BA%94%E7%B1%BB%E7%BA%BF) and [Category 5e cable](https://baike.baidu.com/item/%E8%B6%85%E4%BA%94%E7%B1%BB%E7%BA%BF), as well as [Category 6 cable](https://baike.baidu.com/item/%E5%85%AD%E7%B1%BB%E7%BA%BF). The larger the category number and the newer the version, the more advanced the technology and the wider the bandwidth.

(2) Twisted pair wiring sequence standards

The most widely used twisted pair wiring sequence standards are ANSI/EIA/TIA-568A and ANSI/EIA/TIA-568B. The main difference between these two standards is the different core wire sequence:

The wire sequence definition of EIA/TIA 568A is, in order, green-white, green, orange-white, blue, blue-white, orange, brown-white, brown, with labels as shown in the following table:

| Green-white | Green | Orange-white | Blue | Blue-white | Orange | Brown-white | Brown |
|:----:|-----|------|-----|------|-----|------|-----|
|  1   | 2   | 3    | 4   | 5    | 6   | 7    | 8   |

The wire sequence definition of EIA/TIA 568B is, in order, orange-white, orange, green-white, blue, blue-white, green, brown-white, brown, with labels as shown in the following table:

| Orange-white | Orange | Green-white | Blue | Blue-white | Green | Brown-white | Brown |
|:----:|-----|------|-----|------|-----|------|-----|
|  1   | 2   | 3    | 4   | 5    | 6   | 7    | 8   |

According to the 568A and 568B standards, for each contact of the [RJ-45](https://baike.baidu.com/item/RJ-45) connector (commonly known as crystal head) in network connections, their roles for transmission signals are respectively: 1 and 2 are used for sending, 3 and 6 are used for receiving, 4 and 5, 7 and 8 are bidirectional lines; for the twisted pair connected to it, in order to reduce mutual interference, the standard requires that 1 and 2 must be a twisted pair, 3 and 6 must also be a twisted pair, 4 and 5 are twisted together, and 7 and 8 are twisted together. It can be seen that there is actually no essential difference between the two standards 568A and 568B; only the arrangement order of the 8 twisted pair wires is different when connecting the RJ-45. In actual network engineering construction, the 568B standard is more commonly used.

(3) Switch

A switch works at the second layer of the OSI reference model, that is, the [data link layer](https://baike.baidu.com/item/%E6%95%B0%E6%8D%AE%E9%93%BE%E8%B7%AF%E5%B1%82). When each port is successfully connected, the CPU inside the switch maps the MAC address and port to form a MAC table. In future communication, data packets sent to that MAC address will only be sent to its corresponding port, not all ports. Therefore, a switch can be used to divide data link layer broadcasts, that is, collision domains; but it cannot divide network layer broadcasts, that is, broadcast domains.

A switch has a very high-[bandwidth](https://baike.baidu.com/item/%E5%B8%A6%E5%AE%BD) backplane [bus](https://baike.baidu.com/item/%E6%80%BB%E7%BA%BF) and internal [switching matrix](https://baike.baidu.com/item/%E4%BA%A4%E6%8D%A2%E7%9F%A9%E9%98%B5). All ports of the switch are attached to this backplane bus. After the control circuit receives a data packet, the processing port looks up the address mapping table in memory to determine which port the [NIC](https://baike.baidu.com/item/NIC) (network card) of the destination [MAC](https://baike.baidu.com/item/MAC) ([hardware address of the network card](https://baike.baidu.com/item/%E7%BD%91%E5%8D%A1)) is attached to, and quickly transmits the data packet to the destination port through the internal switching matrix. If the destination MAC does not exist, it broadcasts to all ports. After the receiving port responds, the switch "learns" the new MAC address and adds it to the internal MAC address table. Using a switch can also "segment" the network. By comparing with the IP address table, the switch only allows necessary [network traffic](https://baike.baidu.com/item/%E7%BD%91%E7%BB%9C%E6%B5%81%E9%87%8F) to pass through the switch. Through the switch's filtering and forwarding, collision domains can be effectively reduced, but it cannot divide [network layer](https://baike.baidu.com/item/%E7%BD%91%E7%BB%9C%E5%B1%82) broadcasts, that is, [broadcast domains](https://baike.baidu.com/item/%E5%B9%BF%E6%92%AD%E5%9F%9F).

The main functions of a switch include physical addressing, [network topology](https://baike.baidu.com/item/%E7%BD%91%E7%BB%9C%E6%8B%93%E6%89%91%E7%BB%93%E6%9E%84), error checking, frame sequencing, and flow control. Switches also have some new functions, such as support for VLAN ([virtual local area network](https://baike.baidu.com/item/%E8%99%9A%E6%8B%9F%E5%B1%80%E5%9F%9F%E7%BD%91)), support for [link](https://baike.baidu.com/item/%E9%93%BE%E8%B7%AF) aggregation, and some even have [firewall](https://baike.baidu.com/item/%E9%98%B2%E7%81%AB%E5%A2%99) functions.

Learning: [Ethernet switches](https://baike.baidu.com/item/%E4%BB%A5%E5%A4%AA%E7%BD%91%E4%BA%A4%E6%8D%A2%E6%9C%BA) learn the MAC address of the device connected to each port, and map the address to the corresponding [port](https://baike.baidu.com/item/%E7%AB%AF%E5%8F%A3%E6%98%A0%E5%B0%84), storing it in the MAC address table in the switch [cache](https://baike.baidu.com/item/%E7%BC%93%E5%AD%98).

Forwarding/filtering: When the destination address of a data frame has a mapping in the MAC address table, it is forwarded to the port connected to the destination node rather than all ports (if the data frame is a broadcast/[multicast](https://baike.baidu.com/item/%E7%BB%84%E6%92%AD) frame, it is forwarded to all ports).

Eliminating loops: When a switch includes a [redundant](https://baike.baidu.com/item/%E5%86%97%E4%BD%99) loop, the [Ethernet switch](https://baike.baidu.com/item/%E4%BB%A5%E5%A4%AA%E7%BD%91%E4%BA%A4%E6%8D%A2%E6%9C%BA) avoids the generation of loops through the [Spanning Tree Protocol](https://baike.baidu.com/item/%E7%94%9F%E6%88%90%E6%A0%91%E5%8D%8F%E8%AE%AE), while allowing backup paths to exist.

(4) IP address

An IP address is used to give a number to a computer on the Internet. In daily situations, every networked PC needs an IP address to communicate normally. We can compare a "personal computer" to a "telephone", then the "IP address" is equivalent to a "telephone number".

Every host on the Internet has a unique IP address. The IP protocol uses this address to transmit information between hosts, which is the foundation for the Internet to operate. An IP address is a 32-bit binary number, usually divided into four 8-bit [binary](https://baike.baidu.com/item/%E4%BA%8C%E8%BF%9B%E5%88%B6) numbers (that is, 4 bytes). IP addresses are usually expressed in "[dotted decimal](https://baike.baidu.com/item/%E7%82%B9%E5%88%86%E5%8D%81%E8%BF%9B%E5%88%B6)" form (a.b.c.d), where a, b, c, d are all decimal integers between 0 and 255. Example: the dotted decimal IP address (100.4.5.6) is actually the 32-bit binary number (01100100.00000100.00000101.00000110).

An IP address can be divided into two parts: a network identification number and a host identification number. Therefore, an IP address consists of two parts, one is the network address, and the other is the host address. IP addresses are divided into classes A, B, C, D, and E. Their applicable types are respectively: large networks; medium networks; small networks; multicast addresses; reserved. The commonly used ones are classes B and C.

**【Experiment Principles】**

The management methods of switches and routers (hereinafter referred to as devices) are basically divided into two types: in-band management and out-of-band management. Managing a device through its Console port belongs to out-of-band management, does not occupy the device's network interface, and is characterized by the need to use a configuration cable and configure at close range. When configuring a switch or router for the first time, the Console port must be used for configuration.

The command-line operation modes of switches or routers mainly include: user mode, privileged mode, global configuration mode, port mode, etc.

- User mode: The first operation mode obtained after entering the device. In this mode, you can simply view the device's software and hardware version information and perform simple tests. The user mode prompt is switch\> or router\>

- Privileged mode: The next-level mode entered from user mode. In this mode, you can manage the device's configuration files, view the device's configuration information, and perform network testing and debugging, etc. The privileged mode prompt is switch# or router#

- Global configuration mode: The next-level mode (submode) of privileged mode. In this mode, you can configure the device's global parameters (such as device name, login information, etc.). In this mode, you can enter the next-level configuration mode to configure the device's specific functions. The global configuration mode prompt is switch(config)# or router(config)#

- Port configuration mode: The next-level mode (submode) of global configuration mode. In this mode, you can configure parameters for the network ports of a switch or router. The port mode prompt is switch(config-if)# or router(config-if)#

The basic operation commands of switches or routers include:

> The Exit command returns to the previous operation mode.
>
> The End command means the user directly returns to privileged mode from a level below privileged mode.

The command lines of switches and routers support obtaining help information, command abbreviation, automatic command completion, and shortcut key functions. Configuring the switch's device name and configuring the switch's description information must be executed in global configuration mode.

Hostname configures the device name of a switch or router. When a user logs in to a switch or router, you may need to tell the user some necessary information. You can achieve this purpose by setting banners. You can create two types of banners: daily notification and login banner.

- Banner motd configures the daily prompt information of a switch or router. motd is the abbreviation of message of the day.

- Banner login configures the login prompt information of a switch or router, located after the daily prompt information.

> To view the system and configuration information of a switch or router, the corresponding view commands must be executed in privileged mode.

1)  Show version views the version information of a switch or router. You can view the switch or router's hardware version information and software version information, which is used as the basis for upgrading the switch/router operating system.

2)  Show mac-address-table views the current MAC address table information of the switch.

3)  Show ip route views the routing table information in the router.

4)  Show running-config views the currently effective configuration information of the switch/router.

**【Experiment Principles】**

**(1) Using VLAN to implement isolation:**

VLAN (Virtual Local Area Network) refers to logical division within a physical network segment into several virtual local area networks. The greatest characteristic of VLAN is that it is not limited by physical location and can be flexibly divided. VLAN has the characteristics of a physical network segment. Hosts in the same VLAN can directly access each other. Access between hosts in different VLANs must be forwarded through routing devices. Broadcast data packets can only propagate within the local VLAN and cannot be transmitted to other VLANs.

Port VLAN is one of the ways to implement VLAN. Port VLAN uses switch ports to divide VLANs. A port can only belong to one VLAN.

Tag VLAN is another type based on switch ports, mainly used to enable hosts in the same VLAN across switches to directly access each other, while isolating hosts in different VLANs. Tag VLAN follows the IEEE802.1q protocol standard. When using an interface configured with Tag VLAN for data transmission, 4 bytes of 802.1q tag information need to be added to the data frame to identify which VLAN the data frame belongs to, so that the peer switch can accurately filter after receiving the data frame.

**【Experiment Principles】**

**(1) Using Layer 3 switches to implement inter-VLAN interconnection and communication**

In a switched network, a physical network is logically divided through VLANs. Different VLANs cannot directly access each other and must be connected through Layer 3 routing devices. Generally, routers or Layer 3 switches are used to implement mutual access between different VLANs. Layer 3 switches and routers have network layer functions and can perform path selection and forwarding according to the IP header information of data, thereby implementing access between different network segments.

Directly connected routes refer to: configuring an IP address for the interface of a Layer 3 device and activating the port. The Layer 3 device will automatically generate directly connected route information for the network segment where the interface IP is located.

The principle by which a Layer 3 switch implements VLAN mutual access is to use the routing function of the Layer 3 switch, identify the IP address of the data packet, and look up the routing table for path selection and forwarding. A Layer 3 switch can use directly connected routes to implement mutual access between different VLANs. The Layer 3 switch configures an IP address for the interface and uses SVI (Switch Virtual Interface) to implement inter-VLAN interconnection. **【Experiment Principles】**

(1) Basic routing concepts

A router is a network layer device. It can select an optimal path according to the information in the IP packet header and forward the data packet out. It implements mutual access between hosts in different network segments.

Routers perform path selection and forwarding according to the routing table. The routing table is composed of routing information entries. There are generally 3 ways to generate a routing table:

- Directly connected route: Configure an IP address for a router interface, and the router automatically generates routing information for the network segment where the interface IP is located.

- Static route: In networks with a simple topology, network administrators manually configure routing information for network segments unknown to the local router, thereby implementing connections between different network segments.

- Routes generated by dynamic routing protocol learning: In large-scale networks, or when the network topology is relatively complex, dynamic routing protocols are run on routers, and routers automatically learn from each other to generate routing information.

(2) Static routes:

Static routes refer to routing information manually configured by users or network administrators, including network address, subnet mask, and next-hop address.

Static routes have different purposes in different network environments:
When the network structure is relatively simple, only static routes need to be configured to make the network work normally; in complex network environments, configuring static routes can improve network performance and guarantee bandwidth for important applications; static routes can be used in VPN instances, mainly for VPN route management.

Static routes use less bandwidth than dynamic routes and do not consume CPU resources to calculate and analyze routing updates. However, when a network failure occurs or the topology changes, static routes will not automatically update and must be manually reconfigured.

Static route configuration mainly involves 5 main parameters: destination address and mask, outgoing interface and next hop, and priority.

1.  **Characteristics of static routes:**

- Manually configured

- Fixed routing path (unless manually modified)

- Non-advertised: will not actively advertise to other routers. However, administrators can introduce static routes into dynamic routing on the local device and then advertise them using the corresponding dynamic protocol route.

- Unidirectionality: only provides routing for data along the next-hop direction, and does not provide reverse routing. If bidirectional communication between the source node and the target network is required, the return static route must also be configured.

- Relaying: if the number of hops passed through in the middle of a static route is greater than 1 (the route needs to pass through 3 or more routing nodes), then static routes to the same destination node or destination network must be configured in sequence on the other routers except the last router.

(2) Role of static routes

The greatest role of static routes is security. Dynamic routing requires routers to frequently exchange their respective routing tables, and analysis of routing tables can reveal information such as network topology and network addresses. Therefore, static routes can also be used for network security considerations.

(3) Disadvantages of static routes

Large and complex network environments are usually not suitable for static routes. On the one hand, it is difficult for network administrators to fully understand the topology of the entire network; on the other hand, when the network topology and link status change, the static route information in routers needs to be adjusted on a large scale, and the difficulty and complexity of this work are extremely high.

**【Experiment Principles】**

OSPF (Open Shortest Path First) is an IGP (Interior Gateway Protocol) that was applied earlier and is more commonly used. It is suitable for medium and large networks of the same type and is a typical link-state (Link-State) protocol. The OSPF protocol has become one of the most widely used routing protocols in Internet WANs and Intranet enterprise networks. The OSPF protocol was proposed by the IETF (Internet Engineering Task Force) IGP working group and is a routing protocol based on the SPF algorithm.

The OSPF routing protocol is generally used within the same routing domain. Here, a routing domain refers to an autonomous system Autonomous System—AS. In an AS, all OSPF routers maintain the same database describing the structure of this AS. This database stores the state information of the corresponding links in the routing domain. OSPF routers calculate their OSPF routing table precisely through this database. OSPF sends link state advertisement packets LSA (Link State Advertisement) to all routers in a certain area, which is different from distance vector routing protocols. Routers running distance vector routing protocols pass part or all of their routing tables to their neighboring routers.

The SPF algorithm (also called Dijkstra's algorithm) is the foundation of the OSPF routing protocol. The SPF algorithm takes each router as a root (ROOT) to calculate its distance to each destination router. Each router, based on a unified database, calculates the topology diagram of the routing domain. This structure diagram is similar to a tree and is called the shortest path tree in the SPF algorithm.

In the OSPF routing protocol, the trunk length of the shortest path tree, that is, the distance from an OSPF router to each destination router, is called OSPF Cost. Its algorithm is: Cost = 100×10<sup>6</sup>/link bandwidth. Here, link bandwidth is expressed in bps. That is to say, OSPF Cost is inversely proportional to link bandwidth. The higher the bandwidth, the smaller the Cost, indicating that the OSPF distance to the destination is closer. For example, the Cost of FDDI or Fast Ethernet is 1, the Cost of a 2M serial link is 48, the Cost of 10M Ethernet is 10, etc.

(3) Trace route

Use the tracert command to trace the path taken by data packets sent from PC0 to PC2.

Run tracert 192.168.5.10 on PC0.

>

>
> 1 0 ms 0 ms 0 ms 192.168.1.1
>
> 2 0 ms 1 ms 0 ms 202.115.18.2
>
> 3 0 ms 2 ms 0 ms 192.168.5.10
>
> Trace complete.

- *Comment: From the running result of the tracert command, it can be seen that the data packets sent from PC0 (192.168.1.10) to PC2 (192.168.5.10) pass through the path* 192.168.1.1 (Router0's Fa0/0 port)——202.115.18.2 (Router1's se1/0 port)——192.168.5.10 (PC2)*. The OSPF protocol selected the Router0—Router1 path for communication from PC0 to PC2 (this path is consistent with the information in each router's routing table), which is different from the path manually selected during static routing. This depends on OSPF's metrics and decision-making for the best path.*
