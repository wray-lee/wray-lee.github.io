# Hellfire Chinese Language Pack Notes

## Problem

After installing Hellfire, the interface is in English, and Chinese can't be selected in the settings either. The Chinese language pack I previously installed for the AUR Firefox was useless — the reason is a version mismatch: Hellfire on Linux is 160.0, while that pack is for 157 and only recognizes 157.*. What's more, it was installed in Firefox's own profile, which Hellfire doesn't read at all.

## How it was solved on Linux

Hellfire's profile is in `~/.mozilla/firefox/p9luzrhy.default-default`. To determine which one to use specifically, look at `LastVersion` of `compatibility.ini` in each profile — the one whose version is 160.0 is the one.

1. The official release 160.0 language pack hasn't been published yet, so what was downloaded is the beta one: `https://ftp.mozilla.org/pub/firefox/releases/160.0b2/linux-x86_64/xpi/zh-CN.xpi`. In the pack, `strict_max_version` of `manifest.json` is `160.*`, which covers exactly the needed version.
2. Close the browser and copy it to `<profile>/extensions/langpack-zh-CN@firefox.mozilla.org.xpi`; the filename must be exactly the same, character for character.
3. Add two lines in `user.js`:
   ```js
   user_pref("intl.locale.requested", "zh-CN,en-US");
   user_pref("extensions.autoDisableScopes", 0);
   ```
4. Restart. Once the language pack is recognized, the language list appears in the settings, and Chinese takes effect.

The second line only prevents manually placed packs from being automatically disabled; once it takes effect you can delete it, otherwise any extensions you manually put in later will all be automatically enabled.

What remains unclear: why at first no additional languages could be found in the settings. I checked Mozilla's API, and it returns 103 languages for 160.0, so it's not that the server has no packs. My guess is that the language list is cached, and only after a restart, when the cached locale became zh-CN, did it refresh and show up — but that's just a guess.

## The situation on Windows

Hellfire on Windows is 158.0.1, installed in `C:\Tools\Firefox`, with the profile in `%APPDATA%\Mozilla\Hellfire\Profiles\64elc7uz.default-default-1`. It already contains `extensions\langpack-zh-CN@firefox.mozilla.org.xpi`, which is the 158 language pack (`strict_max_version` is `158.*`), and `intl.locale.requested` in `prefs.js` is also `zh-CN,en-US`. It's the same approach as on Linux: a version-matching zh-CN pack placed in Hellfire's own profile.

Note that the profile directory is `Mozilla\Hellfire`, not `Mozilla\Firefox`, and this machine doesn't have a `Mozilla\Firefox` directory either. So the fact that "install Firefox and then uninstall it" used to work cannot simply be understood as the two browsers sharing the same profile. More likely, that step caused a version-matching 158 pack to land in Hellfire's profile. Exactly how it landed there, I haven't figured out.

If you run into the same thing on Windows in the future, there's no need to install and uninstall Firefox again; just:

1. Check the version with `about:support`.
2. Download the pack for the corresponding version: `https://ftp.mozilla.org/pub/firefox/releases/<版本>/win64/xpi/zh-CN.xpi`; if the release version isn't out yet, use the beta version number. The language pack itself is cross-platform; the contents under the win64 and linux-x86_64 directories are identical.
3. `about:addons` → gear icon → Install Add-on From File, then select this `.xpi`.
4. Select Chinese in `about:preferences`, then restart.

If "Install From File" is blocked, just copy it manually into the profile's `extensions\`, the same as on Linux.

## Things to remember

- The language pack version must match the browser version. Once the browser's major version updates, the old pack stops working and must be re-downloaded.
- When the versions don't match exactly, the interface will show partly Chinese and partly English. The incomplete translation with Mercury before was most likely due to this: strings newly added in the new version aren't in the old pack.
- If you use the beta pack, a few individual strings may differ slightly from the release version. Replace it once the release version comes out.
