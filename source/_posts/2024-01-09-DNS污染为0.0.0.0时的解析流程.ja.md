# DNS汚染が0.0.0.0のときの解決フロー

```mermaid
graph TB
	客户端发起请求-->匹配规则
	匹配规则-->匹配到基于域名的规则
	匹配规则-->A[匹配到基于 IP 的规则]
	匹配到基于域名的规则--域名匹配到代理规则-->通过代理服务器解析域名并建立连接
	匹配到基于域名的规则--域名匹配到直连规则-->B[通过 Clash DNS解析域名]
	A-->B
	B-->Redir-host/FakeIP--查询 DNS 缓存-->C[(cache)]
	C--FakeIP 未命中,代理域名-->通过代理服务器解析域名并建立连接
	C--Cache 命中-->D[查询得到 IP]
	C--Redir-host/FakeIP-Direct 未命中-->E[匹配 nameserver-policy 并查询]
	E--匹配成功-->D
	E--未匹配到-->F[nameserver/fallback 并发查询]
	F-->D
	D--缓存 DNS 结果-->C
```





この図は **Clash Dns** の解決フローです。キャリアDNSがドメインを`0.0.0.0`に汚染し、かつfallbackに暗号化DNSが設定されていない場合、`[nameserver/fallback 并发查询]` では中間者攻撃が成立し得ます。問い合わせで得られた`0.0.0.0` はキャッシュ内のlanドメインと一致し、本機のリッスンアドレスを指すため、MATCHルールを通りません。
