Git is like a sortable stack, with the top of the stack at the very bottom. You can only make changes to the most recent commit. If you want to change earlier data, you need to sort.

All operations except switch and checkout are performed at the current reference location.

The name of a commit record itself is a hash value.

## commit

`git commit` creates a new version (not a complete copy, only records differences)

`git commit --amend` modifies a commit record

## branch

- `git branch <branch_name> <branch_position>`

		branch points to a commit

- `git branch -f main head~3`    ` 	git branch -f main c0`    `git branch -f` can change the branch pointer
- `git switch <branch_name>`

		switch to a certain branch

When moving using a branch, the branch will also follow and move.

## merge&#x2F;rebase

### merge

Pull and merge

`git merge 1`

At this time, if branch is on main, then pull the code from 1 into main; branch remains on main

### rebase

Merge into and copy commit records

`git rebase 1`

Then merge main into the development line of 1; branch is on main

Rebase does not move the lower versions; it only moves the version where the reference currently is.

---

`git rebase -i head~3`			Select 3 commits including the head reference position, and through GUI perform deletion, sorting; the processed result will appear on a new line (base is head~3)

`-i` change all versions from the current version to the base version

`git rebase -参数 基版本	`

## head

That is, the current reference location

`git checkout 1`

Point head to 1

head points to a commit record commit

When head is used as a reference, it must be uppercase HEAD

## checkout

`git checkout -b totallyNotMain o/main`

`git checkout -b 选择分支 追踪分支` (will create a branch, no need to create it in advance)

Can make a certain branch track a certain remote branch, equivalent to replacing main

---

You can also use

`git branch -u 追踪分支 选择分支` (will not create a branch, needs to be created in advance)

## Relative references

^ moves up one commit record

~num moves up num commit records

`git checkout main^`

==You can use a branch to represent a commit record==

^2 can select the second parent commit

Commands support chained operations

`git checkout HEAD~^2~2`

## Undo changes

`git reset`	`git revert`

`git reset head^` is: commit goes back to the previous record, deletes the current record, and the reference changes to the previous record

`git revert head^` adds a new commit on this line, but the new commit is actually the same as the previous one

==Both commands operate on the location where the current reference is==

## Tidy up branches

`git cherry-pick c2 c4`	copies c2, c4 in order under the branch where the reference currently is

# Remote

## clone

`git clone` copies the remote repository

The first clone will automatically set the main and o/main references to the same location

## main and o&#x2F;main

When you checkout o/main and then commit, because the remote repository data has not been downloaded, it will cause HEAD detachment; that is, o/main only changes its pointer when synchronized

The remote branch o/main (o/*) is actually the location of the remote main branch

## fetch

`git fetch`

Does not update the main branch; it only downloads the remote repository code and updates the o/main reference

No parameters are needed; it will automatically compare and download

`git fetch origin <远程选定分支:本地选定分支>` (can use relative references)

`git fetch origin <:本地分支>` will create a local branch

## pull

is `fetch+merge`

`git pull`

is actually `git fetch ; git merge o/main`

Will pull code and automatically merge

It pulls under the current branch, so if o/main is not at the current location, it cannot pull due to being out of sync

`git pull --rebase` pulls code in rebase form and merges the main branch; using this feature, you can rebase the entire branch

You can use `git pull <远程分支:本地分支>`		`git pull <:本地分支>` similar to fetch

## push

Opposite of pull; it uploads code, with no automatic merge. If the local repository is an old version, you need to update before pushing

`git push origin <选定分支>`

	Position HEAD at the head, automatically track the selected branch and upload

`git push origin <本地选定分支:远程选定分支>`

Upload the selected local branch to the selected remote branch; if the remote one does not exist, it will be created

You can use relative references to not upload the entire branch `git push origin <本地选定分支^:远程选定分支>`

	Only upload to above the local selected point

`git push <:远程分支>`

	Will delete the remote branch
