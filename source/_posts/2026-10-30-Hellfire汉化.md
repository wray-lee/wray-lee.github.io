# Hellfire 中文语言包笔记

## 问题

Hellfire 装完是英文界面,设置里也选不了中文。之前给 AUR 火狐装的中文包没用,原因是版本对不上:Linux 上的 hellfire 是 160.0,那个包是 157 的,只认 157.*。而且它装在火狐自己的 profile 里,hellfire 根本不读。

## Linux 上怎么解决的

hellfire 的 profile 在 `~/.mozilla/firefox/p9luzrhy.default-default`。具体用哪个,看各 profile 里 `compatibility.ini` 的 `LastVersion`,版本是 160.0 的那个就是。

1. 官方正式版的 160.0 语言包还没发布,下载的是 beta 的:`https://ftp.mozilla.org/pub/firefox/releases/160.0b2/linux-x86_64/xpi/zh-CN.xpi`。包里 `manifest.json` 的 `strict_max_version` 是 `160.*`,正好覆盖。
2. 关掉浏览器,复制到 `<profile>/extensions/langpack-zh-CN@firefox.mozilla.org.xpi`,文件名要一字不差。
3. `user.js` 里加两行:
   ```js
   user_pref("intl.locale.requested", "zh-CN,en-US");
   user_pref("extensions.autoDisableScopes", 0);
   ```
4. 重启。语言包被识别后,设置里的语言列表就出来了,中文也生效了。

第二行只是防止手动放进去的包被自动禁用,生效后可以删掉,不然以后手动放进去的扩展都会被自动启用。

没搞清楚的:一开始设置里为什么搜不到更多语言。查过 Mozilla 的接口,对 160.0 能返回 103 种语言,所以不是服务器没包。我猜是语言列表有缓存,重启后缓存区域变成 zh-CN 才刷新出来,但这只是猜的。

## Windows 上的情况

Windows 上的 hellfire 是 158.0.1,装在 `C:\Tools\Firefox`,profile 在 `%APPDATA%\Mozilla\Hellfire\Profiles\64elc7uz.default-default-1`。里面已经有 `extensions\langpack-zh-CN@firefox.mozilla.org.xpi`,是 158 的语言包(`strict_max_version` 是 `158.*`),`prefs.js` 里 `intl.locale.requested` 也是 `zh-CN,en-US`。和 Linux 上的做法是一回事:一个版本对得上的 zh-CN 包放在 hellfire 自己的 profile 里。

注意 profile 目录是 `Mozilla\Hellfire`,不是 `Mozilla\Firefox`,这台机器上也没有 `Mozilla\Firefox` 这个目录。所以以前「装 Firefox 再卸载」管用,不能简单理解成两个浏览器共用同一个 profile。更可能是那一步让一个版本匹配的 158 包落进了 hellfire 的 profile。具体怎么落进去的,我没查出来。

Windows 上以后遇到同样的事,不用再装卸 Firefox,直接:

1. `about:support` 看版本。
2. 下载对应版本的包:`https://ftp.mozilla.org/pub/firefox/releases/<版本>/win64/xpi/zh-CN.xpi`,正式版没出就用 beta 版本号。语言包本身跨平台,win64 和 linux-x86_64 目录下的内容是一样的。
3. `about:addons` → 齿轮 → 从文件安装附加组件,选这个 `.xpi`。
4. `about:preferences` 里选中文,重启。

「从文件安装」被拦的话,就手动复制到 profile 的 `extensions\`,和 Linux 的做法一样。

## 要记住的

- 语言包版本必须和浏览器版本匹配。浏览器大版本一更新,旧包就失效,要重新下载。
- 版本不完全匹配时,界面会出现一部分中文、一部分英文。之前用 Mercury 翻译不全,多半就是这个原因:新版本新增的字符串,旧包里没有。
- 用 beta 包的话,个别字符串可能和正式版略有出入。正式版发布后换掉。
