# 小内存 VPS 资源优化记录（2.4G RAM / 2 vCPU）

实例：RackNerd VPS（Ubuntu 22.04），2026-10-13

## 优化前后

| 指标 | 优化前 | 优化后 |
|---|---|---|
| 负载 (load average) | 4.5–5 | 0.4–0.5 |
| 可用内存 (MemAvailable) | ~515 MB | ~880 MB |
| openclaw 重启耗时 | ~15 分钟 | ~2 分钟 |
| openclaw RSS | 1.0–1.24 GB（触发内存压力警告） | ~0.9 GB |
| zerotier CPU | ~50% 单核 | <1% |
| eth0 包速率 | ~25,000 pps | ~80 pps |

## 1. ZeroTier：多 IPv6 地址导致路径探测风暴（CPU 杀手）

**现象**：`zerotier-one` 常驻 ~50% CPU，eth0 每秒几万个 71/166 字节的 UDP 包，zt 接口本身几乎没流量。

**原因**：eth0 配了 20 个 IPv6（`/etc/network/interfaces` 静态配置），ZeroTier 默认在**每个本地地址 × 3 个端口**上绑定，
并与对端（也是多地址 IPv6 家宽）的所有地址/端口组合做打洞和保活，组合爆炸。
它还绑定了 docker 网桥、netbird `wt0`、`warp`，出现 ZT 套 netbird 的双重隧道。

**修复**：`/var/lib/zerotier-one/local.conf`

```json
{
  "settings": {
    "allowSecondaryPort": false,
    "portMappingEnabled": false,
    "interfacePrefixBlacklist": ["docker", "br-", "veth", "wt", "warp", "zt"],
    "bind": ["<公网IPv4>", "<一个公网IPv6>"]
  }
}
```

```bash
systemctl restart zerotier-one
ss -uanp | grep zerotier        # 应只剩 2 个 socket
zerotier-cli peers              # 路径不应再出现 10.0.1.x（netbird）
```

> 排查方法：`top -H -p $(pidof zerotier-one)` 看线程，`/proc/net/dev` 两次采样算 pps，
> `tcpdump -ni eth0 -c 20000 -q` 统计端口分布。

## 2. OpenClaw

### 2.1 跳过每次启动的 doctor（重启 15 分钟 → 2 分钟）

官方镜像入口 `/app/docker-entrypoint.mjs` 在前台启动 gateway 前**无条件**执行
`openclaw doctor --fix --non-interactive`（没有环境变量能关），弱机上要十几分钟。

`/root/openclaw/docker-compose.yml`：

```yaml
    entrypoint: ["tini", "-s", "--"]
    command: ["node", "--max-old-space-size=640", "openclaw.mjs", "gateway"]
```

代价：**更新镜像后必须手动跑 doctor**，已写成 `/root/openclaw/doctor.sh`：

```bash
./doctor.sh          # stop → doctor --fix → up -d
./doctor.sh --pull   # 先 pull 新镜像（升级时用）
```

### 2.2 禁用用不到的插件（加载 16 → 7 个，启动快 ~30 秒）

```bash
for p in anthropic xai ollama canvas cua-computer device-pair geolocation talk-voice github; do
  docker exec openclaw node openclaw.mjs plugins disable $p
done
```

| 插件 | 作用 | 禁用原因 |
|---|---|---|
| anthropic / xai / ollama | 对应厂商的模型提供方 | 只用自定义 openai-completions 提供方 |
| canvas | Control UI 里的 A2UI 仪表盘组件 | 只用 Telegram/Slack |
| cua-computer | 直接操控桌面（Computer Use） | 容器无桌面 |
| device-pair / geolocation / talk-voice | 设备配对 / 定位 / 语音 | 不用 |
| github | Control UI 里公开仓库链接预览 | 不用 |

保留：`browser`、`file-transfer`、`linux-node`、`memory-core`、`openai`、`slack`、`telegram`。
需要时 `plugins enable <id>` 恢复。配置备份：`data/openclaw.json.pre-memopt`。

### 2.3 限制内存增长

```yaml
    command: ["node", "--max-old-space-size=640", "openclaw.mjs", "gateway"]   # V8 堆上限（实测堆 ~290MB）
    environment:
      - MALLOC_ARENA_MAX=2      # glibc 每线程 malloc arena 造成的 RSS 膨胀
```

> RSS 远大于 V8 堆（~1GB vs ~290MB），大头是原生内存：worker 线程、SQLite、插件。
> 再往下压只能关功能（如 browser、memory-core）。

## 3. 系统层面

### 3.1 关掉 fwupd（-141 MB）

固件更新服务，VPS 上无用却常驻 141MB：

```bash
systemctl mask --now fwupd fwupd-refresh.timer
```

### 3.2 zram 压缩 swap

| | 磁盘 swap | zram |
|---|---|---|
| 位置 | 磁盘文件 | 内存（压缩） |
| 换页延迟 | 毫秒级，VPS 磁盘 IO 共享且限速 | 微秒级 |
| 空间 | 占磁盘 | zstd 压缩约 1/3，1GB 满载实际占 ~300–400MB 内存 |
| 代价 | IO 拖慢其它服务 | 少量 CPU |

```bash
apt-get install -y zram-tools
printf "ALGO=zstd\nSIZE=1024\nPRIORITY=100\n" > /etc/default/zramswap
printf "vm.swappiness=100\n" > /etc/sysctl.d/99-zram.conf     # zram 换页便宜，更积极地压缩冷数据
sysctl -p /etc/sysctl.d/99-zram.conf
systemctl enable --now zramswap
swapon --show     # zram0 PRIO 100 > 磁盘 swap PRIO -2，优先用 zram
```

- 磁盘 swap（8G 文件 + 1.2G 分区）保留兜底。
- 已在磁盘 swap 上的旧页不会主动迁移，被读回后再换出时自然进入 zram；
  **不要**为了迁移去 `swapoff /swap`，会一次性把几百 MB 读回内存。

## 4. 实测：fgc（free-games-claimer）的内存峰值

重启 fgc 触发全部站点登录检查，每 ~3 秒采样：

| 阶段 | fgc 占用 | 系统可用内存 |
|---|---|---|
| 平时 | 25–56 MB | ~730 MB |
| 检查期间（~70 秒，逐站启动 Chromium） | 峰值 ~520 MB | 最低 ~520 MB |
| 结束 | 回落 | ~730 MB |

结论：短时峰值 ~500MB，2.4G 机器扛得住，不值得为它单独迁移。

## 6. 以后要不要换机器

2026 年内存涨价（Hetzner CAX +31%、Netcup +40%、多家缺货），优化后这台够用，**先凑合**。
黑五（11/27）若遇到**续费同价**的 8GB 方案（≤ $60–90/年）再整机迁移。
注意：便宜 ARM（Ampere Altra）单核比新款 EPYC/Ryzen 弱，openclaw（Node 单线程为主）不会更快，
ARM 的优势是同价更多核、更大内存。
