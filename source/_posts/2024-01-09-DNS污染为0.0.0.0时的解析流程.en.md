# Resolution Process When DNS Is Poisoned to 0.0.0.0

```mermaid
graph TB
	客户端发起请求-->匹配规则
	匹配规则-->匹配到基于域名的规则
	匹配规则-->A[匹配到基于 IP 的规则]
	匹配到基于域名的规则--域名匹配到代理规则-->通过代理服务器解析域名并建立连接
	匹配到基于域名的规则--域名匹配到直连规则-->B[通过 Clash DNS解析域名]
	A-->B
	B-->Redir-host/FakeIP--查询 DNS 缓存-->C[(cache)]
	C--FakeIP 未命中,代理域名-->通过代理服务器解析域名并建立连接
	C--Cache 命中-->D[查询得到 IP]
	C--Redir-host/FakeIP-Direct 未命中-->E[匹配 nameserver-policy 并查询]
	E--匹配成功-->D
	E--未匹配到-->F[nameserver/fallback 并发查询]
	F-->D
	D--缓存 DNS 结果-->C
```





The figure shows the **Clash Dns** resolution process. If the ISP DNS poisons the domain to `0.0.0.0`, and fallback is not configured with encrypted DNS, then a man-in-the-middle attack may exist at `[nameserver/fallback 并发查询]`. The `0.0.0.0` obtained from the query matches the LAN domain in the cache, points to the local listening address, and will not go through the MATCH rule.
