“现在开始，进入‘架构完备性’评估模式。对于当前代码，请执行以下操作：

拒绝琐碎：忽略语法规范、命名习惯、冗余空格等非逻辑类问题，仅报告可能导致‘系统状态锁死’、‘资源泄露’或‘逻辑竞争’的硬性缺陷。

定义边界：请指出当前模块中哪一部分逻辑是核心（Core），哪一部分是辅助（Utility），并说明如何通过引入异常处理机制（Exception Handling）将核心逻辑与潜在风险彻底隔离。

最终产出：在满足‘核心功能不中断’的前提下，给出最简化的修复方案，并确认该方案已覆盖所有已知的异常路径（Happy Path vs Exception Path）。完成后，除非出现重大架构崩溃，否则请停止对该文件的审计建议。”
