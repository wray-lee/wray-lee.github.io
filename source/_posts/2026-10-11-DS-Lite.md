# Openwrt DS-Lite（IPv4 over IPv6）

## 为什么日本宽带普遍用 DS-Lite

传统方式（PPPoE）在 NTT 的网终装置（BRAS，负责 PPPoE 认证和下发 IPv4）处排队，
晚上高峰期严重掉速。原因是 NTT 的 BRAS 扩容标准按**连接用户数**（会话数）算，
不按实际流量算：用户人均流量涨了十几倍，会话数没涨到阈值，就不给扩容。
扩容费用由谁承担（NTT 还是 ISP）也一直谈不拢，所以这个问题拖了很多年没解决。

绕开的办法是让 ISP 自己建 IPv6 网络（IPoE / v6plus、クロスパス），
流量不经过 BRAS。但纯 IPv6 上不了 IPv4 网站，于是把 IPv4 包封装进 IPv6 隧道，
由 ISP 侧的网关（AFTR）解封装——这就是 DS-Lite（RFC 6333）。
日本另一套同类方案是 MAP-E（JPNE/KDDI 系），DS-Lite 是 NTT 系 ISP 用的。

代价：AFTR 后面是运营商级 NAT（CGNAT），家用路由器拿不到公网 IPv4，
端口转发/自建服务要另想办法（用 IPv6 或穿透）。

## OpenWrt 配置

### 1. 装包

```bash
# 24.10+ 用 apk；23.05 及更早用 opkg
apk add ds-lite luci-proto-dslite
# opkg install ds-lite luci-proto-dslite
```

装完重启 LuCI 或路由器。

### 2. 建接口

网络 → 接口 → 添加新接口：

- 名称：`dslite`（后面的分流脚本里要填这个名字）
- 协议：`Dual-Stack Lite (RFC6333)`
- AFTR 地址：**优先填 IPv6 地址，不要填域名**

填域名（如 `dgw.xpass.jp`）时，路由器要先解析出 AAAA 记录才能建隧道，
而这个过程依赖 wan6 的 DNS——刚拨上号、DNS 还没就绪时解析不到，
DS-Lite 接口就一直连不上。填 IP 直接省掉这一步。

| ISP | AFTR 域名 | AFTR IPv6 地址 |
|---|---|---|
| 乐天光（クロスパス / Xpass） | `dgw.xpass.jp` | `2001:f60:0:200::1:1` |
| transix（IIJ 等） | `gw.transix.jp` | 东日本 `2404:8e00::feed:100`，西日本 `2404:8e01::feed:100` |
| v6 コネクト | `dslite.v6connect.net` | 域名解析获取 |

IP 是运营商侧的地址，理论上可能变；连不上时先用 `nslookup -type=AAAA dgw.xpass.jp`
确认当前值（transix 用公共 DNS 可能查不到，以运营商公告为准）。

其它选项：

- WAN 口的 IPv6 接口（一般是 `wan6`）要先拿到 240 开头的地址，DS-Lite 才能建隧道
- 防火墙区域：选 `wan`
- 高级设置 → 使用网关跃点：填 `10`（比公寓网等备用线路优先级高）

### 3. 和 PPPoE 并存

两条线路同时可用时，靠跃点定优先级：DS-Lite 填 10，PPPoE 填 20，
平时走 DS-Lite，断了自动落到 PPPoE。要固定某台机器走 PPPoE 用策略路由，见「接口分流」。

## 断线自动切换

`/root/failover.sh`（cron：`* * * * * /root/failover.sh`），
DS-Lite 探测不通就摘掉它的默认路由，流量落到备用线路：

```bash
#!/bin/sh

# 1. 填入你的乐天 DS-Lite 接口名称
IFACE_RAK="dslite"

# 2. 测试连通性的目标 IP（Google DNS）
TEST_IP="8.8.8.8"

# 强制使用乐天接口发送 3 个探测包
ping -c 3 -W 2 -I $IFACE_RAK $TEST_IP >/dev/null 2>&1

if [ $? -eq 0 ]; then
    # 【乐天存活】：恢复/保持乐天的默认路由（跃点 10）
    # 如果路由已存在，命令会静默失败，对系统零消耗
    ip route add default dev $IFACE_RAK metric 10 2>/dev/null
else
    # 【乐天断网】：拔掉乐天的默认路由
    # 此时系统的底层路由表只剩下跃点为 20 的公寓网，流量瞬间切换
    ip route del default dev $IFACE_RAK metric 10 2>/dev/null
fi
```

IPv6 侧同理（`/root/failover_v6.sh`），接口名按实际拿到 240 开头地址的那个填：

```bash
#!/bin/sh

# ================= 配置区 =================
IFACE_RAK="wan6"                 # 乐天光 IPv6 接口名（或者是 pppoe-wan / dslite，根据实际获取到240开头的接口填）
TEST_IP="2001:4860:4860::8888"   # Google 公共 DNS IPv6 节点
# ==========================================

# 1. 动态抓取乐天光当前的 IPv6 网关
GW=$(ip -6 route show default dev "$IFACE_RAK" | awk '/via/ {print $3; exit}')

# 如果连网关都拿不到，说明物理层彻底断开，直接切除路由，回落到公寓网
if [ -z "$GW" ]; then
    ip -6 route del default dev "$IFACE_RAK" 2>/dev/null
    exit 0
fi

# 2. 核心锚点：建立一条只属于探针的静态主机路由，防止删除默认路由后无法探测外网
ip -6 route add "$TEST_IP" via "$GW" dev "$IFACE_RAK" metric 1 2>/dev/null

# 3. 强制通过固定宿主路径向外发射 3 个探测包
ping6 -c 3 -W 2 "$TEST_IP" >/dev/null 2>&1

if [ $? -eq 0 ]; then
    # 【乐天光 IPv6 正常】：将其默认路由以高优先级（metric 10）强行注入（如果已存在则静默跳过）
    ip -6 route add default via "$GW" dev "$IFACE_RAK" metric 10 2>/dev/null
else
    # 【乐天光 IPv6 断流】：精准切除乐天光的默认路由
    # 此时主路由表只剩下公寓网的默认路由（metric 20），流量瞬间无缝转移
    ip -6 route del default via "$GW" dev "$IFACE_RAK" 2>/dev/null
fi
```

## 坑

- 端口转发不能用：AFTR 后面是 CGNAT，没有公网 IPv4。要对外提供服务走 IPv6。
- DS-Lite 接口的 IPv4 是运营商内网地址，别拿它做本机服务绑定。
- 只拿到一个 /64 PD 时，子网要 NAT6 或中继，见「ipv6 nat」和「公网 v6 分配给子网」。
