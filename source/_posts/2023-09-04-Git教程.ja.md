gitはソート可能なスタックのようなもので、スタックの先頭は最下端にあり、最近のコミットに対してのみ変更でき、以前のデータを変更するには並べ替えが必要である

switch, checkout を除くすべての操作は、参照が現在ある位置で行われる

コミット記録自体の名前はハッシュ値である

## commit

`git commit` 新しいバージョンを作成する（完全なコピーではなく、差分のみを記録する）

`git commit --amend` コミット記録を修正する

## branch

- `git branch <branch_name> <branch_position>`

		branchは1つのcommitを指す

- `git branch -f main head~3`    ` 	git branch -f main c0`    `git branch -f` はブランチの参照先を変更できる
- `git switch <branch_name>`

		特定のブランチに切り替える

ブランチを使用して移動すると、ブランチも追随して移動する

## merge&#x2F;rebase

### merge

プルしてマージ

`git merge 1`

このときbranchがmainにあれば、1のコードをmainにプルし、branchはmainのままである

### rebase

マージ先へ、コミット記録をコピーする

`git rebase 1`

するとmainを1の開発路線にマージし、branchはmainにある

rebaseは下層のバージョンを移動せず、参照が現在あるバージョンのみを移動する

---

`git rebase -i head~3`			head参照位置を含む3つのcommitを選択し、GUIで削除・並べ替えを行い、処理後の結果は新しい路線上に現れる（基底はhead~3）

`-i` 現在のバージョンから基底バージョンまでのすべてのバージョンを変更する

`git rebase -参数 基版本	`

## head

すなわち現在の参照が存在する位置

`git checkout 1`

headを1に向ける

headは1つのコミット記録commitを指す

headを参照として使用する場合は大文字のHEADにする

## checkout

`git checkout -b totallyNotMain o/main`

`git checkout -b 选择分支 追踪分支`（ブランチを作成する。事前に作成しておく必要はない）

あるブランチにリモートの特定のブランチを追跡させることができ、mainを置き換えるのに相当する

---

も使用できる

`git branch -u 追踪分支 选择分支`（ブランチを作成しない。事前に作成しておく必要がある）

## 相対参照

^ 1つ上のコミット記録へ移動する

~num 上にnum個のコミット記録移動する

`git checkout main^`

==ブランチをコミット記録commitの代わりに使用できる==

^2 は2番目の親コミットを選択できる

コマンドはチェーン操作をサポートする

`git checkout HEAD~^2~2`

## 変更の取り消し

`git reset`	`git revert`

`git reset head^` はcommitを前の記録に戻し、現在の記録を削除し、参照を前の記録に変更する

`git revert head^` はこの路線上に新しいcommitを追加するが、新しいcommitは実際には前のものと同じである

==2つのコマンドはどちらも現在の参照が存在する位置に対して操作を行う==

## ブランチの整理

`git cherry-pick c2 c4`	c2,c4を順番に参照が現在存在するブランチの下へコピーする

# リモート

## clone

`git clone` リモートリポジトリを複製する

初回clone時は自動的にmainとo/mainの参照を同じ位置にする

## mainとo&#x2F;main

checkout o/main をしてから commit すると、リモートリポジトリのデータをダウンロードしていないため、HEAD分離が発生する。つまり o/main は同期時のみ参照先が変化する

リモートブランチ o/main（o/*）は実際にはリモートmainブランチの位置である

## fetch

`git fetch`

mainブランチは更新せず、リモートリポジトリのコードをダウンロードするだけで、o/main参照を更新する

引数は不要で、自動的に比較してダウンロードする

`git fetch origin <远程选定分支:本地选定分支>`（相対参照を使用できる）

`git fetch origin <:本地分支>` はローカルブランチを作成する

## pull

つまり `fetch+merge`

`git pull`

実際には `git fetch ; git merge o/main`

コードをプルして自動マージする

現在のブランチでプルを行うため、o/mainが現在位置にない場合は同期していないためプルできない

`git pull --rebase` はリベース形式でコードをプルしてmainブランチをマージする。この特性を利用すると、ブランチ全体のリベースを実現できる

fetchに似た `git pull <远程分支:本地分支>`		`git pull <:本地分支>` を使用できる

## push

pullとは逆で、コードをアップロードし、自動マージはない。ローカルリポジトリが古い場合は更新してからpushする必要がある

`git push origin <选定分支>`

	HEADを先頭に位置づけ、選択したブランチを自動追跡してアップロードする

`git push origin <本地选定分支:远程选定分支>`

ローカルで選択したブランチをリモートで選択したブランチへアップロードする。リモートに存在しない場合は作成される

相対参照を使用してブランチ全体をアップロードしない `git push origin <本地选定分支^:远程选定分支>`

	ローカルで選択した位置より上のみアップロードする

`git push <:远程分支>`

	リモートブランチを削除する
